## 第 3 章 评价体系：从 IC 到 fitness

> 本章回答：一个因子到底是「好」还是「坏」？答案不是一个数字，而是一组口径互不相同、且经常被混用的数字。本章把 IC、RankIC、ICIR、分位收益、换手、覆盖率逐个写清公式与统计单位，再说明 FactorMiner 如何把它们压成一个可优化的 fitness 标量，以及这个压缩过程丢掉了什么。

### 3.1 IC 与 RankIC：相关性到底在相关什么

信息系数（Information Coefficient）的标准定义是**每个时点截面上，因子打分与随后收益的相关系数**：

```
Pearson IC_t  = cov(f_t, r_{t+1}) / ( σ(f_t) · σ(r_{t+1}) )
Spearman IC_t = Pearson( rank(f_t), rank(r_{t+1}) )        = RankIC_t
IC            = (1/T) Σ_t IC_t
ICIR          = mean(IC_t) / std(IC_t)
t_naive       = mean(IC_t) / ( std(IC_t) / √T )            ← 仅在 iid 假设下成立
```

`f_t ∈ R^N` 是时刻 `t` 对 N 个资产的打分，`r_{t+1} ∈ R^N` 是对应的前瞻收益。**逐期算相关、再对时间序列取均值**，这个次序不能反：先把 `T×N` 展平成一个大向量再算一次相关，会把「某一时点全市场同涨同跌」的共同冲击全部算成预测力。

为什么要同时报 Pearson 与 Spearman？因为因子值经过非线性单调变换后，Pearson 会变而 Spearman 不变；极端值（加密市场尤其多）会强烈扰动 Pearson。`docs/fitness_hook_guideline.md` 记录了 FactorMiner 从 Pearson 转向 RankIC 作为基础评价的动机，以及一个典型症状：「Fitness Score 30+，但真实覆盖率 5% 且 RankIC 为负」。调研报告里 `crypto-factor-lab` 的 `selection_score` 也用 `abs(val_rank_ic) − 0.001·complexity`，`alphalens` 默认按 date 分组算 `stats.spearmanr`。**RankIC 是主口径，Pearson IC 是交叉校验。**

但 RankIC 也有一处必须说清的代价：**它对尾部不敏感**。一个因子只要把 Top 20% 与 Bottom 20% 排对，中间 60% 全排错，RankIC 依然可能不错；反之，一个主要靠极端尾部赚钱的因子，RankIC 可能低估它。这就是第 15 章要引入分位多空收益的原因——项目里那次「OOS IC 同向显著但含成本 −6.40%」，正是十分位收益不单调、尾部价差仅约 0.006%/日导致的。

FactorMiner 的实现（`core/evaluation/evaluator.py:302-335`）按输入类型自动切换统计单位：

```python
# 截面口径：双方均为 DataFrame[T, N]
IC      = factor_values.corrwith(returns, axis=1, method="pearson").mean()
RankIC  = factor_values.corrwith(returns, axis=1, method="spearman").mean()
Turnover= factor_values.diff().abs().mean().mean()   # 先按列、再跨列

# 时序口径：双方均为 Series
IC      = factor_values.corr(returns, method="pearson",  min_periods=30)
RankIC  = factor_values.corr(returns, method="spearman", min_periods=30)
Turnover= factor_values.diff().abs().mean()
```

在 `_validate_metric_inputs()`（`:355-395`）里还有一层防御：Series↔Series / DataFrame↔DataFrame 类型必须一致，`index.equals` 且 `columns.equals` 必须**完全相等**（不静默 reindex），禁止重复索引、非数值 dtype、`inf`，因子至少有一个有限值。这层校验看着啰嗦，却挡住了「因子值索引错位一格仍算出漂亮 IC」这类最难发现的错误。

### 3.2 三个口径陷阱：Turnover、IR 与 t

**Turnover 至少有三种互不等价的语义**，混用是行业通病：

| 语义 | 公式 | 出处 |
| --- | --- | --- |
| 原始因子值变化 | `mean(|f_t − f_{t−1}|)` | `evaluator.py` 的基础 Turnover |
| 归一化因子变化 | `mean(|Δf|) / (mean(|f|) + 1e−9)` | `inspector/metrics.py:178-181` |
| 组合权重换手 | `0.5 · Σ_i |w_{t,i} − w_{t−1,i}|` | `portfolio_eval.py` 的 `turnover_series` |

它们量纲不同、与成本的关系也不同。真正能乘成本率的是第三种——因为交易成本发生在**权重变化**上，不是因子值变化上。第 15 章的 `cost = turnover × cost_rate` 用的就是它。

**ICIR 的「年化」必须写明约定**。`icir × √A` 里的 `A` 是第 2 章的 7×24 年化因子；不写 `A` 的 ICIR 只是「每期 IC 均值 / 每期 IC 标准差」。历史报告里把 252 口径的「年化 2.35」与 365 口径的 2.83 混用，就属于这类事故。

**朴素 t 检验几乎总是过于乐观**。`t = mean/(std/√T)` 假设 `IC_t` 独立同分布，而重叠标签（`h>1`）、市场状态持续、截面残差相关都会制造自相关。第 13 章的 Newey–West HAC 是最小修正；`crypto-factor-lab` 用 `hac_lags=1` 的 Bartlett 核，`LLM-Framework` 用 21 滞后并诚实记录「实测中位数 `|iid t|/|NW t| = 1.03`，膨胀来自多重性而非自相关」——**这个记录很重要：它说明在该数据集上，真正的问题不是自相关，是试了多少次**。

### 3.3 分位收益、衰减与覆盖率

IC 是相关，分位收益是**可交易性**的第一层近似。做法：每期把资产按因子值分 5 组（或取前后各 `q=0.20`），计算各组下一期平均收益，看 `Q5 − Q1` 的多空价差是否单调、是否显著。

```
Long_Short_t = mean( r_{t+1,i} | f_{t,i} ∈ Top q ) − mean( r_{t+1,i} | f_{t,i} ∈ Bottom q )
```

`core/inspector/metrics.py:185-256` 用 `rank(method="first")` 分组，并要求 `(counts >= n_quantiles) & (distinct >= n_quantiles)` 才认为该期可用——**因子值全相同的一期不能产生有效分位**。`alphalens` 的默认 `quantiles=5, periods=(1,5,10), max_loss=0.35`，分位价差的联合标准误取 `sqrt(std1² + std2²)`。

另外三个诊断量：

- **Lag IC 衰减**：把标签换成 `horizon = 1..10`（`ForwardReturnTarget.with_horizon(lag)`），看信号在多长之后消失。衰减快意味着必须高频交易，成本压力随之上升。
- **Coverage**：有效观测占理论观测的比例。嵌套极值、复杂算子、过长的 `min_periods` 会让因子只剩几十根有效 K 线。FactorMiner 在 fitness 里对 `coverage < 0.20` 施加二次惩罚 `(coverage/0.20)²`（`docs/fitness_hook_guideline.md`）。
- **稳定性**：分时期、分资产、分波动率状态的 RankIC 分布，而不是一个全局均值。`crypto-factor-lab` 用 `stability_windows=8` 的滚动 RankIC 与 `positive_test_rank_ic_ratio`；`AlphaMaster` 用「前后半段同号 +0.5 / 异号 −1.0」的启发式。

### 3.4 fitness：把研究偏好压成一个标量

搜索算法需要一个可优化的标量。`DEFAULT_FITNESS_CFG`（`core/evaluation/evaluator.py:37-51`）与 `_build_fitness()`（`:400-483`）给出完整构造：

```
blended   = rankic_in^(1−λ) · rankic_oos^λ        λ = oos_exponent = 0.5
cons_mult = 1.0  或  0.3                          # 样本内外 RankIC 符号不一致时
shrink    = √( max(n_obs − k, 0) / n_obs )        # k = shrinkage_k = 30，仅 use_oos 时
penalty   = (coverage / 0.20)²   若 coverage < 0.20，否则 1.0
tp        = 1 / (1 + γ · max(0, turnover_norm − cap))    # γ = turnover_penalty，默认 0（关）
fitness_score = 100 · blended · cons_mult · shrink · tp · penalty
```

四个设计决定值得逐一解释：

**（1）几何混合而非算术加权。** `rankic_in^(1−λ) · rankic_oos^λ` 是几何平均。只要任一侧塌陷到 0，整个 fitness 归零；算术加权 `0.5·in + 0.5·oos` 则允许「样本内极好、样本外为零」仍拿到一半分数。这是防过拟合的一个廉价但有效的结构性选择。`rankic_in <= 0` 时直接置 0，配合后续的 `orientation` 定向逻辑（先按样本内符号定向，再算 IR/成本），避免负 IC 因子被符号误杀——那是 Phase 4 修掉的四个缺陷之一。

**（2）验证段被反复读取的代价。** `out_of_sample` 有 `test_period` 时自动启用，`λ=0.5` 意味着**每个候选每一代都读一次验证段 RankIC**。这不是最终 holdout 泄漏（最终留出由独立脚本重算、不进 fitness），但它等价于把验证集当成训练集用，且当时没有试验次数折减、没有 gap/embargo、没有逐折重拟合。`docs/research/platform_maturity_gap.md` §4.2 专门做了这个口径收窄，并促成后来 `val_read_count` 这个计数——正式 run 里是 **87**。**记录「验证集被读了几次」比记录「跑了几个 epoch」更能暴露过拟合。**

**（3）收缩项。** `√((n_obs − k)/n_obs)` 是一个小样本折减，`k=30` 相当于扣掉 30 个观测的信用。它不改变排序（同一批候选 `n_obs` 通常相近），但防止短窗口上的高 RankIC 被过度奖励。

**（4）成本暂时不进 fitness。** `gate_cost_rate = 0.0018` 用在 `_build_verdict()` 的**收益口径闸门**里，不在 fitness 里。这是一个有意的分层：fitness 负责搜索，闸门负责证伪。行业里 `AlphaMaster` 把成本直接塞进驱动搜索的 `pnl = pos·ret − turnover·cost_rate`（`backtest.py:429,644`），`crypto-factor-lab` 的最终入库条件也含成本；FactorMiner 的选择更保守，但也因此在搜索阶段看不到换手代价，需要靠 P0.5 的收益口径闸门事后拦下。

自定义 Fitness Hook 是这套体系的扩展点（`core/miner/registry.py:36-48` 校验必须接收 `factor_values, returns, base_metrics` 三个位置参数）。一个典型写法：

```python
@EvaluatorRegistry.register_fitness_hook("turnover_aware")
def turnover_aware(factor_values, returns, base_metrics: dict) -> dict:
    ic       = float(base_metrics.get("IC", 0.0))
    turnover = float(base_metrics.get("Turnover", 0.0))
    penalty  = 0.02 * turnover
    return {"fitness_score": abs(ic) * 100 - penalty,
            "turnover_penalty": penalty}   # 额外指标随因子一起落库，供 Inspector 审查
```

启动校验会在**读取数据之前**检查 Hook 是否已加载、签名是否正确；名称拼错会聚合报错并列出已加载 Hook，绝不静默回退（README §启动校验）。这个「不静默回退」的纪律，和沙盒「无 sandbox 直接抛错、禁用不安全 exec 回退」是同一种设计哲学。

### 3.5 竞品对照：各家把什么当成优化目标

| 框架 | 主优化目标 | 简约 / 复杂度控制 | 成本是否在目标内 | 样本外进 fitness |
| --- | --- | --- | --- | --- |
| gplearn | `metric − c·len(program)·sign(metric)`，`c='auto'` 取 `Cov(len,fit)/Var(len)` | ✅ 显式长度惩罚 | ❌ | ❌ `oob_fitness` 是样本内子采样 |
| gpquant | **回测 Sharpe / ann_return / 方向准确率** | ✅ `parsimony=0.005` | ✅ 含滑点 A/B、手续费、冲击成本 | ❌ 固定单次切分 |
| AlphaGen | **加入池后的组合 IC 增量 `new_obj`** | ❌ 靠 `MAX_EXPR_LENGTH=15` | ❌ | 三段 OOS，但非 fitness |
| AlphaForge | `−mean(pred) + loss_simi + loss_potential` | ❌ 长度上限 8、相邻重复 −0.3 | ❌ | ⚠️ predictor 用 train/test split 0.2 |
| qlib | 模型预测误差；评价用 IC / Rank IC / ICIR | ❌ | ✅ `risk_analysis` 分含/不含成本 | ❌ |
| RD-Agent | validation IC / 平台超额收益 | ❌ | ✅ 反馈含 `with_cost` | ⚠️ hypothesis 阶段可见历史 test 指标 |
| crypto-factor-lab | `abs(val_rank_ic) − 0.001·complexity` | ✅ | ✅ 最终确认含成本 | ✅ 最终留出三条件 |
| LLM-Framework | validation IC（**从不回灌 feedback**） | ✅ 六层 anti-paraphrase | ⚠️ 坦诚承认无成本组合 | ✅ 三段 + 8 道闸门 |
| AlphaMaster | **0.60·年化收益 + 0.10·Sortino + 0.05·Calmar + …**（FTMO 模式 0.75·年化） | ❌ 注释里的复杂度惩罚实际不存在 | ✅ 单边 3bps + 2× 压力 | ⚠️ OOS Sortino 乘 0.1~1.2 的启发式 |
| **FactorMiner** | 样本内外 RankIC 几何混合 + 覆盖/一致性/收缩/换手惩罚 | ✅ 覆盖惩罚、GP 的 `parsimony=0.05` | ⚠️ 成本在闸门不在 fitness | ⚠️ `oos_exponent=0.5` + `val_read_count` 计数 |

表里最该警惕的是最后两行。**AlphaMaster 把「搜索」和「交易」焊死，reward 直接是回测年化收益（权重 0.60–0.75）**，好处是目标端到端一致，代价是搜索可以直接攻击回测口径的全部自由度——结合 172.8 万次无分母候选，这条路本身就是 beta 退化的病因的一部分。FactorMiner 的 RankIC 几何混合虽然也过拟合，至少不直接对收益曲线做梯度上升。

另一处值得学的是 LLM-Framework 的「文本 gate 在碰 DataFrame 之前拒掉约 90% 候选」：把最便宜的检验放在最前面，等价于**降低有效试验次数**，是提升统计功效最省力的手段（第 14 章会量化：`n_trials` 从 787 降到 1，MDE 从 0.15 降到 0.06）。

### 3.6 FactorMiner 实现：从因子值到落库指标

一次评估的完整数据流：

```
factor.compute(X)  →  _validate_metric_inputs
                   →  _calculate_built_in_metrics       IC / RankIC / Turnover
                   →  _build_fitness                    fitness_score
                   →  _build_verdict                    hac_t / p_value / dsr /
                                                      ls_* / cost_adj_return
                   →  custom Fitness Hook（如有）
                   →  metrics 写入 FactorMetadata
```

`_build_verdict()`（`evaluator.py:488-606`）把分位多空组合的每期净收益映射为 `ls_return / ls_vol / ls_sharpe / ls_hit / ls_turnover / ls_cost / ls_t`，并计算 **`sr = cost_adj_return / std_return`**——注意这是**每期净 Sharpe**，不是 IC-IR，也不是年化 Sharpe，它是 DSR 的输入。单资产输入走 `_build_temporal_verdict()`（`:608-698`）：滚动分位择时（252 根、只用当期信息）→ 净收益序列 → NW t + DSR，附 `ls_exposure`。这个项目在单标的时序上第一次拿到真实判决，最好一个 `t=2.31 / p=0.021 / OOS RankIC 0.121`，此前该分支恒为 `t=0 / p=1`。

指标落库的唯一契约是四个字段：`metrics.IC`、`metrics.RankIC`、`metrics.Turnover`、`metrics.fitness_score`。`README` 特别提醒：「`0` 可以是某个候选的真实评分，但一批新因子若全部为零，应先确认后端已重启到最新 Python 代码」——这是一条运维经验，也是一个诚实的设计：**没有指标时宁可写 0，也不要编一个看起来合理的数**。

### 3.7 工程陷阱

1. **把时序 IC 与截面 IC 求平均**。两者统计单位不同（沿时间 vs 逐期截面），混成一个无语义数字是 `research-protocol.md` §7 明确禁止的。
2. **常数 / 全零因子**。`corrwith` 在标准差为 0 时返回 NaN；若下游用 `fillna(0)` 兜底，会得到一个「零分但看起来正常」的候选。FactorMiner 的 Anti-Bloat 拦截会在 `corrwith` 前告警并降级，`_safe_corr` 在共同有限值 <30 时直接返回 `None`（`expressions.py:295-306`）。
3. **三种 Turnover 混用**，导致成本估算差一个数量级。记住只有组合权重换手能直接乘成本率。
4. **fitness 权重文档与代码不符**。AlphaMaster 文件头注释写 `0.35 Sortino + 0.20 Calmar + … − complexity`，实际是 0.60 年化收益且无复杂度惩罚——**以源码为准**。
5. **同一指标多套口径**。索提诺下行 std 地板在 AlphaMaster 三个文件里有三种实现；FactorMiner 因此在 `annualisation.py` 里做了单一来源，并用测试锁定闸门判定不随年化变化。
6. **验证段被免费反复读取**。每读一次都在消耗统计证据；必须计 `val_read_count` 并写进报告。
7. **把 fitness 当显著性**。fitness 是搜索用的排序标量，`p_adj / dsr / gate_pass` 才是证伪结果。两者共用 `metrics` 字典，但语义完全不同。

### 本章小结

1. IC 的正确次序是「逐期截面算相关 → 对时间序列取均值」；把 `T×N` 展平算一次相关会把市场共同冲击误当作预测力。
2. RankIC 对异常值稳健、对单调变换不变，是主口径；但它对尾部不敏感，必须配分位多空收益一起看。
3. Turnover 有原始因子变化、归一化变化、组合权重换手三种语义，只有第三种能乘成本率。`ICIR × √A` 必须写明 `A` 的取值。
4. fitness 用**几何混合**（而非算术加权）让任一侧塌陷即归零，并叠加覆盖惩罚、符号一致性惩罚、小样本收缩与可选换手惩罚；成本留给闸门而非 fitness。
5. `oos_exponent=0.5` 意味着验证段被反复读取，因此 `val_read_count` 是必需的研究元数据；正式 run 记录为 87。
6. 竞品里最危险的目标是「直接优化回测年化收益」（AlphaMaster），最省力的功效提升是「在昂贵计算前用廉价 gate 拒掉 90% 候选」（LLM-Framework）。
7. 指标可以写 0，不可以编。「宁可零分，不要模拟图表」贯穿 FactorMiner 的评估、快照与 Inspector 三层。
