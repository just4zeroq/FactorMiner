## 第 1 章 因子、Alpha 与预测问题

> 本章回答：我们到底在找什么？「因子」在数学上是一个函数，在统计上是一个待检验的假设，在工程上是一段可执行代码，在业务上则是一笔还没扣成本的钱。这四重身份不重合，正是绝大多数量化研究事故的起点。本章先把它们拆清楚，再给出全书使用的概念框架与结论等级。

### 1.1 因子的两个祖先：资产定价与统计预测

「因子」这个词有两套彼此不完全兼容的血统。

第一套来自**资产定价**。Fama–French 传统里，因子是解释横截面收益差异的风险暴露：市场、规模、价值、动量、质量、低波动。它的目标是解释 `E[r_i]`，关心的是「为什么这些资产长期平均收益不同」，通常用排序分组、Fama–MacBeth 回归、因子暴露与风险溢价来检验。这类因子必须能讲出经济机制，且往往要求跨市场、跨时期稳健。

第二套来自**统计预测与机器学习**。在这里，因子只是一个把当期可观测信息映射成未来收益排序的函数：

```
F : X_{≤t}  →  s_t ∈ R^N        （截面打分）
或  F : X_{≤t}  →  s_t ∈ R          （单标的时序打分）
```

其中 `X_{≤t}` 是截至 `t` 时刻**真实可得**的全部信息，`s_t` 是对未来收益的预测分数。它不要求有经济学解释，只要求在未见数据上保持预测力。WorldQuant 的 101 Formulaic Alphas、qlib 的 Alpha158/Alpha360、以及本书讨论的绝大多数自动挖掘框架，都属于这一支。

两者的冲突很实际：一个统计上显著的预测器，可能只是对某个已知风险因子的隐性押注。AlphaMaster 的仓库状态档案里记着一个经典病例——某组指数因子因 `TS_RANK` 连用导致符号丢失，退化成 **91.8% 时间做多**的 beta 因子，年化 +117.7% 看起来很漂亮，作者自己最后标注「不是 alpha 而是 beta」「短数据放大」「不建议单独使用」（`docs/research/alphamaster_competitor_review.md` §2.4.2）。因子挖掘系统如果没有办法区分「预测了收益」和「承担了市场风险」，就会把杠杆暴露当成 discoveries。

> **原理**：区分二者的最小检验是**方向中性**与**市场中性**。若把因子值对市场等权收益做回归后残差仍具预测力，或在 dollar-neutral 多空组合上仍为正，才算脱离了纯 beta。FactorMiner 的分位多空组合正是按「多空各 0.5、gross 归一到 1.0」构造的（`core/evaluation/portfolio_eval.py:63-190`），共同市场冲击在截面秩与美元中性下被抵消——这也是第 14 章闸门校准里用半合成 DGP 注入 `market_frac=0.6` 共同因子却仍能测出真实 IC 的原因。

### 1.2 因子的数学定义与三种形态

把定义写严谨一点。设市场有 `N` 个资产、时间轴 `t = 1..T`，令

- `X_t ∈ R^{N×D}`：时刻 `t` 可观测的 `D` 维特征面板（OHLCV、资金费、持仓量……）；
- `r_{t+1} ∈ R^N`：从 `t` 之后可成交时点入场、持有至 `t+h` 的前瞻收益；
- `F(·; θ)`：由结构 `θ`（公式树、网络权重、源码）参数化的因子函数。

则因子值 `f_t = F(X_{≤t}; θ) ∈ R^N`，我们关心的是它在每个截面上对 `r_{t+1}` 的**排序能力**：

```
IC_t(θ)      = corr_pearson( f_t , r_{t+1} )
RankIC_t(θ)  = corr_spearman( f_t , r_{t+1} )
IC(θ)        = (1/T) · Σ_t IC_t(θ)
```

注意两个容易被忽略的点。其一，**`f_t` 只能用 `X_{≤t}`**，这是因果性约束，不是实现建议；任何 `shift(-n)` 用在特征侧、任何全样本 `fit_transform`、任何 backfill 都在破坏它。其二，因子值本身没有量纲意义，只有**排序**有意义：把 `f` 换成 `3f+7` 或 `rank(f)`，Pearson IC 会变，RankIC 不变，组合不变。这也是 FactorMiner 在软去重时先 `rank(axis=1)` 再展平的原因——它要比较的是 ordering，不是 scale（`core/miner/paradigms/base.py:15-38`）。

按输出形态，因子可分三类，研究口径完全不同：

| 形态 | 输出 | 评价统计单位 | 典型场景 |
| --- | --- | --- | --- |
| **截面因子** | `f_t ∈ R^N`（每个时点给 N 个资产打分） | 逐期截面 IC，再对时间序列汇总 | 多币种 / 多股票横截面选币 |
| **时序因子** | `f_t ∈ R`（每个时点给自己打分） | 沿时间轴滚动相关或分位择时 | 单标的择时、CTA 信号 |
| **条件 / 过滤器** | 布尔或离散状态 | 条件分组收益、覆盖率 | 波动率状态过滤、事件驱动 |

FactorMiner 用 `mining_mode` 区分前两者：`cross_asset` 下因子与收益都是 `DataFrame[T, N]`，`IC = factor_values.corrwith(returns, axis=1, method='pearson').mean()`；`sequential_single` 下都是 `Series`，`IC = factor_values.corr(returns, method='pearson', min_periods=30)`（`core/evaluation/evaluator.py:302-335`）。**这两种口径的数字不能混在一起报告**，第 3 章会展开。

### 1.3 因子挖掘的完整研究闭环

把「挖因子」画成一条链，会发现问题往往不在搜索那一段：

```
   ① 假设           「放量突破后短期延续」—— 必须可证伪
        ↓
   ② 表示           算子集 + 终端集 + 表达式语言（AST / 代码 / 张量）
        ↓
   ③ 搜索           GP / RL / LLM / NN / 枚举 / 手工，产出候选 θ_1..θ_K
        ↓
   ④ 评价           IC、RankIC、分位收益、换手、覆盖率 → fitness 标量
        ↓
   ⑤ 证伪 ◀──── 多重检验折减、HAC、FDR、DSR、留出账本、purge/embargo
        ↓
   ⑥ 组合           去重、因子池、权重拟合
        ↓
   ⑦ 执行           事件驱动回测：成本、滑点、资金费、容量
        ↓
   ⑧ 归档           manifest、快照、谱系、生命周期状态
```

绝大多数开源框架把力气花在 ③ 和 ④。而对 21 个框架的源码级调研给出的结论是：**前六个环节大家都在做，第七环（统计闸门）才是分水岭**（`docs/research/industry_factor_mining_survey.md` §3.2.6）。18 个仓库里只有 `LLM-Alpha-Mining-Framework` 与 `crypto-factor-lab` 两家把 FDR / Holm / Romano–Wolf / DSR / 随机零分布真正写进代码；微软 RD-Agent 工程与生态顶级（839 文件、166 测试、CI/Docker/53 篇文档），统计闸门得分却是 0——其 `prompts.yaml:187-190` 甚至鼓励「任何微小改进都替换最佳结果」。**工程越成熟，越能高效地把验证集用穿**，这句话值得贴在研究室的墙上。

FactorMiner 自己走过同一条弯路：早期版本四范式齐全、59 个算子、Web 控制台、组合回测都有，但全仓检索不到 `FDR / BH / Holm / DeflatedSharpe / purge / embargo / NeweyWest / holdout ledger`。随后 6 个已标记 `INSPECTED` 的因子在严格样本外全军覆没（总收益 −11.18%、Sharpe −1.14，零成本仍 −7.37%），逐因子 `|RankIC|` 从 0.0568 衰减到 0.0280、6 个里 2 个方向翻转。诊断写得非常直白：**「我们有一套『打分』，但没有一套『证伪』机制」**（`docs/research/optimization_plan.md` §0）。

### 1.4 什么算「发现了一个因子」：结论等级

研究结论必须分级，否则「IC 显著」会被口头升级成「找到了 alpha」。`skills/factorminer-research-architect/references/research-protocol.md` §9 给了一套六级刻度，本书全盘沿用：

| 等级 | 名称 | 证据要求 | 允许的表述 |
| --- | --- | --- | --- |
| 1 | 研究设想 | 假设与方案已写，未运行 | 「我们猜测……」 |
| 2 | 候选结果 | 训练 / 搜索过程中表现良好 | 「候选在样本内 fitness 靠前」 |
| 3 | 验证结果 | 在用于选择的验证区间表现良好 | 「通过验证段筛选」 |
| 4 | 最终测试结果 | 冻结方案后在一次性留出集上评估 | 「严格 OOS 的 IC 同向显著」 |
| 5 | 策略级证据 | 额外纳入成本、滑点、容量、组合与执行 | 「含成本后组合为正」 |
| 6 | 实盘证据 | 真实执行记录 | 「已上线运行」 |

**不得跨级表述。** 这条规则能挡住量化研究里最常见的一类失真：把「第 2 级」的样本内高 fitness 讲成「第 5 级」的可交易策略。FactorMiner 的生命周期状态 `DISCOVERED → INSPECTED → PAPER_TRADING → LIVE → RETIRED`（`core/miner/entities.py`）本质是同一套等级的工程化；全库重审把 84 个因子全部降级为 `DISCOVERED_UNVERIFIED`、6 个旧 `INSPECTED` 无一幸免，就是一次集中的降级纠偏。

一个特别容易混淆的跳跃是 **4 → 5**。项目里有过一次极有教学价值的实证：2025-07→2026-11 的一次性严格 holdout 上，通过闸门的两个因子 OOS IC 全部同向显著（`|t|` 4.17–5.45，无方向翻转，通过组组合 RankIC +0.0577 / t +4.11），**但含成本组合 −6.40%，零成本仅 +2.22%；被闸门拒掉的那个因子反而净 +23.35%**。原因是十分位收益不单调、尾部价差仅约 0.006%/日（年化约 1.5%），而 5 日调仓成本 8.6% 远高于毛收益。结论：**闸门能有效阻止「OOS 方向翻转 / IC 崩塌」，但不能排序经济价值**（`user_workspace/reports/p0_holdout/README.md`）。

### 1.5 算法与伪代码：一个最小但完整的研究循环

下面这段伪代码不是玩具，它标出了每个环节**必须留下的证据**。少了任何一行注释里的产物，后面的审计都会断链。

```python
# 阶段 0：冻结研究方案（预注册）——在看任何结果之前
spec = {
    "hypothesis":       "放量突破后 3 根 bar 内收益延续",
    "universe":         ["BTC/USDT:USDT", ...],       # 资产池与 PIT 规则
    "windows":          {"mine": [...], "val": [...], "holdout": [...]},
    "target":           {"entry": "next_open", "exit": "close",
                         "horizon_bars": 3, "return_type": "simple"},
    "gates":            {"hac_t_min": 2.0, "fdr_max": 0.05,
                         "dsr_min": 0.90, "oos_rankic_min": 0.02},
    "cost":             {"commission": 0.0004, "slippage": 0.0005},
    "seed":             20261114,
}
manifest = build_manifest(spec)   # config_hash / git_sha / operator_set_hash /
                                  # data_snapshot_hash / seed / n_trials_at_start
# ↑ 阈值必须在查看最终测试集前设定；之后任何"再跑一次看看"都要消耗新窗口

trial_log = []                    # ← 每一次评估都记，含失败者（num_trials 分母）
for epoch in range(n_epochs):
    candidates = miner.generate_candidates()          # ③ 搜索
    candidates = diversity_filter.filter(candidates)  # 硬/软去重
    for c in candidates:
        f = c.compute(X_mine)                         # ② 表示 → 因子值
        metrics = evaluate(f, r_mine, r_val)          # ④ 评价
        trial_log.append({"id": c.logic_hash, "p": metrics.p_value,
                          "status": metrics.status})  # ← 失败者也计数
    miner.update_model(candidates, metrics)           # 更新种群/策略/反思

# ⑤ 证伪：把历史 + 本轮全部 p 值一起做 BH，DSR 用真实 n_trials 折减
verdicts = apply_promotion_gates(shortlist,
                                 family_p_values=[t["p"] for t in trial_log],
                                 n_trials=len(trial_log),
                                 null_tstats=sample_null(60))
promoted = [c for c, v in zip(shortlist, verdicts) if v["gate_pass"]]

# ⑥⑦ 组合与执行：权重只在样本内拟合，方向从样本内库学，值取 OOS 重算库
weights = fit_pool(promoted, X_mine)
result  = run_backtest(factors=promoted, weights=weights,
                       X=X_holdout, real_funding=True, strict_oos=True)

# ⑧ 归档：绿灯只说明过程可复现，不等于盈利
archive(manifest, verdicts, result, note="绿灯 ≠ 正向 OOS 证据")
```

注意 `trial_log` 这一行。很多系统只记录「幸存者」——被保存的短名单——于是 `num_trials` 被系统性低估，Deflated Sharpe Ratio 的门槛被人为调松。`LLM-Alpha-Mining-Framework` 把这句话写进了源码注释：*"trace is also the multiple-testing denominator. Counting only the survivors ..."*。FactorMiner 也踩过同一个坑：`deflated_sharpe_ratio(..., n_trials=1)` 让 DSR 退化成普通 Sharpe 检验，直到 `ParallelEvaluator` 累计 `total_evaluated`（含未进短名单的失败者）才修好（`docs/research/optimization_plan.md` Phase 1.6）。

### 1.6 竞品对照：六类框架各自把「因子」当成什么

| 框架 | 因子的物理形态 | 优化目标 | 有没有把「证伪」当一等公民 |
| --- | --- | --- | --- |
| qlib | 声明式字符串表达式 / Alpha158 模板 | 模型预测误差；评价用 IC/ICIR | ❌ 无挖掘器、无多重检验 |
| gplearn | 前缀 program 列表（符号回归） | `metric − c·len(program)` | ❌ `oob_fitness` 是样本内子采样 |
| gpquant | `SyntaxTree` | **回测 Sharpe** | ❌ 固定 `[:400]/[400:800]` 单次切分 |
| AlphaGen | 栈式 RPN token | **加入池后的组合 IC 增量** | ❌ 三段 OOS 但无统计校正 |
| AlphaForge | one-hot token 序列 | `−mean(pred) + 多样性正则` | ❌ 按年切分、无 purge |
| RD-Agent | LLM 生成的 Python 因子代码 | validation IC / 平台 Sharpe | ❌ 鼓励"微小改进即替换最优" |
| LLM-Framework | 受约束的公式 + 文本 gate | validation IC（**从不回灌反馈**） | ✅ BH/Holm/RW + DSR + 8 道闸门 |
| crypto-factor-lab | 21-op DSL AST | `|val RankIC| − 0.001·complexity` | ✅ 17 道闸门 + 一次性留出账本 |
| AlphaMaster | 定长 8 的 RPN 公式 | **回测年化收益（权重 0.60–0.75）** | ❌ 四条统计闸门全缺 |
| **FactorMiner** | AST dict / Python 源码 / 张量通道 | 样本内外 RankIC 几何混合 fitness | ✅ HAC + 累积 FDR + DSR + 随机零分布 + promotion gates + 账本 |

看最后一列比看第二列更重要。AlphaMaster 有 62 个算子、65 个预计算特征、动作掩码、Web 控制台、断点续训，是产品化最完整的一家；但 `9000 步 × 192 公式/步`（理论上界 172.8 万次候选）全部在同一批 val 折上打分、每步用 `val_score` 刷新冠军并写盘，全仓检索 `bonferroni|holm|fdr|deflated|num_trials|embargo|purge` 零命中，结局就是前面那个 91.8% 做多的 beta。**因果链是完整的：搜索强度足够、证伪机制为零 → `max(170 万个噪声)` 被当成 alpha。**

### 1.7 FactorMiner 实现：概念如何落到类型上

本书后续章节反复引用的几个类型，先在这里建立索引：

- `FactorExpression`（`core/miner/expressions.py:6-44`）：抽象基类，统一 `compute(data)` / `get_source()` / `get_complexity()` / `to_display_string()`。五个子类分别承载 AST dict、Python 源码、NN 通道、RL 动作轨迹、线性组合。
- `FactorMetadata` 与 `data_lineage`（`core/miner/entities.py:25`）：因子谱系。入库时写入数据来源、交易对、周期、样本范围、输入流、规范化 `target` 与精确收益公式；实验流水线再补上 `run_id / config_hash / git_sha / operator_set_hash / data_snapshot_hash / seed` 六个身份字段。
- `FactorMinerDirector`（`core/miner/director.py`）：唯一调度网关。四范式完全封装在后面，Director 负责去重、评估、闸门判定、落库与谱系快照。
- `ParallelEvaluator`（`core/evaluation/evaluator.py`）：把因子值变成 `IC / RankIC / Turnover / fitness_score` 四个契约字段，外加 `hac_t / p_value / dsr / ls_* / gate_checks`。
- `factor_db/`：异构存储。`metadata/*.json` 存逻辑与指标，`values/*.parquet` 存与评估切片对齐的因子值和未来收益快照，`weights/` 与 `models/` 存 NN 工件。Inspector 的 Tearsheet 只从快照生成，**不回算、不补造、不用模拟图占位**（README §Phase II）。

指标契约只有四个原始字段：`metrics.IC`、`metrics.RankIC`、`metrics.Turnover`、`metrics.fitness_score`。CLI、Launchpad、Dashboard、Inspector 都读这四个，不用小写别名。这条看似琐碎的约定，是为了避免「同一个指标三套口径」——AlphaMaster 的索提诺下行标准差地板在三个文件里有三种实现、年化 `ppy` 一处数据驱动一处写死 6240，就是反例。

### 1.8 工程陷阱

1. **把因子值当预测收益**。`f_t` 是排序分数，不是收益预测值。直接拿它做回归目标或计算「预测误差」没有意义；要用 IC、分位价差或组合净收益来评价。
2. **把 `INSPECTED` 当成「有效」**。它只是通过了一批人为设定的闸门，闸门本身还需要阳性对照来验证功效（第 14 章：`n_trials=182` 下 MDE=0.10，远高于加密日频现实 IC 0.02–0.05）。
3. **概念混用导致的口径污染**：把时序 IC 与截面 IC 求平均、把原始因子变化 / 排序变化 / 组合权重换手三种 Turnover 混成一个数、把 fitness 与统计显著性混为一谈。
4. **README 驱动的研究**。竞品调研里反复出现「文档声称的流水线在源码里不存在」（`AlphaForge-Crypto` 主入口 import 不存在的模块、回测全 TODO）、「fitness 权重的文件头注释与代码不符」（AlphaMaster 注释写 0.35 Sortino，实际 0.60 年化收益）。**以源码为准，不以 README 为准**，这是本书的方法论底线。
5. **报告层的话术降级**。AlphaMaster 内部状态档案诚实写下「不是 alpha 而是 beta」，但给面向用户的 AI 分析器的 system prompt 却是「不要轻易下『过拟合』结论，尽量不要提过拟合」「不要因训练分远高于验证分就建议停止」（`web/ai_analyze.py:31,57`）。统计诚实与用户侧解说被拆成两套，闸门就会被话术架空。
6. **零产物却报成功**。`README` 特别强调四契约的第 4 条：只更新模型、不把最终候选写进 `state.population` / `replay_buffer`，任务会「正常完成」但没有任何可保存因子。同类问题还有 6 币预留池下 `min_assets=10` 导致每次调仓被拒、**0 交易 0% 收益却报回测成功**（第 16 章）。

### 1.9 本书的立场

如果只带走一句话：**在拿到干净的、含成本为正的样本外证据之前，所有工程投入都是在让「一个还没被证明的方法」变得更严谨**。这不是说工程没用——它决定不返工、决定结论能不能被别人复用——但它是乘数，不是被乘数。`docs/research/platform_maturity_gap.md` 用四维评分把这件事讲得很清楚：能力覆盖 A=8、纪律可信 D=8、运营可复现 O=6，而结果产出 R=1；**R 是乘数，这一项没动，A 和 D 再高也只等于「一套很严谨的、暂时还没挖到东西的研究工具」**。

因此本书的排序是：先把概念与口径定死（第 1–3 章），把表示与搜索讲透（第 4–10 章），然后**用三章讲证伪**（第 11–13 章），再用一章讲为什么 IC 好不等于赚钱（第 15 章），最后才谈架构、竞品与路线图。

### 本章小结

1. 因子有四重身份：数学上的函数、统计上的假设、工程上的可执行代码、业务上的未扣成本收益。混淆它们是绝大多数研究事故的起点。
2. 因子的定义自带两条硬约束：只能用 `X_{≤t}`，且只有排序有意义。前者是因果性，后者决定了 RankIC、截面秩与软去重为什么是更稳健的口径。
3. 完整闭环有八段，行业普遍把力气花在「搜索 + 评价」，而决定结果可信度的是「证伪 + 留出纪律」。21 个框架的横向调研把统计闸门称为分水岭。
4. 结论分六级，不得跨级表述。「样本内 fitness 高」「严格 OOS IC 显著」「含成本组合为正」是三件完全不同的事；项目里 −6.40% 与被拒因子 +23.35% 的对照就是活的证据。
5. `num_trials` 必须记录**全部尝试**（含失败者），否则 DSR 与 FDR 的分母被低估，闸门形同虚设。
6. 绿色流水线证明的是过程可复现、可审计，不是挖到了赚钱的因子。这句话在第 16 章还会再出现一次，值得记两遍。
