## 第 20 章 研究方法论与路线图：什么先做，什么别做

> 本章回答：把前面十八章收成一套可执行的研究协议——从一句交易直觉开始，到一份能被人复现、审计、且明确标注结论等级的实验报告。最后给出路线图排序与一份可直接使用的检查清单。这一章不引入新算法，只回答「怎么不错」。

### 19.1 研究设计协议九步

`skills/factorminer-research-architect/references/research-protocol.md` 给了一套框架无关的九步协议，本书按 FactorMiner 的语境补全落地方式：

**第 1 步 · 输入归一化。** 提取六个要素：研究对象（市场 / 资产类别 / 标的池）、信号来源（价格 / 成交量 / 订单簿 / 基本面 / 加密原生流）、研究类型（单标的时序 / 多标的截面 / 混合）、决策频率与预测 horizon、方向（趋势延续 / 反转 / 风险 / 截面排序 / 条件过滤）、目标限制（低换手 / 稳定性 / 覆盖率 / 可解释性 / 计算成本）。缺失时采用**保守暂定值并写明它如何影响结论**，不要凭空选「最优」标的或周期。

**第 2 步 · 时间语义。** 对每个实验明确 `feature_end / decision_time / entry_time / label_end`（第 2 章）。写成可核对的公式，例如 `close[t+h]/open[t+1] − 1`。

**第 3 步 · 假设与对照。** 假设必须可证伪：

> 在流动性过滤后的 BTC 永续 5 分钟数据中，相对成交量异常且价格突破过去窗口高点的信号，对随后 3 根 bar 的收益具有正向 RankIC。

至少设计一个**反向或替代解释**：极端成交量代表耗竭而非延续、信号只是波动率暴露、收益来自少数行情阶段、由交易时段或流动性驱动、因子只是已有基线的重复表达。对照优先包括：只用价格突破、只用相对成交量、信号取反、打乱但不破坏时间块结构的安慰剂、不同窗口/horizon/行情阶段、与简单动量或反转因子比较。

**第 4 步 · 特征与标签规格。** 每个特征记录：字段与来源、公式、窗口与 `min_periods`、是否滞后、缺失/零值/极值/除零处理、标准化方式及**拟合样本**、时序或截面语义、计算后的索引对齐。标签记录：价格基准、entry/exit、horizon、简单或对数收益、是否去市场/行业暴露、重叠标签处理、缺失资产与幸存者偏差处理。代码审查提示清单见第 2 章 §2.8。

**第 5 步 · 范式选择。** 先问三个问题：候选空间是否已经很小且明确？用户需要的是**新的数据变换、评价偏好还是搜索机制**（三者不能混）？增加模型复杂度是否对应明确的研究需要？

| 方法 | 适用情况 | 必要产物 | 主要风险 |
| --- | --- | --- | --- |
| 明确公式 / 网格 | 假设具体、参数少 | 公式、参数网格、对照 | 参数窥探 |
| GP | 搜索短小 AST 公式 | AST、算子空间、精英候选 | 多重检验、表达式膨胀 |
| RL | 逐步构造本身是研究对象 | state/action/reward、轨迹、策略 | reward hacking、训练不稳 |
| NN | 连续复杂关系或多通道表征 | schema、scaler、权重、通道 | 泄漏、不可解释、过拟合 |
| LLM | 文字到候选代码及迭代修订 | prompt、源码、反馈历史 | 不安全代码、幻觉、测试集泄漏 |

**LLM 更适合作为候选生成器或研究助手，而不是未经约束的结论生成器。** 所有生成候选仍需在统一评价协议下真实运行。

**第 6 步 · 数据切分。** 角色分离见第 14 章 §13.1；「一次」按信息暴露计。切分需保留时间顺序，并考虑最长回看窗口的 warm-up、标签 horizon 造成的边界污染、purge/embargo、市场结构变化、资产上市退市、重叠标签导致的有效样本量下降。**若数据很短，诚实缩小结论范围；不要用随机交叉验证制造样本量。**

**第 7 步 · 评价体系。** 先确定统计单位（单标的时序沿时间、多标的截面逐期、混合研究分别报告不混成一个无语义数字）。核心指标：Pearson IC、RankIC、ICIR（说明年化约定）、Coverage、Turnover（明确是原始因子变化 / 排序变化 / 组合权重换手）、Decay、Quantiles、Stability。显著性不能只看普通 t，需 HAC / block bootstrap；大量候选时报告选择偏差并考虑 FDR、White Reality Check、DSR。**验收阈值必须在查看最终测试集前设定**，且应与频率、资产、样本长度匹配，不使用通用「神奇数字」。

**第 8 步 · 泄漏与过拟合审查。** 三类：数据泄漏（PIT、scaler 拟合样本、特征选择是否看过验证标签、幸存者偏差）、搜索偏差（一共测了多少候选和超参、是否保存失败候选、是否反复查看最终测试集、是否只报最好时期/资产、是否根据结果改假设）、实现风险（索引时区 bar 闭合、重复时间戳、缺失传播、数值溢出、时序算子误用于截面、缓存与随机种子）。对自动生成或搜索的表达式还要加**语义不变量检查**：候选是否仍表达原假设而非只共享几个输入字段；方向、阈值和联合条件是否被算子绕过或反转；除法/倒数/标准化在接近零时是否改变经济含义；主候选与反向/消融对照是否清楚分开；实际标签公式是否与任务卡完全一致。

**第 9 步 · 结论等级。** 第 1 章的六级刻度，不得跨级表述。

### 19.2 一份合格的实验报告应该长什么样

把上面九步压成模板。任何一条答不出来，报告就不该发出去：

```markdown
# 实验报告 · <run_id>
## 0. 预注册（在查看结果前冻结）
- 假设 / 反向解释 / 对照：
- 资产池与 PIT 规则：
- mine / validation / holdout 三段区间；purge / embargo：
- target：entry / exit / horizon / return_type：
- 验收阈值（hac_t_min / fdr_max / dsr_min / oos_rankic_min / ls_t_min）：
- 成本：commission / slippage / gate_cost_rate / funding 来源：
- seed、config_hash、git_sha、operator_set_hash、data_snapshot_hash：

## 1. 数据
- 面板规模（T × N）、覆盖率、重复/缺口/极端收益检查结果：
- 新鲜度与已消耗窗口（引用 holdout ledger）：

## 2. 搜索
- 范式、算子集、终端集、参数网格：
- **num_trials（含失败者）**、val_read_count、预算使用率、DSR 门槛：
- 去重统计（硬去重 / 软去重拦下数、max_observed_corr）：

## 3. 结果
- 候选清单与 IC / RankIC / Turnover / Coverage / fitness：
- 判定：hac_t / p / p_adj / empirical_p / dsr / gate_checks / gate_pass：
- 分位多空：ls_return / ls_cost / ls_turnover / ls_sharpe / ls_t：
- walk-forward：逐折 RankIC、净收益、weights_differ_across_folds：
- 回测：净值 / 回撤 / 总成本明细 / funding_source / strict_oos：

## 4. 结论
- **结论等级（1–6 级）**，不得跨级：
- 阴性结果原样写出（0 promoted、含成本为负、被拒因子表现）：
- 与反向解释的对照结论：
- 局限与未解决问题：
- 可复现性：reproducibility / mismatches / 同种子重跑差异：
```

模板里三个字段最常被省略，也最不该省：`num_trials`（含失败者）、`val_read_count`（验证集被读几次）、**阴性结果原样写出**。FactorMiner 的 `user_workspace/runs/<run_id>/report.md` 与 `docs/README.md` §5 的诚实边界，本质就是这个模板的实现。

### 19.3 路线图：S1 → S5 的排序逻辑

`platform_maturity_gap.md` §5 与 `survey.md` §9 的排序，按「是否依赖新数据 / 是否依赖正向结果」分五阶段：

| 阶段 | 内容 | 前置 / 验收 | 为什么在这个位置 |
| --- | --- | --- | --- |
| **S1（现在）** | 接线：零分布接入晋升判定、账本 API 化、`num_trials` 跨机器一致、默认配置改严谨、算子集版本戳 | 不依赖新数据；全量测试不退化 + 接线断言 | 已实现但未成为平台能力，成本最低 |
| **S2（与 S1 并行）** | gap/embargo + 验证集读取计数 + **逐折重拟合** roll-forward；run registry；断点续训 | 用历史窗口做多段复验，账本能列出每次揭示 | 让「验证」可复用，不必每验一次烧一段数据 |
| **S3（等数据，被动但要有设计）** | PIT 资产池、OI 数据源、真实 8h funding 入回测并统一两处成本、RL/NN 终端接入 | 60 个流里 ≥3 类可用、两处成本同源 | 扩大「能挖出什么」，独立于统计纪律 |
| **S4（累积干净窗口）** | P0.5 预注册正向实验；**把目标周期/换手按 P0.5 结论重新设计**；等待期做前瞻 paper trading 记录 | 30 根新 bar × 3 窗，或 universe holdout 的不重叠新标的 | 唯一能改变 R 的阶段；在此之前所有工程都是防返工 |
| **S5（R 破之后）** | 实盘链路、动态权重 / 风险模型 / 归因、认证与多用户、调度监控、分布式评估、生命周期自动化 | 至少 1 个通过闸门且含成本为正的因子 | 有了可上线的东西，平台化投入才有回报 |

**一句话排序**：先接线（S1）→ 让验证可持续（S2）→ 补数据面（S3）→ 等新数据拿正向证据（S4）→ 才谈平台化扩展（S5）。

**明确不做**（S4/S5 之前）：epoch 级断点续训（当前 `--resume` 仅阶段级）、PIT 资产池的复杂实现、OI 只有 25 行时的特征模板、liquidation 数据源、NN 独立特征路径、真实 funding 与 gate 成本的进一步细化、Hypothesis 属性测试之外的大规模测试重写、实盘/下单/风控、认证与多用户、Ray/Celery 分布式评估、Hypothesis 属性测试的全面铺开、ADR/CHANGELOG/CONTRIBUTING、动态 AlphaPool / 风险模型、因子自动退役。

理由只有一句：**R（结果产出）= 1 时先补工程规模，边际收益最低。** qlib 是最成熟的平台却不含挖掘器，AlphaMaster 工程最完整却退化成 beta——这两个反例足以支撑排序。

一条被反复验证的纪律（`survey.md` §9）：

> 阶段 2 的每次评估都必须先过 P0-1 的账本；任何「再跑一次看看」都必须消耗一段新的未见数据。**这条纪律比任何新算子都重要。**

### 19.4 给研究者的检查清单

**开工前**

- [ ] 假设可证伪，且至少写了一条反向解释与三组对照
- [ ] 四个时点已写明，标签公式可直接核对
- [ ] 三段切分、purge / embargo、验收阈值已在看结果前冻结
- [ ] 成本参数与 gate 成本恒等式一致
- [ ] `num_trials` 会从第一次评估开始累计，且含失败者
- [ ] seed / config / 算子集 / 数据快照已指纹化

**运行中**

- [ ] 每个候选都过索引对齐与数值有效性校验
- [ ] 硬/软去重统计已记录（含 `max_observed_corr`）
- [ ] 验证段读取计数在增长且被记录
- [ ] 所有评估入口都经过 holdout 守卫
- [ ] 沙盒候选全部真实执行，没有「看起来合理」的跳过

**出结果后**

- [ ] `p_adj` 基于**累积族**，不是本批
- [ ] DSR 用真实 `n_trials` 与**成本后净策略 Sharpe**
- [ ] `weights_differ_across_folds = True`
- [ ] 报告里同时有 `ls_return` 与 `ls_cost`，不是只有毛收益
- [ ] 阴性结果原样写出，包括被拒因子的表现
- [ ] 结论等级标注正确，没有跨级表述
- [ ] 可复现性字段齐全（`reproducibility / mismatches`）
- [ ] 报告层没有抑制性指令、没有选择性呈现
- [ ] 明确写出「绿灯 ≠ 正向 OOS 证据」

**选型 / 审查第三方框架时**

- [ ] 用第 19 章 §18.6 的十步流程走一遍，含最后的阳性对照
- [ ] 读报告先读顶部的基线校准 / 实施补记
- [ ] 核对许可（AlphaMaster 是 AGPL-3.0）
- [ ] 把「未找到」理解为全仓检索零命中，不是绝对不存在

### 19.5 从 0 到 1：一次完整实验的最小可行范式

把全书压成一次可执行的实验，推荐这个顺序（不要求一次做到 S5）：

```bash
# 0. 预注册：冻结方案，生成 manifest（六字段身份 + 成本恒等式校验）
python -m core.cli experiment --config user_workspace/configs/configExperiment.json \
    --miner GP --seed 20261114

# 1. 只读查看数据预算：哪些窗口已烧、下一个滚动窗口还差多少根 bar
python -m core.experiment.windows            # 或 GET /api/gates/holdout

# 2. 查看闸门功效：当前 n_trials 下闸门的最小可检出 IC 是多少
python -m core.experiment.gate_calibration --out user_workspace/reports/gate_calibration.md

# 3. 单因子深审：滚动 IC / Lag 1–10 衰减 / 5 分位收益 / 换手 / 覆盖率
factorminer inspect --factor "fac_xxxxxxxx" --pairs "BTC/USDT:USDT"

# 4. 严格 OOS 组合回测：方向从样本内库学，因子值只取 OOS 重算库
factorminer backtest --db-root factor_db_oos --orientation-db-root factor_db \
    --start 2025-01-01 --end 2025-06-30   # 默认即真实资金费率(crypto_streams)；--constant-funding 回落常数网格

# 5. 逐项核对 user_workspace/runs/<run_id>/report.md 的阴性结果与结论等级
```

四范式最小化验证（每范式一轮、真实 Feather 数据、至少落一个 metadata）可用：`python -B -m unittest discover -s tests -v`，项目里 `tests/test_cli_smoke.py` 为 MyCustomGP / MyCustomRL / MyCustomLLM / NN 分别创建了临时行情并跑通公开 CLI。

**注意**：这套命令的正确用法是「跑完看报告」，不是「跑到出现正数为止」。每重复一次都要检查是否消耗了新的数据窗口。

### 19.6 六个常见误区

**误区 1：「闸门全绿 = 挖到 alpha」。** 全绿只是第 4 级结论。`run_20261114T104814Z_b9eb49` 八阶段全通过、`reproducibility=True`、验证段回测仍是 −4.43% / 0 promoted。

**误区 2：「IC 显著就该能赚钱」。** P0 实验：OOS IC 同向显著（`|t|` 4.17–5.45）、含成本 −6.40%、被拒因子反而 +23.35%。相关 ≠ 单调、中间 ≠ 尾部、显著 ≠ 幅度、毛 ≠ 净。

**误区 3：「闸门越严越好」。** 虚警率 0.0% 的代价是 `n_trials=182` 下 MDE=0.10，高于加密日频现实 IC 0.02–0.05。闸门需要阳性对照，也需要通过减少 `K`、增加 `n_obs`、提高 `sr` 来提升功效。

**误区 4：「多试几次总能试出来」。** 正是这个直觉制造了 `max(170 万个噪声)`。在固定的数据预算下，试验次数越多，需要的真实信号越强。

**误区 5：「加算子 / 加范式能解决 OOS 亏钱」。** 瓶颈是统计闸门与留出纪律，不是表达力。在 R=1 时扩表达力，只会把重复采样放大成更高效的重复采样。

**误区 6：「工程完整 = 平台成熟」。** qlib 是最成熟的平台却不含挖掘器；RD-Agent 工程生态顶级但 M4=0；AlphaMaster 产品化最完整却退化成 beta。四维里 R 是乘数。

### 19.7 本章小结

1. 研究协议九步（输入归一化 → 时间语义 → 假设与对照 → 特征与标签规格 → 范式选择 → 数据切分 → 评价体系 → 泄漏与过拟合审查 → 结论等级）是框架无关的；FactorMiner 是它最完整的执行后端，但不是协议本身。
2. 假设必须可证伪且配反向解释与对照；范式选择先问「需要的是数据变换、评价偏好还是搜索机制」，三者不能混为一谈。
3. 验收阈值必须在看最终测试集前冻结；模板里最不该省略的三个字段是 `num_trials`（含失败者）、`val_read_count`、阴性结果原样写出。
4. 路线图 S1→S5 的排序依据是「是否依赖新数据 / 是否依赖正向结果」：先接线、再让验证可持续、再补数据面、然后等干净窗口拿正向证据，最后才谈实盘与分布式。R 是乘数，这一项不动时扩平台规模是负 ROI。
5. 六个常见误区都可归到同一句话：**「生成候选」不是研究产出，「可信的证据」才是**。
6. 检查清单应按「开工前 / 运行中 / 出结果后 / 审查第三方」四阶段执行，且最后一步永远是阳性对照——前九步只能证明能拦坏因子，第十步才证明没连好因子一起拦掉。

### 19.8 结语：把「不知道」写进结论

这本书用十九章讲了一件其实很简单的事：**因子挖掘的产出不是因子，是可信的证据**。

生成一万个公式在今天很容易：GP、RL、LLM、NN 四种范式加上 59 个参数化算子，一个下午就能塞满因子库。难的是回答「这一万个里有没有一个不是运气」，而这个问题要求的不是更多算力，是三样朴素的东西——**数清自己试过多少次、把没看过的数据真的留到最后一刻、把不好看的结果原样写进报告**。

项目里最值得记住的不是任何一次绿灯，而是这几行数字：84 个存量因子全库重审 0 通过、严格 OOS 含成本 −6.40%、验证段 −4.43%、正式 run 0 promoted、首个干净窗口 ETA 2026-12-13、R 仍为 1。它们共同构成了一句诚实的话：**这套系统目前证明了自己不会骗人，但还没证明自己能赚钱。**

绿色流水线不等于盈利，统计显著不等于可交易，历史结果不等于未来收益。把「不知道」写进结论，不是研究的失败，是研究开始变得可信的标志。
