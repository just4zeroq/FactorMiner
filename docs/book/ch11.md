## 第 11 章 去重、多样性与因子池：从一堆公式到一个组合

> 本章回答：挖掘器吐出上百条公式，为何先删掉重复的比再多挖几代更重要？冗余怎样抬高试验分母、挤占因子池、制造多样性幻觉？两级去重如何在只度量截面次序的前提下判重？从单因子 fitness 排序到组合目标驱动搜索，隔着哪些数学与工程权衡？拟合出的权重，又凭什么贯通到回测而不被抹平？

### 10.1 为什么去重比多挖更重要：三类冗余与试验分母

挖掘器真正产出的不是"因子"，而是"候选表达式"。遗传规划的交叉变异、大语言模型的措辞改写、强化学习的动作采样，本质上都是在一个巨大的公式空间里做随机搜索。搜索最贵的代价不是 CPU 时间，而是统计意义上的试验次数 num_trials——每把一个候选送进评估器，账本上就多记一次假设，这个数字一旦写进去就再也拿不掉。因此，判断一个候选该不该被评估，比判断它该不该被保留更关键。

冗余不是一种，而是三类，且需要完全不同的判据。第一类是**源码等价**：同一棵 AST 换了个变量名、多包一层冗余括号，或两个算子名指向同一实现，`str(get_source())` 完全相同。第二类是**数值等价**：因子的消费方式从来不是它的绝对数值，而是它在每个截面上把资产排成什么次序，所以 `rank(close)` 与 `zscore(close)`、`close/volume` 与 `(close×1000)/(volume×1000)`，在排序意义上是同一个信号。第三类是**经济含义等价**：反向信号 `−momentum` 与 `momentum` 只差一个权重符号，一群刻画同一价量关系的不同算子组合也彼此可替代。第一类是语法问题，第二、三类是语义问题；只做语法去重，等于只检查了最表浅的一层。

危害之所以被系统性低估，是因为它同时从三个方向侵蚀研究结论，而每一处都不会抛异常。

其一是**放大试验分母**。BH-FDR 与 Deflated Sharpe 的门槛随累计假设数单调变严，用文字写清这个关系：

```
p_adj   ≈ p · num_trials / rank(p)        （BH 校正上界，示意）
SR_bar  = f(num_trials, n_obs)            （DSR 基准 Sharpe，随分母递增）
```

符号解释：`p` 是某个候选的原始 p 值，`rank(p)` 是该 p 值在全部假设中的升序位次，`num_trials` 是跨 run 累计的试验次数，`n_obs` 是有效观测数，`SR_bar` 是"要算显著必须超过的每期 Sharpe"。一个冗余候选不带来任何新信息，却把 `num_trials` 加一，从而把每一个真候选的门槛往上抬。于是出现一个反直觉的现象：**挖得越多，越难显著**。这不是市场变难了，是分母被自己制造的冗余撑大了。项目里把 `num_trials` 做成跨机器可提交的单调快照、把"验证段读取次数"单独记为 `val_read_count`，正是为了让这笔账可审计。

其二是**挤占因子池容量**。组合层的容量 K 是硬约束（FactorMiner 默认 10）。若 K 个席位里有 m 个被同一信号的不同写法占住，池子的有效独立维度只剩 `K_eff = K − m`。更糟的是权重归一 `Σ|w| = 1`：每个冗余马甲都会分走约 `1/K` 的权重，等价于对同一个赌注重复下注多次，既没有分散风险，又让换手率虚高。

其三是**多样性幻觉**。控制台打印"本轮发现 46 个新因子"很振奋，实测却约三成是同信号改写。按单因子 fitness 排出的 Top-K 列表，前排会是同一因子的几个马甲；研究员以为自己拥有了 K 条独立证据，实际上只有一条。后面所有的组合优化、显著性推断、净值归因，都建立在被高估的自由度之上。

由此得到一个带因果的判断：**去重不是收尾清理，而是搜索目标的一部分**。它决定分母、决定池子的有效维度、决定后续所有统计推断是否诚实。先把分母压住，比多跑几代去碰运气更有价值；后者会同时抬高门槛、稀释权重、制造虚假的自由度，三样都指向同一个结果——过拟合被加速，却被"产出很多"的表象掩盖。

### 10.2 两级去重：源码硬去重与面值相关性软去重

FactorMiner 用两级串联的过滤器，成本从低到高，判据从语法到语义。

**第一级是 MD5 源码硬去重**，位于 `core/miner/paradigms/base.py:135-139`：`h = hashlib.md5(str(cand.get_source()).encode()).hexdigest()`。之所以对源码字符串取哈希而不是用对象 id，是因为同一逻辑在不同范式里会被序列化成 AST 字典、Python 代码字符串或 RL 动作序列，但稳定文本是可复现的；在候选量级上 MD5 碰撞概率可忽略。这一级是 O(1)，并且哈希集合会跨轮持久化——`mine()` 启动时把全库历史哈希通过 `storage_client.get_all_logic_hashes()` 注入 `initial_hashes`（`base.py:258-264`），所以上一代评估过的表达式这一代直接被挡，不重复消耗试验次数。

**第二级是面值相关性软去重**，核心函数是 `factor_signature`（`base.py:15-38`）。这里有一个必须讲透的设计判断：要度量的是截面的 **ordering**，不是 scale。因子最终被消费的方式是截面排序（RankIC、分位多空、截面 rank 后合成信号），任何单调正变换都不改变交易含义。所以 DataFrame 先 `rank(axis=1)` 逐期按截面排序，再按 C 序展平成一维签名；Series 直接展平。C 序（行优先、时间主序）保证所有子因子与未来收益共享同一套 `(时间, 资产)` 观测次序，后续逐元素比较才成立。

判据写在 `signature_correlation`（`base.py:41-55`）：两个签名先取共同有限值位置，若少于 50 个返回 `None`——样本太少时相关系数不可信，此时既不判重也不记忆，宁可放过也不误杀；否则取 Pearson 相关的绝对值：

```
ρ(a,b) = Σᵢ (aᵢ − ā)(bᵢ − b̄) / √( Σᵢ(aᵢ − ā)² · Σᵢ(bᵢ − b̄)² )

判重条件： |ρ| > θ ，  θ = 0.99
```

符号解释：`a`、`b` 是两个候选在同一面板上展平后的签名向量，`i` 遍历共同有限值位置，`ā`、`b̄` 为各自均值，`θ` 为阈值。**取绝对值是刻意的**：反向信号 `ρ = −1` 同样是冗余，因为一个 `−1` 的权重就能把 `-ρ` 翻成 `ρ`，池子不需要为它单开一个席位。这也说明为什么阈值必须是 0.99 而不是 0.7：`0.99` 判的是"等价"，`0.7` 判的是"太像、该去探索别的"，两者目的相反，混用必然误杀或漏放。

archive 容量是成本闸门。软去重是"候选 × archive 签名"的两两比较，只对通过硬去重的候选计算面值，并给签名库设上限：`dedup_value_archive` 默认 40（`base.py:273`，`DiversityFilter._remember` 在 `:113-118` 达到上限即停止记忆），避免单代比较成本随轮次膨胀成 O(K²)。

带注释的伪代码如下，对应 `base.py:15-159` 的真实骨架：

```python
# 两级去重：MD5 硬去重 → 面值相关性软去重（伪代码）
def factor_signature(values):
    """把因子面板压成一维签名；只保留截面的 ordering，丢掉 scale。"""
    if isinstance(values, DataFrame):
        if values.empty:
            return None
        # 逐期按截面排序：rank(close) 与 zscore(close) 会得到同一签名
        return values.rank(axis=1).to_numpy(float, na_value=NaN).reshape(-1)  # C 序展平
    if isinstance(values, Series):
        return None if values.empty else values.to_numpy(float).reshape(-1)
    return None

def signature_correlation(a, b):
    """共同有限值上的 Pearson 相关；样本不足则拒绝下结论。"""
    if a is None or b is None or a.shape != b.shape:
        return None
    mask = isfinite(a) & isfinite(b)
    if mask.sum() < 50:          # 少于 50 个共同有限值：不可信，返回 None
        return None
    aa, bb = a[mask] - a[mask].mean(), b[mask] - b[mask].mean()
    denom = sqrt((aa**2).sum() * (bb**2).sum())
    return float((aa * bb).sum() / denom) if denom > 0 else None

def filter_redundant(candidates, panel, archive_hashes, signatures,
                     theta=0.99, cap=40):
    kept = []
    for cand in candidates:
        # ① 硬去重：源码文本级 MD5，跨轮持久化，O(1)
        h = md5(str(cand.get_source()))
        if h in archive_hashes:
            continue                       # 完全相同的表达式，直接丢弃
        # ② 软去重：只对通过硬去重者计算面值，控制成本
        sig = factor_signature(cand.compute(panel))
        if theta > 0 and sig is not None:
            corr = max((abs(signature_correlation(sig, s))
                        for s in signatures if signature_correlation(sig, s) is not None),
                       default=0.0)
            max_observed_corr = max(max_observed_corr, corr)
            if corr > theta:               # 含反向信号：|ρ| 超阈值即冗余
                value_rejected += 1
                continue
            if len(signatures) < cap:
                signatures.append(sig)     # 记忆签名，供本代后续候选比较
        archive_hashes.add(h)
        cand.logic_hash = h
        kept.append(cand)
    return kept
```

真实实测记在 `TODO.md` §3 与 `user_workspace/reports/engineering_hardening.md`：20 币、2 代，`DiversityFilter` 拦下 **46 个候选（约 30%）**，`max_observed_corr = 1.000`。`1.000` 不是数值 bug，恰恰证明存在逐期截面完全同序的候选——约三分之一"新因子"只是同一信号换了个写法。

这里还留过一次接线教训：第一版把 `self.data`（`RealDataClient` 对象本身）直接传给 `candidate.compute()`，结果全部抛异常、签名全为 `None`，去重静默失效却不报任何错，直到日志里 `archive=0` 才暴露。现在由 `_factor_panel()`（`base.py:237-247`）统一取出真实面板。**去重必须能自证生效**：`value_rejected`、`archive_size`、`max_observed_corr` 三个字段都要写进 `dedup_summary`（`base.py:161-167`），否则"没拦到"和"压根没运行"在结果上长得一模一样。

### 10.3 竞品做法对照

下表把业界几类去冗余做法放在同一口径下比较，阈值、判据层次与处理动作分开列，便于看清各自解决的是三类冗余中的哪一类。

| 系统 | 冗余判据 | 关键阈值 | 处理动作 | 源码依据 |
|---|---|---|---|---|
| RD-Agent（微软） | SOTA 库与新因子的横截面 Pearson 相关，按 `datetime` 分组取时间均值，`IC_max.unstack().max(axis=0)` | 与任一库内因子相关 `≥ 0.99` | 剔除；全被剔除抛 `FactorEmptyError` | `factor_runner.py:46-61,107-110` |
| LLM-Alpha-Mining-Framework | 18-niche MAP-Elites 行为档案 + anti-paraphrase 六层：sanitizer / complexity / Alpha101 共享子树 / archive 共享子树 / coverage / rank correlation | `max_shared_subtree=5`、`max_abs_corr=0.7`（仅在 validation 上 sweep 后冻结） | 分 niche 引导 EXPLORE，拦截"一个 idea 的 20 种改写" | `evo/archive.py:1-25,210-304`、`fitness.py:8-16,38-41`、`config.py:69-105` |
| crypto-factor-lab | 验证期 Spearman 相关 | `\|corr\| ≥ 0.95` | 标记 `duplicate`，按 score 贪心留代表 | `mining.py:234,395-421` |
| AlphaGen | 新因子与池内成员的 mutual-IC（IC 时间序列相关） | `> 0.99` | 直接拒收，不入池 | `linear_alpha_pool.py:173-189` |
| AlphaForge | 无效/同质因子过滤：NaN 占比、唯一值比率、与 zoo 相关 | `NaN > 0.8`、`唯一值 < 0.01`、与 zoo 相关超阈值 | 打分置 0，不进 zoo | `train_AFF.py:127-144` |
| FactorMiner（本章） | 源码 MD5 + 按截面 rank 展平后的面值 \|Pearson\| | `0.99`；archive 容量 40；共同有限值 `< 50` 不判 | 硬去重丢表达式，软去重丢席位 | `core/miner/paradigms/base.py:15-159` |

读这张表要抓住三处判断。

第一，**阈值分成两档，不能互换**。RD-Agent、AlphaGen、FactorMiner 的 `0.99` 判的是"是否等价、要不要占一个席位"，crypto-factor-lab 的 `0.95` 与 LLM-Framework 的 `0.7` 判的是"是否太像、该不该继续往这个方向探索"。一个是准入闸门，一个是探索导向，把 `0.7` 拿来当去重阈值会把大量互补因子误杀，把 `0.99` 拿来当多样性阈值则几乎拦不住任何东西。

第二，**结构法与数值法互补而非替代**。LLM-Framework 的六层 anti-paraphrase 从语法结构入手（共享子树、Alpha101 子树、archive 子树、coverage），抓的是"换汤不换药"，好处是不必先算面值；但当候选横跨 AST、Python 源码、张量通道三种形态时，统一的结构指纹很难定义。FactorMiner 的面值相关从数值结果入手，与表达方式完全无关，代价是每个候选都要先 `compute` 一遍面板。两法覆盖的正是不同类别的冗余。

第三，**有的做法其实不是去重**。AlphaForge 的 `NaN > 0.8`、唯一值比率 `< 0.01` 本质是"无效因子"质量闸门，把去重问题转成了打分置零；FactorMiner 没有照搬，因为常数与全空因子在评估器里已有 Anti-Bloat 告警拦截。诚实地标注"这一格解决的不是同一问题"，比把所有系统塞进一张表更可取。

结论是：没有单一判据能覆盖三类冗余。FactorMiner 用 MD5 + 面值相关，是以最小的实现成本覆盖第 1、2 类和反向的第 3 类；明确留下的边界是**跨轮面值正交暂缓**——软去重只在单代内比较 archive 里最多 40 个签名，跨 run 的正交目前靠 MD5 与 AlphaPool 的 mutual-IC。要对全库几十个因子做面值正交，就得重算全部面板，成本高，属于"知道该做、但排在正向 OOS 证据之后"的那一类。

### 10.4 从单因子 fitness 排序到组合目标直接驱动搜索

去重解决的是"别把同一条证据数很多遍"，但还有一个更结构性的问题：即便 K 个因子彼此正交，按单因子 fitness 排序取 Top-K 再事后组合，仍未必得到好组合。传统做法隐含了一个未经验证的假设——"单因子好，组合也好"。组合的表现取决于因子**之间**的互相关，不是各自的边际 RankIC。两个各自 RankIC 0.05 却 mutual-IC 0.99 的因子，组合起来几乎不增加信息；两个 RankIC 只有 0.03 但互相正交的因子，组合后反而更稳。`docs/research/industry_factor_mining_survey.md:698` 把这句话说得很直白：我们的搜索目标是单因子 fitness、组合是事后独立的一步，而 AlphaGen / AlphaForge 的搜索目标直接是组合增量——**这正是"挖出一堆 IC 还行、组合起来亏钱"的结构性原因之一**，不是玄学，是目标错位。

修正方向是把组合目标写进搜索循环：让新因子得到的 reward 等于"它给池子带来多少增量"，而不是"它自己 IC 多高"。AlphaGen 的做法最具代表性，`MseAlphaPool.optimize`（`linear_alpha_pool.py:285-329`）最小化：

```
L(w) = wᵀMw − 2wᵀc + 1 + α‖w‖₁
```

符号解释：`w` 是池内 K 个因子的权重向量；`M` 是 mutual IC 矩阵（`Mᵢⱼ` = 成员 i 与 j 的 IC 时间序列相关，刻画冗余）；`c` 是 single IC 向量（`cᵢ` = 成员 i 的单因子 IC）；常数 `1` 是目标收益的方差归一项；`α‖w‖₁` 是 L1 稀疏项。前三项展开正是组合 IC 的均方误差代理：`wᵀMw` 是组合方差、`−2wᵀc` 是组合与目标的协方差，因此最小化 `L` 等价于**直接优化组合 IC**，而非名字里那个 `Mse` 所暗示的预测 MSE。`α = 5e-3` 让弱因子权重自动归零，等价于软淘汰。求解用 Adam（`lr = 5e-4`、10000 步、`patience = 500`）；当 `α ≈ 0` 时问题退化为普通最小二乘，可直接 `np.linalg.lstsq(M, c)` 拿闭式解，这也是纯数学上最干净的路径。池容量取 10 / 20 / 50 / 100（`scripts/rl.py:300-304`），新因子先算对池内所有成员的 mutual IC，任一 `> 0.99` 直接拒收；超容量时剔除 `|w|` 最小者，若新因子自己最差就回滚。

同族的 `MeanStdAlphaPool`（`:336-404`）换的是目标函数：用逐日 `batch_pearsonr` 直接优化 `ICIR = mean/std`，或更保守的 `LCB = mean − β·std`。差别在于前者把"稳定性"写进目标，后者把"悲观下界"写进目标，而不只是优化均值——这在处理 IC 波动大的加密日频数据时尤其有意义。

AlphaForge 走的是另一条路（`combine_AFF.py:160-243`）：不优化一个固定池，而是从验证集首日逐日 walk-forward，`shift = 21`，`begin = cur − window − shift`，**只用 `begin:cur−shift` 的历史窗口**算各因子的 `icir / ricir / retir`，选出 top-N 后对该历史窗口做 `torch.linalg.lstsq`（带常数列）求当日系数，权重逐日变化并全部保存。`shift = 21` 是明确的防前视设计：预测当日时，拟合所用的最后一根收益 bar 距离当日至少 21 根。

| 系统 | 组合目标 | 权重更新方式 | 防前视手段 |
|---|---|---|---|
| 单因子排序 + 事后组合 | 各因子边际 fitness | 样本内一次拟合后固定 | 仅依赖训练/验证切分 |
| AlphaGen `MseAlphaPool` | `wᵀMw − 2wᵀc + 1 + α‖w‖₁`（组合 IC） | 每加入一个因子重优化全池 | 权重只在 in-sample 拟合 |
| AlphaGen `MeanStdAlphaPool` | ICIR 或 LCB | 同上 | 同上 |
| AlphaForge 动态组合 | 逐日 top-N 的加权预测 | 逐日 `torch.linalg.lstsq` | `shift = 21` |
| FactorMiner 静态 AlphaPool | 组合 RankIC 的岭回归代理 | 每次 admission 后重优化 | `weight_fit_shift = 21` |

判断是：动态权重表达力最强，却也最危险。在结果产出 R 仍为 1（尚无一个通过闸门且含成本为正的因子）时引入逐日重估，等于允许模型每天重新解释一遍噪声，把过拟合包装成"自适应"。`docs/research/platform_maturity_gap.md` 把动态权重、风险模型、归因层排到路线图 S5——"至少有一个能上线的因子之后"——是有因果依据的排序，不是保守。FactorMiner 因此停在静态版：权重只在样本内拟合一次，之后固定，OOS 的 RankIC 才是对泛化能力的诚实度量。

### 10.5 FactorMiner 实现：静态 AlphaPool 与权重贯通回测

`core/miner/pool.py:74-150` 的 `AlphaPool` 是这一层的落点。构造参数（`pool.py:77-85`）逐一对得上前面的设计：`capacity = 10`、`mutual_ic_max = 0.99`、`weight_fit_shift = 21`、`reg_lambda = 5.0`、`min_obs = 200`、`weight_norm = "l1"`。

`mutual_ic`（`:131-145`）取新因子 IC 时间序列与每个成员 IC 序列的 `|Pearson|` 最大值，`evaluate_admission`（`:148-154`）以 `> mutual_ic_max` 拒收，理由写在 docstring 里：高相关意味着候选预测的是与某个成员相同的截面模式。注意这里比的是 **IC 时间序列**，与 10.2 的软去重比 **因子面值** 是两个层次——一个在入门前查"写法是否重复"，一个在入池时查"预测模式是否重复"，互不替代。

`_target_for_shift`（`:112-119`）是防前视的关键三行：

```
tgt = np.roll(self._returns, -shift, axis=0)   # 未来收益向前滚 shift 期
tgt[-shift:, :] = np.nan                       # 尾部 shift 行置 NaN，杜绝环形回卷
```

`np.roll` 是环形回卷，尾部会卷回最早的历史收益。若不把尾部置 `NaN`，权重回归就会拿"因子的未来"去拟合"收益的过去"，凭空造出一条泄漏通道。这一行看着不起眼，却是组合 IC 是否可信的分界线。

`_optimize_weights`（`:215-239`）把每个成员面板展平成列，拼成设计矩阵 `X`，在有限值掩码上解岭回归：

```
XtX = XmᵀXm + reg_lambda · I
w   = np.linalg.solve(XtX, Xmᵀy)
```

有效样本 < `min_obs`、目标唯一值 < 2、或矩阵奇异（`LinAlgError`）时退化为等权 `1/K`；随后按 `weight_norm` 做 L1（`w / Σ|w|`）或 L2（`w / ‖w‖₂`）归一。满容量时 `_admit_with_replacement`（`:183-212`）走贪心替换：逐个试把某成员换成新因子，取组合 RankIC 提升最大的位置替换，没有任何提升就拒收并记 `no_improvement`。

装配入口在 `core/miner/paradigms/base.py:334-364` 的 `_finalize`，由配置 `finalize_method` 选择 `"linear"`（默认）或 `"alphapool"`。`_finalize_alphapool`（`:412-485`）把候选按 fitness 排序取 `top_m = 30` 逐个 `pool.admit`，不足 2 个非冗余成员就返回 `None` 回退到线性策略，最后把池权重装进 `LinearCombinedFactor` 并 prepend 到结果列表。默认的 `_finalize_linear` 走 `core/miner/expressions.py:309-370` 的 `fit_linear_combination`：同样解 `XtX = XmᵀXm + λI`、`w = solve(XtX, Xmᵀy)`，但 `reg_lambda = 1.0`、`min_obs = 60`，且不设容量、不做 mutual-IC 准入，只按相关性阈值挑几个 diverse 子因子。两者的差别正是"一次性事后组合"与"容量池 + 准入 + 重优化"的差别。

权重要真正影响净值曲线，还得贯通四段链路，这是最容易断链、也最容易被忽略的一段：

1. `LinearCombinedFactor.to_dict / from_dict`（`core/miner/expressions.py:244-262`）序列化为 `{"type": "linear_combination", "weights": [...], "sub_asts": [...]}`。
2. `director._save_excellent_factors`（`core/miner/director.py:161-371`）先给整批候选预分配 `fac_{uuid[:8]}` id（`:276`），再对 `LinearCombinedFactor` 把每个子表达式对应的 id 写进 `logic["member_factor_ids"]`（`:326-333`）。没有这一步，组合因子只能以匿名 sub-AST 落库，回测侧根本不知道权重该挂在谁身上。
3. `core/backtest/backtest_engine.py:137-200` 的 `resolve_signal_weights` 递归展开：读到 `type == "linear_combination"` 且带 `member_factor_ids` 时，按 `weight * sub_w` 把父层权重乘进每个成员（`:184-185`），嵌套深度 `> 4` 直接抛错（`:172-173`），防止组合套组合无限展开。
4. `load_factor_signals`（`:203-295`）：每个因子先按 `(timestamp, factor_id)` 做截面 rank（`:273`），乘 `orientation`（`:274`），乘展开后的成员权重（`:275-276`），再按 `(timestamp, asset)` 求和（`:277-279`），最后除以 `Σ|w|`（`:280-281`）归一——保证不同 run、不同权重规模之间的信号量纲可比。`orientation_db_root`（`:207-230`）允许"方向从样本内库学、因子值只取 OOS 重算库"：符号在训练期冻结，验证段的信息无法回流进信号，这是严格留出里最容易被漏掉的一条。

这里有一个必须讲清的 bug 与修复：此前回测侧只用等权 `mean()` 合成成员，**AlphaPool 拟合出来的权重被完全抹平**——池子优化得再认真，到了净值曲线上跟随便挑几个因子没区别。`backtest_engine.py:142-148` 的 docstring 明确记录了这一点，`director.py:271-275` 的注释也说明预分配 id 就是为了让组合不再退化成匿名子式。这是典型的"优化层与执行层之间链路断裂"：两端代码各自都对，中间的 id 映射丢了，结果静默退化，不抛异常、不报错，只是净值 quietly 变差。修它的价值不在算法，在于把落库 schema 与读取端变成一条可测试的显式契约。

### 10.6 工程陷阱

1. **阈值设 0 会静默关闭，设过低会误杀**。`dedup_value_threshold = 0` 是官方开关（`README.md`），但关掉之后日志里只剩 MD5 命中，看起来"没有冗余"，实际是根本没检查。反过来把 `0.99` 下调到 `0.7`，会把大量互补因子当成改写拦掉——`0.7` 是探索阶段的多样性阈值，不是等价阈值。判重阈值必须绑定"一个权重符号能否替代"这个语义，而不是拍脑袋取个好看的数。
2. **archive 容量与单代比较成本要一起看**。软去重是"候选 × archive"两两算相关，`dedup_value_archive = 40` 是成本闸门；调大能跨轮多抓一些冗余，单代耗时却线性上升。更要清楚它的边界：软去重只在轮内生效，跨 run 的正交靠 MD5 与 mutual-IC，对全库几十个因子做面值正交需要重算全部面板，成本高，目前明确缓做。别把 `archive = 40` 误读成"全库已正交"。
3. **时变权重是"给噪声加自适应外衣"**。AlphaForge 的逐日 `lstsq` 很漂亮，但在 R = 1 时引入，等于让模型每天重新解释一遍噪声，把过拟合包装成自适应能力。等有了至少一个通过闸门、含成本为正的因子，再谈动态权重与风险模型，顺序不能倒。
4. **组合权重样本内拟合后固定，与 OOS 泄漏只隔一行**。`_target_for_shift` 尾部置 `NaN`、`weight_fit_shift = 21`、`orientation_db_root` 从样本内库学方向，三处共同构成防前视。任何一处被"顺手优化"掉（比如为了多几个样本去掉尾部 `NaN`，或直接用验证段推断符号），组合 IC 立刻被 in-sample 拟合抬高，OOS 结论随之失真。
5. **`min_assets` 与实际资产池不匹配，会产出"0 交易却报成功"的空回测**。回测默认 5 多 / 5 空、`min_assets = 10`，在 6 币预留池下每次调仓都被拒，产出"0 交易、0% 收益、成功"的假绿。修复是 `adapt_book_to_universe()`（`core/backtest/backtest_engine.py:442`）：按实际资产数取 `k = min(n_long, n_short, max(1, 资产数 // 3))`，6 币降为 2 多 2 空、`min_assets = 4`，20 币仍是 5 / 5、行为不变。组合层的一切统计检验都建立在"真的成交了"之上，空回测比亏损更危险，因为它不会触发任何告警。
6. **权重贯通是链路问题，不是算法问题**。`from_dict` → `member_factor_ids` → 递归展开 → `Σ|w|` 归一，任何一环缺位都会静默退化成等权，而且不抛异常。这类缺陷只能靠落库 schema 与回测读取端之间的契约测试暴露，不能靠"跑一遍看净值差不多"——恰恰因为等权与加权在小样本上常常看起来差不多。

### 10.7 本章小结

1. 去重不是收尾清理，而是搜索目标的一部分：它同时决定 `num_trials` 分母、因子池的有效维度 `K_eff`，以及后续所有统计推断是否诚实。
2. 三类冗余（源码等价、数值等价、经济含义等价）需要不同判据；MD5 覆盖第一类，按截面 `rank(axis=1)` 展平后的 `|Pearson| > 0.99` 覆盖第二类与反向的第三类，共同有限值 `< 50` 时拒绝下结论以免误杀。
3. 判重阈值 `0.99` 与多样性阈值 `0.7–0.95` 目的相反，混用必然误杀或漏放；20 币 2 代实测拦下 46 个候选（约 30%），`max_observed_corr = 1.000`，说明"多样性幻觉"是真实存在且可量化的。
4. 组合目标必须从"单因子 fitness 排序 + 事后组合"前移到搜索循环内部；AlphaGen 的 `wᵀMw − 2wᵀc + 1 + α‖w‖₁`（Adam / `lstsq` 闭式解）与 AlphaForge 的逐日 `lstsq`（`shift = 21`）是两条路线，FactorMiner 在 R = 1 之前选择静态版。
5. FactorMiner 的实现链路是 `AlphaPool`（capacity 10 / mutual-IC 0.99 / ridge λ = 5.0 / shift 21 / min_obs 200）→ `LinearCombinedFactor` → `member_factor_ids` → 回测侧递归展开与 `Σ|w|` 归一；任何一环断掉，权重都会被等权 `mean()` 抹平。
6. 最危险的失败全是静默的：软去重失效、环形回卷泄漏、空回测报成功、权重退化成等权，都不抛异常；只能靠显式报告字段（`value_rejected`、`max_observed_corr`、`effective_weights`）与契约测试把它们逼到台面上。
