## 第 15 章 从 IC 到 PnL：成本、组合与三次诚实的失败

> 本章回答：为什么「OOS IC 同向显著、|t| 4.17–5.45」的因子，含成本组合还是 −6.40%？本章把因子值一路推到净值曲线：分位多空组合的构造、换手与成本的恒等式、事件驱动回测的成交时点、真实资金费聚合，然后完整复盘项目里四次真实实验的负数结果。这是全书最不「励志」也最有价值的一章。

### 14.1 从因子值到组合权重

`core/evaluation/portfolio_eval.py:63-190` 的 `long_short_returns()` 把因子值变成每期净收益：

```python
r_df    = r_df.reindex(index=f_df.index, columns=f_df.columns)   # 严格对齐，不隐式 reindex
ranks   = f_df.rank(axis=1, pct=True)                            # 每期截面百分位秩
is_long = ranks >= 1 - q                                          # q = 0.20
is_short= ranks <= q
w_long  = +0.5 / n_long        # 多头总权重 0.5
w_short = -0.5 / n_short       # 空头总权重 -0.5 → dollar neutral，gross = 1.0
gross   = Σ|w| = 1.0

ls_t            = Σ_i w_{t,i} · r_{t+1,i}                        # 当期毛收益
turnover_t      = 0.5 · Σ_i | w_{t,i} − w_{t−1,i} |              # 组合权重换手
cost_t          = turnover_t · cost_rate                         # cost_rate = 0.0018 往返
cost_adj_return = mean(ls_t) − mean(cost_t)
sr              = cost_adj_return / std(ls_t)                    # 每期净 Sharpe → DSR 输入
sharpe_annual   = (mean(ls_t) / std(ls_t)) · √A                  # 仅展示用
ls_t_stat       = NW-HAC(ls_t, lags = max(5, rebalance_bars))
```

几个设计细节：

- **gross 归一到 1.0、美元中性**：多空各 0.5，共同市场冲击在截面上抵消。这让「beta 伪装成 alpha」更难，也让第 14 章的半合成 DGP 能注入 `market_frac=0.6` 的共同因子。
- **`rebalance_bars > 1` 时按 `idx = arange(n)//hold*hold` 前向持有**，权重只在调仓日更新。`_resolve_gate_rebalance_bars()`（`evaluator.py:102-123`）优先读 `fitness.gate_rebalance_bars`，否则镜像 `target.horizon_bars`——**评估的调仓周期必须和标签周期一致**，否则成本估算与信号衰减对不上。
- **`tradable` 要求两腿均非空**：只有多头或只有空头有价格的一期不产生可交易收益，不能算作有效观测。
- 返回键：`mean_return / std_return / sharpe / hit_rate / turnover / cost / cost_adj_return / n_obs / n_assets_long / gross / ls_t`，映射到落库的 `ls_return / ls_vol / ls_sharpe / ls_hit / ls_turnover / ls_cost / ls_t`。

单资产 Series 走另一条路：`timing_returns()`（`:193-287`）用 `rolling(lookback=252).rank(pct=True)` 做**只用当期信息的滚动分位择时**，附 `ls_exposure`。这个分支让 BTC 1d 的 12 个候选第一次拿到真实判决（最好 `t=2.31 / p=0.021 / OOS RankIC 0.121`），此前恒为 `t=0 / p=1`。

### 14.2 成本恒等式：一处定义，两处使用

P0.5 之前，项目有两套成本：fitness / 闸门侧 `gate_cost_rate = 0.0018`，回测侧 commission + slippage + 常数 funding，两边不同源。`core/experiment/costs.py:17-45` 把它们锁成一个恒等式：

```
gate_cost_rate = 2 × ( commission_rate + slippage_rate )
默认           = 2 × (0.0004 + 0.0005) = 0.0018      （18 bp 往返）
consistent     = |delta| < 1e−6
funding        = 独立计费（funding.mode 默认 "constant"）
```

`resolve_cost_params()` 返回 `implied_round_trip / delta / consistent`；正式 run 的 `consistent = True`。**「成本入判定」成立，但只有恒等式统一后才成立**——这是 `framework_maturity_gap.md` §4.3 的一处口径收窄：「成本模型已闭合」在早期是不成立的。

为什么是 `2×`？一次完整往返包含建仓与平仓两次换手，每次都付 `commission + slippage`。而 `turnover_t = 0.5·Σ|Δw|` 已经是「单边换手」的归一形式，乘 `2×` 才对应双边费率。这个系数若搞错，成本会被低估一半，足以把一个亏损策略判成盈利。

另一个方向的错误是**把 funding 当成交易成本**。资金费是持仓成本，按 8h 结算、与持仓方向和时间相关，不与换手相关。它必须独立建模。

### 14.3 事件驱动回测：成交时点决定一切

`core/backtest/backtest_engine.py` 用 `ml4t-backtest` 的事件驱动引擎。`CrossSectionalFactorStrategy`（`:55-118`）的 `on_data`：

```python
self._bar += 1
if self._bar == 1 or (self._bar - 1) % rebalance_every == 0:
    rows = collect(asset, signal, price)          # 有效资产 < min_assets 直接返回
    rows.sort(by=signal, descending=True)
    longs, shorts = rows[:n_long], rows[-n_short:]
    per = equity / (n_long + n_short)
    desired[a] = ± per / price
    for a in targets ∪ holdings:
        submit_order(a, desired[a] - held_qty[a])
```

`build_backtest_config()`（`:417-439`）的关键参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ExecutionMode` | `NEXT_BAR` | 信号在 t 形成、t+1 成交 |
| `ExecutionPrice` / `next_bar_execution_price` | `CLOSE` | 下一根收盘成交 |
| `commission_rate` | 0.0004 | 百分比手续费 |
| `slippage_rate` | 0.0005 | 百分比滑点 |
| `initial_cash` | 1,000,000 | 初始资金，用于按 `equity/(n_long+n_short)` 计算每腿名义仓位 |
| `n_long / n_short / rebalance_every / min_assets` | 5 / 5 / 5 / 10 | 由 `adapt_book_to_universe()` 按实际资产数自适应 |
| `allow_short_selling / allow_leverage` | True | 允许多空双向持仓与杠杆，配合 `desired[a] = ±per/price` |
| `skip_cash_validation` | True | 关闭现金校验，避免 dollar-neutral 组合因双边保证金被拒单 |

`run_backtest()`（`:469-617`）的 summary 汇总 `total_commission / total_slippage / total_funding / total_costs / avg_turnover`，产物是 `equity.csv`（净值 / 累计收益 / 回撤）、`prices.csv`、`signals.csv`、`summary.csv`。**方向从 `orientation_db_root`（样本内库）学习**，`infer_orientation()`（`:121-134`）用 Spearman(factor, forward_return)，少于 10 行默认 −1；评估窗口的因子值只取 OOS 重算库，`strict_oos` 标志写进 summary。这是防止「用 OOS 数据反推因子符号」的关键隔离。

合成因子的权重贯通见第 11 章：`resolve_signal_weights()`（`:137-200`）递归展开 `linear_combination` 的 `member_factor_ids`，权重相乘传递；`load_factor_signals()`（`:203-295`）对每个因子做截面 `rank(method="first")` → 乘 `orientation` → 乘权重 → 按 `(timestamp, asset)` 求和 → 除以 `Σ|w|` 归一。此前这里用等权 `mean()` 把 AlphaPool 拟合的权重抹平了，是一个「功能做了但结果没生效」的典型 bug。

### 14.4 真实资金费：从常数网格到 8h 流

早期 `build_funding()` 是 `grid["rate"] = 0.0001` 的常数网格。`load_funding_series()`（`:346-380`）改为读取真实 8h 结算文件：

```python
_FUNDING_FREQ = {"1d":"1D","4h":"4h","1h":"1h","15m":"15min","5m":"5min","1m":"1min"}
series = raw.resample(freq).sum(min_count=1).dropna()   # 按 bar 频率聚合 8h 结算
# build_funding 构造 (timestamp, asset) 全网格，默认 rate，有真实序列时 map 后 fillna(rate)
attrs["funding_source"]            = "crypto_streams (N assets)" | "constant"
attrs["funding_assets_matched"]    = N
```

`sum(min_count=1)` 的含义是：一个 1d bar 覆盖 3 次 8h 结算，应把三段费率相加；若某 bar 完全没有结算记录，保持 NaN 以便回落到配置常数，而不是填 0 假装免费。正式 run 里 `funding_source` 命中 20 个标的；universe holdout 的机制验证 run 命中 6 个标的。

`adapt_book_to_universe()`（`:442-466`）：`k = min(n_long, n_short, max(1, available_assets//3))`，返回 `n_long=k, n_short=k, min_assets=2k`，`available<2` 抛错。6 币 → 2/2/4，20 币仍 5/5/10。这条修复针对的是「0 交易 0% 收益却报成功」——**一个不产生任何交易的回测，比一个亏钱的回测危险得多**，因为它会被当成「策略中性、暂不启用」而不是「配置错了」。

### 14.5 四次诚实的失败（全部是真实落盘结果）

这一节的数字不是演示，是 `user_workspace/reports/` 与 `user_workspace/runs/` 里的实际记录。

**（1）早期 6 因子严格 OOS（`oos_validation_2025H1.md`）**

| 口径 | 总收益 | 零成本 | Sharpe |
| --- | --- | --- | --- |
| 样本内 2024 | −17.87% | −10.41% | −0.55 |
| OOS 2025H1（泄漏版方向） | −6.59% | −4.19% | −0.24 |
| **OOS 2025H1（严格，方向冻结自 2024）** | **−11.18%** | **−7.37%** | **−1.14** |

逐因子 `|RankIC|` 均值 `0.0568 → 0.0280`（衰减至 49%），**6 个里 2 个方向翻转**。零成本仍亏 → 因子没有 alpha，不是成本问题。这次失败直接触发了整个 P0 统计闸门工程。

**（2）P0 一次性严格 holdout（`p0_holdout/README.md`）**

设计：mine `2023-04→2024-12`、验证 `2025H1`、一次性 strict holdout `2025-07→2026-11`；GP 60×20 代，实际评估 **787 个候选**；闸门全开。

- 4 个最终候选 → **2 INSPECTED / 2 DISCOVERED_UNVERIFIED**；
- **IC 层面成立**：3 个可重算候选在 holdout 上全部同向显著（`|t|` 4.17–5.45，无方向翻转），通过组等权组合 RankIC +0.0577 / t +4.11；
- **经济层面不成立**：通过组含成本 **−6.40%**（Sharpe −0.07），零成本仅 **+2.22%**；**被拒的 `fac_0edecf9e` 反而净 +23.35%**（Sharpe 0.57）。

原因写在报告里：通过组十分位收益不单调、尾部价差仅约 0.006%/日（年化约 1.5%），RankIC 显著不等于可交易；5 日调仓成本 8.6% 远高于毛收益。**结论：闸门能防「OOS 方向翻转 / IC 崩塌」，不能排序经济价值。**

**（3）P0.5 收益口径成本闸门（`p0_5_return_gate.md`）**

`cost_adj_return` 从「IC 口径的某种代理」改成**分位多空组合的每期净收益**（gross 1.0、美元中性、18 bp 往返、调仓频率默认 = `target.horizon_bars`），新增 `ls_return / ls_cost / ls_turnover / ls_sharpe / ls_t` 落库与可选 `ls_t_min` 闸门。用新口径复判 P0 四因子：**0/4 通过**，旧闸门放行的两个（毛收益为正、被换手吃光）被精确拦下。

核心结论比任何算法调优都重要：

> **必须在交易周期上挖。1 日目标 + 20 币的年化换手成本 6–17%，大于可得边际。**

**（4）端到端正式 run 与 universe 机制验证**

- `run_20261114T104814Z_b9eb49`：8 stages completed、641 bars / 0 warning、4 候选 / 4 落库 / **0 promoted**、`empirical_p` 4/4 已算（3 个被 `empirical_null_pass` 拦下）、`val_read_count=87`、5 折逐折重拟合、4 份 OOS 快照、真实 funding 命中 20 标的、`reproducibility=True`、mismatches `{}`、两次同种子运行收益只差浮点末位。**验证段回测 −4.43% / Sharpe −0.37**。
- `run_20261114T125520Z_2722fb`（universe holdout 机制验证）：6 币 OOS 快照、75 笔交易、**−20.53%**，`clean=False` 明确标注「仅验机制，不是独立证据」。
- 全库重审 `scripts/reaudit_factor_db.py`：84 个存量因子 → **0 通过**，6 个旧 `INSPECTED` 全部降级；主要拦截原因是成本后为负。

四个负数放一起，构成一条完整的经验曲线：**从「样本内显著」→「OOS IC 显著」→「成本后为负」→「闸门 0 放行」→「流水线全绿但仍无正向证据」**。每一步都是方法论进步，但没有一步改变 R=1。

### 14.6 为什么 IC 不能排序经济价值

把 §14.5 的教训写成可推广的机理：

| 断点 | 说明 |
| --- | --- |
| 相关 ≠ 单调 | RankIC 只约束整体秩相关；十分位收益可以完全不单调 |
| 中间 ≠ 尾部 | 交易只吃 Top/Bottom `q`，中间 60% 排得再好也不产生 PnL |
| 显著 ≠ 幅度 | 大样本下 `|RankIC| = 0.02` 也能 t > 4，但对应价差可能只有每日几个 bp |
| 毛收益 ≠ 净收益 | 换手成本与调仓频率成正比，高频弱信号必然被吃光 |
| 因子 ≠ 组合 | 单因子 IC 好，加入池后可能因 mutual-IC 高而毫无增量 |
| 回测 ≠ 实盘 | 容量、冲击、部分成交、funding、强平都未进入因子评价 |

因此评价体系的正确层次是：**IC / RankIC 做筛选 → 分位多空净收益做经济判定 → DSR 折减净策略 Sharpe 做统计判定 → 事件驱动回测做执行校验**。跳过中间任何一层，都会得到「统计上漂亮、账上亏钱」的结果。

项目把这件事固化成了 P1 的一次改造：DSR 从折减 IC-IR 改为折减 `sr = cost_adj_return / std_return`。理由已经在第 13 章写过——IC-IR 无量纲，奖励「稳定但很小」的因子；策略净 Sharpe 随真实边际增大、随成本变重而减小。**把统计判定锚定到经济口径，是这条经验曲线最重要的工程产出。**

### 14.8 工程陷阱

1. **把 `0.0018` 写成单边成本**。它是往返成本 `2×(0.0004+0.0005)`；漏掉 2× 会让成本减半。
2. **调仓周期与标签周期不一致**。`gate_rebalance_bars` 必须镜像 `horizon_bars`，否则信号衰减与换手成本对不上；P0 的 5 日调仓成本 8.6% 就是这样吃掉毛收益的。
3. **评估窗口反推方向**。`orientation` 必须从 `orientation_db_root` 的样本内库学，不能用 OOS 数据。
4. **因子值与收益隐式 reindex**。`long_short_returns` 显式 `reindex(index=..., columns=...)` 并保留 NaN；任何自动对齐都可能把 t 期的因子配上 t+1 期的收益。
5. **0 交易却报成功**。小标的池必须 `adapt_book_to_universe()`，并用真实价格文件的回归测试锁定「必须真的成交」。
6. **同一指标多套口径**。因子值变化 / 排序变化 / 权重换手三种 Turnover 不能混；只有 `0.5·Σ|Δw|` 能乘成本率。
7. **用零成本结果讲故事**。P0 里「零成本 +2.22%」与「含成本 −6.40%」同时存在；只报前者就是选择性呈现。
8. **把流水线全绿读成盈利**。八阶段全通过、`reproducibility=True`、两次同种子只差浮点末位，证明的是过程可复现可审计，**不等于挖到了赚钱的因子**。

### 本章小结

1. 分位多空组合是「IC → PnL」的桥：`rank(axis=1, pct=True)` → 前后各 `q=0.20` → 多空各 0.5、gross 1.0、美元中性 → `turnover = 0.5·Σ|Δw|` → `cost = turnover × cost_rate`。
2. 成本恒等式 `gate_cost_rate = 2 × (commission + slippage)`（默认 0.0018）把闸门与回测锁到同一来源；funding 是持仓成本，必须独立建模并按 8h 结算聚合。
3. 事件驱动回测用 `NEXT_BAR / CLOSE`，方向从样本内库学、因子值取 OOS 重算库；合成因子的 `member_factor_ids` 权重必须递归展开，否则 AlphaPool 拟合权重会被等权抹平。
4. 四次真实失败构成完整经验曲线：早期 6 因子 OOS −11.18% → P0 含成本 −6.40%（被拒因子反 +23.35%）→ P0.5 新口径 0/4 → 正式 run −4.43% / 0 promoted。每一步是方法论进步，但没有一步改变 R=1。
5. IC 不能排序经济价值，断点有六个：相关≠单调、中间≠尾部、显著≠幅度、毛≠净、因子≠组合、回测≠实盘。
6. 最重要的工程产出是把 DSR 从折减 IC-IR 改为折减**成本后的每期净策略 Sharpe**——让统计判定锚定经济口径。
7. P0.5 的根本结论是结构性的：**1 日目标 + 20 币的年化换手成本 6–17% 大于可得边际，必须在交易周期上挖**。这不是调参能解决的问题。
8. 绿色流水线只证明过程可复现、可审计。这句话在第 1 章出现过，在这里有了四个负数作为注脚。
