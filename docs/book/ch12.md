## 第 12 章 过拟合的数学：max of noise 与选择偏差

> 本章回答：为什么「因子样本内 IC 显著、样本外全亏」不是运气不好，而是数学上的必然？本章把搜索过程写成一个极值统计问题，推导「试得越多、冠军越假」的定量关系，再逐条清点选择偏差进入研究的所有通路。读完这一章，读者应该能自己算出：在给定的试验次数下，一个因子至少要有多强，才值得被继续讨论。

### 11.1 一个思想实验：1000 个纯噪声因子

设真实世界中因子与收益**完全无关**。你写了一个 GP 挖掘器，生成 `K = 1000` 个候选，每个候选在 `T` 期数据上算出一个 IC 序列。在零假设下，每个候选的 `t` 统计量近似 `N(0,1)`，于是：

```
P( 某个候选 |t| > 1.96 ) = 1 − (1 − 0.05)^1000 ≈ 1 − e^(−50) ≈ 1
P( 至少 1 个 |t| > 3.29 ) = 1 − (1 − 0.001)^1000 ≈ 63.2%
```

也就是说，**在纯噪声里搜 1000 次，几乎必然能找到「p < 0.001」的因子**。这不是模型有问题，是使用 p 值的方式有问题：单次检验的显著性只在「只检验了一次」时成立。

把这个结论写成一般形式。若单次检验的拒绝域是 `p ≤ α`，做 `K` 次独立检验后至少一次假阳性的概率（族错误率 FWER）为：

```
FWER = 1 − (1 − α)^K  ≈  K·α        （Kα 很小时）
```

| K（试验次数） | α = 0.05 下的 FWER |
| --- | --- |
| 1 | 5.0% |
| 20 | 64.2% |
| 100 | 99.4% |
| 787（项目一次真实搜索） | ≈ 100% |
| 1 728 000（AlphaMaster 理论上界） | ≈ 100% |

`docs/research/optimization_plan.md` 记着一个把这件事讲得最透的实测：6 个旧因子在 `n_trials = 787` 下被 DSR 全部拦下，而用 `n_trials = 1` 时 **5 个能过**。**分母就是结论**。同一批因子、同一套指标，仅仅因为「承认自己试过多少次」不同，就从「5 个显著」变成「0 个显著」。

### 11.2 极值的期望：Deflated Sharpe 的理论起点

比 FWER 更贴合交易研究的是「冠军的期望表现」。设每个策略的真实 Sharpe 都是 0，估计量标准差为 `σ_SR`，`K` 个独立尝试中的最大值期望约为：

```
E[ max_{k≤K} SR_k ] ≈ σ_SR · [ (1−γ)·Z⁻¹(1 − 1/K) + γ·Z⁻¹(1 − 1/(K·e)) ]
```

`γ` 是欧拉–马歇罗尼常数（≈0.5772），`Z⁻¹` 是标准正态分位函数。工程实现常用更简洁的上界（`core/evaluation/significance.py:219-229`）：

```
E[max SR] ≈ sr_0 + σ_SR · √( 2 · ln K )      // K=1 时返回 sr_0
```

这个式子的直觉极强：**噪声冠军的表现按 `√ln K` 增长**。想让「运气」翻倍，试验次数得按指数增加；反过来，试验次数从 1 增到 787，`√(2 ln 787) ≈ 3.65`，门槛抬了三倍多。

FactorMiner 把 `σ_SR` 取为 `1/√(n_obs − 1)`（每期 Sharpe 估计量的抽样离散度），因此**搜索预算本身决定了要多强的策略才算显著**：787 次试验 × 610 个观测下，基准日 Sharpe 约 0.148（旧 252 口径年化 2.35，7×24 口径 2.83）。`docs/research/optimization_plan.md` P1 把这条写成了结论：「**幅度感知筛选**——DSR 折减策略净 Sharpe 而非 IC-IR，代价是门槛变硬，因为搜索预算本身决定了要多强的策略才算显著」。

注意 `σ_SR ∝ 1/√n_obs`：**样本越短，噪声冠军越容易高**。这解释了为什么「用 1 年数据扫 1 万个参数」比「用 10 年数据扫 100 个参数」危险得多，也解释了为什么加密高频数据（bar 多但每 bar 信息量小、自相关强）不能简单地用 bar 数当有效样本量。

### 11.3 选择偏差的全部通路

「多重检验」常被狭义理解为「跑了多少个候选公式」。实际上至少有八条通路在偷偷增加 `K`：

| # | 通路 | 典型表现 | 为什么容易被漏计 |
| --- | --- | --- | --- |
| 1 | 候选公式搜索 | GP 每代 20 个 × 50 代 | 只记幸存者，不记失败者 |
| 2 | 参数 / 窗口扫描 | `window ∈ {5,10,20,60}`、阈值网格 | 觉得"只是调个参" |
| 3 | 超参调优 | 种群大小、变异率、学习率 | 记在实验笔记里，不进账本 |
| 4 | 验证集反复读取 | 每代每候选都读一次 `test_period` | 只有 epoch 数，没有 `val_read_count` |
| 5 | 时间段挑选 | 「这段行情效果特别好」 | 报告里只展示最好区间 |
| 6 | 资产池挑选 | 换一批币再跑 | 换机器后账本清空 |
| 7 | 失败后的「再跑一次看看」 | 修了 bug 重跑同一 holdout | 按命令次数算「一次」，不按信息暴露算 |
| 8 | 人工筛选与叙述 | 只汇报符合直觉的因子 | 没有原始 trace |

第 7 条最需要纪律。`research-protocol.md` §6 的原文值得引用：

> 最终测试的「一次」按**信息暴露**计算，而不是按成功命令次数计算。错误公式、失败流水线、调试脚本或不完整报告只要展示过该区间的结果，也会消耗该留出集。修复实现后必须使用新的未查看时期，或把旧时期降级为诊断/验证数据。

项目自己就吃过这个亏：2025-07→2026-11 这段 holdout 在 P0 实验里被**一次性揭示**后写入 `.holdout_ledger.json`，从此永远不能再用；P0.5 的正向验证只能等新的未触碰区间。`TODO.md` 里那句「一次 2025-07→2026-11 已消耗，不可复用」不是形式主义，是数据预算的会计账。

第 4 条则催生了 `val_read_count` 这个指标：`fitness` 以 `oos_exponent=0.5` 把验证段 RankIC 几何混合进优化目标，每个候选每代读一次验证集，正式 run 里读了 **87 次**。`docs/research/platform_maturity_gap.md` §4.2 特意做了口径澄清——这里被反复使用的是**验证段**，最终 holdout 由独立脚本重算、不进 fitness，所以准确表述是「验证集被当成训练集用」，不是「holdout 已泄漏」。这个区分很重要，因为两者的补救措施不同：前者靠 gap/embargo + 逐折重拟合 + 试验折减，后者只能换数据。

### 11.4 有效样本量：T 不等于 n

朴素 t 检验 `t = mean/(std/√T)` 假设 `IC_t` 独立同分布。三个因素会让它系统性虚高：

**（1）重叠标签。** 若 `horizon_bars = h > 1`，`r_t` 与 `r_{t+1}` 共享 `h−1` 根 bar 的价格路径，`IC_t` 序列至少有 `h−1` 阶自相关。有效样本量约 `T/h`，标准误被低估 `√h` 倍。

**（2）市场状态持续。** 波动率聚集、趋势段、资金费周期使 IC 序列自带正自相关，`t` 进一步虚高。

**（3）截面相关。** 多资产面板里，同一时点 N 个资产的残差共享市场冲击。若把 `T×N` 个观测当成 `T·N` 个独立样本，标准误会小到荒谬。`optimization_plan.md` Phase 1 有一条已知限制写得很直白：**「跨截面 N 较大时 IC 时间序列标准误极小，单因子原始 t 检验会『假性显著』，因此闸门不依赖原始 p，而靠 BH-FDR + DSR + OOS 一致性 + 成本后为正共同兜底」**。

修正方向有三类，第 13 章会展开：Newey–West HAC 稳健标准误、block bootstrap、以及把「试验次数」显式纳入的 DSR / 随机零分布。

一个相关的量化事实：LLM-Framework 用 21 滞后 Bartlett 核做 NW t，实测中位数 `|iid t| / |NW t| = 1.03`，于是诚实地写下「膨胀来自多重性而非自相关」。**这是很好的研究习惯：先测出误差来源，再决定修哪里。** 盲目加 HAC 而忽略 `n_trials`，等于把标尺的一端调准、另一端继续歪着。

### 11.5 算法与伪代码：把「试过多少次」变成一等公民

```python
# 反例：只记幸存者 → n_trials 被系统性低估
survivors = [c for c in candidates if c.fitness > threshold]
dsr = deflated_sharpe_ratio(sharpe, n_trials=len(survivors))   # ✗ 严重错误

# 正例：每一次评估都计入，含被去重拦下、超时、报错、未入短名单的候选
trace = ExperimentTrace()          # 跨 run 持久，按 signature sha256[:16] 去重
fdr_ledger = FdrLedger()           # 累积所有成功评估候选的原始 p
budget = HypothesisBudget()        # 可提交的单调快照，跨 clone 同步

for epoch in range(n_epochs):
    cands = miner.generate()
    cands, dedup_info = diversity_filter.filter(cands)
    for c in all_generated:                      # ← 不是 cands
        trace.record(c.signature, status=c.status)   # timeout / error / rejected 都记
        try:
            m = evaluator.evaluate(c)
            fdr_ledger.append(run_id, m.p_value)     # 原始 p 入累积族
        except Exception:
            pass                                     # 失败仍是「一次尝试」

n_trials = max(trace.num_trials,
               budget.snapshot["n_trials"]) + evaluator.total_evaluated
p_adj    = bh_fdr(fdr_ledger.cumulative_p_values())   # 历史 + 本轮全部假设
dsr      = deflated_sharpe_ratio(sr=sr, n_obs=n_obs,
                                 n_trials=n_trials, skew=skew, kurt=kurt)

# 报告里必须能看到这三个数，否则结论不可审计
report({"n_trials": n_trials, "val_read_count": evaluator.total_evaluated,
        "budget_utilization": budget.utilization()})
```

三处设计值得注意：

- **`n_trials` 取 `max` 而非求和**：`trace`、`budget` 快照与 `total_evaluated` 之间可能有重叠，`core/experiment/budget.py:81-97` 的 `resolve()` 取 `max(trace_num_trials, snapshot["n_trials"])`，`sync()` 单调取 `max`，`MAX_PVALUES=10000`。账本被设计成**只增不减**，因为试验次数一旦发生就不能被"优化掉"。
- **跨机器一致**：早期 `.fdr_ledger*.jsonl` 与 `.experiment_trace.jsonl` 被 `.gitignore` 忽略，fresh clone 后 `num_trials` 归零，DSR 门槛被系统性低估。修法是新增可提交的 `.hypothesis_budget.json` 单调快照，并在 `GET /api/gates/budget` 融合 portable snapshot。另一个同源 bug 是 `.gitignore` 曾忽略 `.holdout_ledger.json`——克隆后账本为空，一次性留出的守卫形同虚设。
- **失败也消耗预算**：`LLM-Framework` 的 `claim_evaluation` 在**读 holdout 之前**以独占方式写 `consumed_before_read`，失败评估同样消耗窗口。这是「信息暴露」会计的正确实现。

### 11.6 一条完整的病因链（实证）

`docs/research/alphamaster_competitor_review.md` §2.4.2 给出了一条可以从源码逐环验证的因果链，它是本章全部抽象的具象化：

```
9000 步 × 192 公式/步                      ← 理论上界 172.8 万次候选，无 num_trials 记录
        ↓
每个候选在【同一批 val 折】打分，val 与 train 只隔 20 bar、无 purge/embargo
        ↓
每步 val_score 刷新冠军 → 写盘 → 更新精英回放采样权重   (engine.py:876-912)
        ↓
无 BH-FDR / 无 DSR / 无随机零分布 / 无一次性 holdout    (全仓精确检索零命中)
        ↓
搜索直接优化 0.60~0.75 权重的【回测年化收益】           (backtest.py:615-626)
        ↓
max(170 万个噪声) 被当成 alpha
        ↓
index 组退化成 91.8% 做多的 beta；metals 年化 +117.7% 虚高；
组合 +35.52% 靠 1.37 年短数据放大
        ↓
作者自己在 STATUS_20250705.md 标注「❌ 不建议单独使用」「不是 alpha 而是 beta」
```

把这条链和 FactorMiner 早期 OOS 的 `−11.18% / Sharpe −1.14` 对照，会发现**是同一个失败模式**：搜索强度足够、证伪机制为零。差别只是 FactorMiner 做了严格 OOS 并当场发现，AlphaMaster 是在策略状态档案里事后诊断。

还有一个更微妙的教训在同一份报告 §2.4.3：作者内部诊断诚实，但给面向用户的 AI 分析器写的 system prompt 是「不要轻易下『过拟合』结论，尽量不要提过拟合」「不要因训练分远高于验证分就建议停止」（`web/ai_analyze.py:31,57`）。**内部结论与对外解说被拆成两套，统计闸门会被话术从下游架空**。这促成了项目里一条纪律：报告层禁止话术降级，所有显著性结论必须原样出现在用户可见报告里。

### 11.7 竞品对照：谁真的在数自己试过多少次

| --- | --- | --- | --- | --- | --- |
| qlib | ❌ | ❌ | ❌ | ❌ | 工程第一，无闸门 |
| RD-Agent | ❌ | ❌ | ❌ | ❌ | prompts 鼓励微小改进即替换最优 |
| AlphaGen / AlphaForge | ❌ | ❌ | ❌ | ❌ | 三段 OOS 但无校正 |
| gplearn / gpquant | ❌ | ❌ | ❌ | ❌ | 固定单次切分 |
| WorldQuant-LLM | ❌ | ❌ | ❌ | ❌ | 平台 Sharpe≥1.25 即通过，反复 sweep |

| **crypto-factor-lab** | ⚠️ 候选预算 | ✅ BH（手写，`fdr_q=0.05`） | ✅ 100 次置换 | ✅ holdout ledger（**仅 HTTP service 生效**） | ✅ 17 道闸门 |

行业结论（`industry_factor_mining_survey.md` §0.2 发现 1）：18 个仓库里**只有两家**把 FDR / Holm / Romano–Wolf / DSR / 随机公式零分布真正写进代码。多数 LLM 挖因子项目——包括微软 RD-Agent——没有任何多重检验校正。

需要如实标注两处收窄，避免把优势说满：

1. `crypto-factor-lab` 的 holdout ledger 只在 HTTP service 生效，CLI 主入口 `scripts/run_factor_mining.py:60-110` 不调用也不写 `holdout_end`（`framework_maturity_crypto_fit.md` §3.3）。「全链路强制」是过度表述。
2. FactorMiner 早期的三个零分布函数 `target_permutation_tstats / random_formula_null / empirical_p`（`significance.py:147,169,208`）**只有单元测试引用、主流程零调用**，一度被前序报告高估为领先项。后来才通过 `apply_promotion_gates(..., null_tstats=)` 接入，并把 `empirical_p / gate_pass / gate_checks` 写回因子档案。**「有实现」不等于「闸门已启用」**，这个差别值得在任何能力盘点里单独核对。

### 11.8 工程陷阱

1. **只把幸存者计入分母**。这是最普遍也最致命的一条，直接让 DSR 退化成普通 Sharpe 检验。项目 Phase 1.6 修的就是 `n_trials=1` 空转。
2. **账本被 gitignore / 存于内存**。换机器、重启服务、clone 后分母归零。修法是可提交的单调快照 + 启动时 fail-fast。
3. **把「再跑一次」按命令次数计**。信息暴露才是会计单位；调试脚本展示过留出区间也算消耗。
4. **修正多重检验却忽略有效样本量**（或反之）。HAC 与 DSR 修的是两件事；先测出膨胀来自哪里再动手。
5. **把验证集复用误写成「holdout 已泄漏」**，从而开错药方。前者靠时间隔离与试验折减，后者只能换数据。
6. **报告层选择性呈现**。作者诚实的内部诊断若被面向用户的解说淡化，整套闸门在决策链上等于不存在。
7. **以为「闸门越严越好」**。第 14 章会给出反面：在 `n_trials=182` 下闸门 MDE=0.10，远高于加密日频现实 IC 0.02–0.05，「0 promoted」有一部分是**功效不足**而非因子都不行。证伪系统自己也需要被证伪。

### 本章小结

1. 在纯噪声里搜 `K` 次，至少一次「显著」的概率是 `1 − (1−α)^K`；`K=1000, α=0.05` 时约为 1。样本内显著不是证据，是搜索的副产品。
2. 噪声冠军的期望表现按 `σ_SR·√(2 ln K)` 增长，而 `σ_SR ∝ 1/√n_obs`。**试验次数与样本长度共同决定门槛**；787 次试验下的基准日 Sharpe 约 0.148（7×24 年化约 2.83）。
3. 选择偏差有至少八条通路，其中「验证集反复读取」「失败后再跑一次」「只记幸存者」最常被漏计。`val_read_count` 与 `num_trials` 必须是报告的一等字段。
4. 有效样本量不等于 bar 数：重叠标签、状态持续、截面相关都会让朴素 t 虚高；FactorMiner 因此不依赖原始 p，而靠 BH-FDR + DSR + OOS 一致性 + 成本后为正共同兜底。
5. 三账本（ExperimentTrace / FdrLedger / HypothesisBudget）取 `max` 且只增不减，是为了让「试过多少次」跨 run、跨机器、跨克隆都不可被抹掉。
6. AlphaMaster 的 172.8 万候选病因链是本章全部抽象的实证；其与 FactorMiner 早期 OOS 全亏是同一个失败模式。
7. 「有实现」不等于「闸门已启用」。任何能力盘点都必须核对主流程调用，而不只是函数定义与单测。
