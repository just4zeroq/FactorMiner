## 第 10 章 神经网络：端到端表征与通道因子

> 本章回答：为什么一个因子可以是网络的某个输出通道，而不是一段可读公式；MSE 与 Pearson IC Loss 的联合目标怎样写出解析梯度、又为何比单纯拟合收益更贴近交易；训练张量与可落盘因子之间那条必须划清的边界；以及当权重被冻成 `.npz` 工件、通道被赋予谱系之后，工程上还有哪些会让样本外结论悄悄失效的陷阱。

### 9.1 从「符号公式」到「可微函数」

在 GP 范式里，因子是一棵由算子与终端拼成的表达式树：`ts_rank(ts_div(close, volume), 20)` 是离散、可枚举、可化简、可向风控解释的符号对象。神经网络把这件东西重新定义了。设面板特征矩阵为 `X`（行是样本、列是终端），一个单隐层网络的前向传播是

```
channels   = tanh( X @ W1 + b1 )       # 形状 (n, h)，h 个隐藏通道
prediction = channels @ W2 + b2        # 形状 (n,)，第 0 个可交易输出
```

此时「因子」不再是字符串，而是参数化映射 `f(X; W)` 的一个标量输出通道：算子塌缩为矩阵乘与非线性，终端塌缩为输入特征列，整棵表达式树变成一个计算图。这个视角转换是本章其余部分的前提——既然因子是函数的一个输出，那么「挖因子」就等价于「训练一个函数并从中挑出好用的通道」，而「保存因子」就等价于「保存能重算这个通道的全部参数」。

代价是一个绕不开的三角权衡。

**表示能力**最强：`tanh` 单隐层是通用逼近器，能表达算子树的任意连续组合，还能表达算子库里根本不存在的交互项，且不受 `MAX_EXPR_LENGTH` 一类长度约束。**可解释性**最弱：`W1` 的一列只是 h 个实数，没有「20 日动量」或「成交量冲击」这类经济语义，一个通道为何有效无法像符号公式那样归因到某个终端与窗口。**可复现性**则从「代码加数据即可重算」退化成一串依赖：权重初值与随机种子、标准化统计量、特征顺序、数据模式、`schema_version`——任何一项漂移，同一段「逻辑」都会算出不同数值。

正确的工程判断不是把黑盒包装成白盒，而是把可复现性从「表达式可读」整体迁移到「工件可重载 + 谱系可追溯」，并把可解释性缺口如实写进因子档案。`docs/architecture/v4_architecture_design.md:714-720` 之所以专门开一节讲边界，正是因为这三者的失衡最容易在「模型看起来训练得不错」时被忽略。

还有一层容易被跳过的因果：隐藏宽度 `h` 同时是「每轮候选因子数」和「模型的容量」。GP 每代靠变异与交叉产出一批新树，种群规模与单棵树的复杂度是两件事；NN 每轮只有一个模型、一次训练，候选数恰好等于 `h`，想多试几个思路只能把 `W1` 加宽。`hidden_dim` 默认 8（`my_custom_nn.py:56`）不是随手取的：太小则去相关约束没有腾挪空间、Top-K 无从挑选，太大则参数量随 `input_dim × h` 线性上涨，在 `nn_min_samples = 30` 这种小样本设定下几乎必然过拟合。换句话说，端到端范式把「搜索广度」这个原本由种群规模控制的旋钮，压进了网络结构超参里；后续所有关于早停、去相关、留出排名的设计，都是在给这个压扁的旋钮兜底。

数据侧的契约也随之改变。`NNDataAdapter`（`core/miner/nn.py:71-190`）负责把异构输入压成统一的稠密矩阵 `X`：`sequential_single` 模式下 `X` 的一行是一个时间戳，索引就是面板的时间轴；`cross_asset` 模式下先把「特征名 → DataFrame」求时间与资产的公共交集，再 `stack` 成 `(timestamp, asset)` 的 MultiIndex 样本（`:117-190`）。两种模式都只保留特征与标签同时有限的样本，但输出时必须 `reindex` 回**全量**索引，缺失处补 NaN（`:56-68`）——因子面值的长度与索引必须和行情面板严格一致，否则下游 `_validate_metric_inputs` 会因索引不匹配直接拒绝，而不是像某些实现那样静默对齐。

还要先说清一层定位：AlphaGen 的 `LSTMSharedNet` / `TransformerSharedNet`（`rl/policy.py:26-106`）是 RL 的策略网络，负责采样表达式 token，不是端到端监督的因子网络；qlib 里虽有 LGBM / NN 模型层，但本体不含自动因子挖掘器（`docs/research/industry_factor_mining_survey.md:178`）。二者都常被误列入「深度学习挖因子」，实际分别属于策略搜索与执行平台。FactorMiner 的 NN 是第三类：直接把隐藏通道当作候选因子评分。

### 9.2 训练目标：MSE 与 Pearson IC Loss 的联合目标

基础参考模型 `NumpyMLPFactorModel` 的损失是 `MSE + L2 + Gram 去相关`（`core/miner/nn.py:271-283`）；教学模板 `TemporalICFactorModel` 把它升级为显式面向交易目标的联合损失（`user_workspace/custom_miners/my_custom_nn_temporal.py:195`）：

```
L = (1 − α) · MSE + α · (1 − corr(pred, y))
```

符号解释：`pred ∈ Rⁿ` 是网络输出（n 为批次内有效样本数），`y` 是标准化后的**前瞻收益**标签，`corr` 是 Pearson 相关系数，`MSE = mean((pred − y)²)`，`α ∈ [0,1]` 在数值拟合与排序拟合之间插值，默认 **0.7**（`my_custom_nn_temporal.py:127`，亦可由 `nn_ic_loss_weight` 配置，`:390`）。代码中 `alpha = min(max(self.ic_loss_weight, 0.0), 1.0)`（`:178`），把配置值夹在合法区间内。

为什么直接优化 IC 比优化 MSE 更贴近交易？组合构建只消费横截面排序（或单品种时序分位），不消费 `pred` 的绝对量纲；RankIC 对任何单调变换不变，MSE 却对整体平移和缩放敏感，且平方项会被尖峰厚尾收益里的少数离群点主导。换句话说，一个把收益幅度拟合得很准、但把资产顺序排错的网络，MSE 可能很低而完全不可用；反之一个只保序不保幅的预测，多头空头组合照样成立。α = 0.7 表示主要优化排序，同时保留 0.3 的 MSE 项提供数值锚点——否则 `pred` 可以退化成任意尺度的排序向量，`L2` 与梯度裁剪失去意义，相关系数接近饱和时梯度也会失去信号。

把两个端点想清楚，α 的取值就不再是玄学。α = 0 时目标退化为纯回归，网络会认真拟合收益的幅度，而幅度恰恰是尖峰厚尾、最不可预测的部分；α = 1 时目标退化为纯相关最大化，损失对 `pred` 的整体平移与正缩放完全不变，`b2` 与 `W2` 的尺度因此可以任意漂移，训练只剩方向信息而没有数值锚点，早停判据 `loss + 1e-10 < best_loss` 也会因为数值抖动而提前触发。中间取值是在「排序正确」与「梯度良态」之间换一个折中。还要注意相关系数梯度的一个固有性质：当 `p̂` 与 `ŷ` 已经高度共线时，`∂r/∂pred` 的两项几乎抵消，梯度趋近于零，训练自然停滞——这不是实现 bug，而是目标函数本身的饱和，此时更需要 MSE 项把参数继续拉回有信息的区域。至于标签本身，可以选简单前瞻收益，也可以先做截面 rank 或 winsorize 再标准化；当前模板选了前者并保留 `return_type = "simple"`（`my_custom_nn_temporal.py:379-387`），因此异常值仍会通过 MSE 项进入训练，这一点在评估高波动品种时必须计入风险。

标签处理因此不能省。`TemporalICFactorModel.train` 先按训练段求 `target_mean` / `target_std` 并标准化标签（`:167-175`），再把 `pred` 与 `target` 分别中心化（`:176, :189`）；`NumpyMLPFactorModel.fit_scaler` 对特征做同样的事，且 `feature_std < 1e-12` 时置 1 防除零（`core/miner/nn.py:224-230`）。金融前瞻收益非正态、厚尾，α 越大越不依赖幅值，这本身是一种稳健化；但当前模板只做标准化而不做 winsorize，极端行情仍会通过 MSE 项与范数项进入梯度，这是保留的改进点，不该被当成已解决。

**相关系数的解析梯度**是这段实现最值得读懂的部分。记

```
p̂ = pred − mean(pred)          ŷ = y − mean(y)
r  = ⟨p̂, ŷ⟩ / (‖p̂‖ · ‖ŷ‖)
```

把均值、范数都视作 `pred` 的函数逐项求导再合并，可得

```
∂r/∂pred = ŷ / (‖p̂‖·‖ŷ‖) − r · p̂ / ‖p̂‖²
∂L/∂pred = (1−α)·(2/n)·(pred − y) − α·∂r/∂pred
```

第一项是 MSE 的常规梯度，第二项里 `−r·p̂/‖p̂‖²` 来自 `1/‖p̂‖` 的导数，是「提高相关性」的修正方向；分子里 `ŷ` 是常数（标签不随参数变）。之后按链式法则回传：`∂L/∂W2 = channelsᵀ·(∂L/∂pred) + l2·W2`，`∂L/∂channels = (∂L/∂pred) ⊗ W2`，再乘 `tanh` 的导数 `1 − channels²` 得到 `∂L/∂W1`。下面是一个带注释的代码块，对应 `my_custom_nn_temporal.py:183-225` 的真实实现。

```python
# MSE + Pearson IC Loss 的一次前向与解析反向（纯 NumPy，无自动微分框架）
for _ in range(epochs):
    channels   = np.tanh(normalized @ W1 + b1)      # (n, h) 隐藏通道
    prediction = channels @ W2 + b2                 # (n,)   可交易输出

    error = prediction - target
    mse   = float(np.mean(error ** 2))               # 数值拟合项

    # 相关系数：中心化后做归一化内积，分母加 1e-12 防零范数
    pc = prediction - prediction.mean()
    pn = float(np.linalg.norm(pc)) + 1e-12
    correlation = float(np.dot(pc, target_centered) / (pn * target_norm))
    loss = (1.0 - alpha) * mse + alpha * (1.0 - correlation)

    # 解析梯度：dMSE 是 (2/n)·error；dCorr 由 1/‖p̂‖ 的导数合并而来
    d_mse = (2.0 / len(target)) * error
    d_correlation = (target_centered / (pn * target_norm)
                     - correlation * pc / (pn ** 2))
    d_prediction = (1.0 - alpha) * d_mse - alpha * d_correlation

    # 链式回传到 W2 / b2 / W1 / b1，并叠加 L2 与 Gram 去相关
    dW2 = channels.T @ d_prediction + l2 * W2
    d_channels = d_prediction[:, None] * W2[None, :]
    d_pre_activation = d_channels * (1.0 - channels ** 2)   # tanh'
    dW1 = normalized.T @ d_pre_activation + l2 * W1
    gram = W1.T @ W1
    dW1 += diversity * 4.0 * (W1 @ (gram - np.diag(np.diag(gram))))
```

需要点明：这是**解析梯度**，不是框架自动微分。整个 FactorMiner NN 用纯 NumPy 实现，无 PyTorch 依赖；好处是工件小、可移植、无 GPU 也能跑，代价是每加一种结构都要自己推导并维护反向传播。

### 9.3 通道物化：训练张量与可保存因子的边界

「模型权重不是一个可以直接评分的因子」这句话必须讲透。`W1` 形状是 `(input_dim, hidden_dim)`，它既不与面板索引对齐，也不是对任一资产的打分；`ParallelEvaluator` 只接受 `pd.Series` / `pd.DataFrame` 形式的因子面值，或带 `requires_grad` 的训练张量（`core/evaluation/evaluator.py:183-188`）。把权重数组塞进因子档案，评估器无从计算 RankIC，闸门无从判定，Inspector 也无从展示——它不是一个因子，只是产生因子的参数。

因此训练阶段需要一个只承载计算图的临时对象。`MyCustomNNMiner.generate_candidates` 每轮只生成一个 `channel_idx=-1` 的 `MyNNExpression`（`my_custom_nn.py:113-120`），其 `compute` 在 `channel_idx < 0` 时返回 `NNTrainingTensor(data)`（`:35-43`），该对象 `requires_grad=True`，让评估器走「保留原始输出」分支，`update_model` 才能拿到反馈并完成一次训练（`:261-267`）。这个候选不入库、不展示、不交易，`docs/architecture/v4_architecture_design.md:716` 把它称作「完整模型输出，仅用于让 ParallelEvaluator 返回带梯度的原始张量」。

训练完成后才是**通道物化**：冻结模型快照、导出工件、按工件内容生成版本戳，再把每个隐藏通道冻成独立因子 `FactorExpressionTensor(model_version_id, channel_idx)`（`core/miner/expressions.py:147-164`）。其 `compute` 转调 `model_instance.predict_channel(data, channel_idx)`（`my_custom_nn.py:42-43`），由 `NNDataAdapter.restore_channel` 把一维预测还原成与全量索引对齐的 `pd.Series`；`cross_asset` 模式则 `unstack` 成「时间 × 资产」的 `pd.DataFrame`（`core/miner/nn.py:56-68`）。整数 `channel_idx` 从此成为因子的身份，而不再依赖某次内存中的模型对象。

这里 `clone()` 不是可有可无的拷贝。多轮挖掘中模型每轮继续训练，若通道表达式直接持有 `self.model` 的引用，那么上一轮入库的因子在下一轮会被新权重悄悄改写：同一个 `logic_hash`、同一个 `model_version_id`，重算出来的面值却变了，谱系追踪随之失效。`clone`（`core/miner/nn.py:318-326`）逐个复制 `W1` / `b1` / `W2` / `feature_mean` / `feature_std` 与 `b2`，把该轮权重冻成不可变快照；工件摘要取自这份快照（`:309-311`），因此版本戳与通道实际使用的参数严格对应。代价是每个轮次多驻留一份模型与预测缓存，教学模板为此在 `update_model` 结尾主动调用 `clear_prediction_cache()` 释放冻结快照里的完整矩阵（`my_custom_nn_temporal.py:418-430`）——长跑时内存边界与数值正确性同样重要。

去相关约束决定了这些通道是否值得挑。`W1` 的第 i 列是第 i 个隐藏通道在输入空间里的权重向量，令

```
gram     = W1ᵀ · W1
off_diag = gram − diag(diag(gram))
dW1     += diversity · 4 · (W1 · off_diag)
```

`gram` 的 `(i,j)` 元是通道 i、j 权重的内积；扣掉对角线后，非对角元不为零就说明两个通道在输入空间里不正交、倾向于学同一个信号。惩罚项等价于对 `‖off_diag‖²_F` 求导，系数 4 来自解析结果，`diversity` 默认 `1e-3`（`core/miner/nn.py:251`、`my_custom_nn.py:65`）。它不保证正交，只压低冗余，好让后续 Top-K 选择真的有多个不同信号可选。同一段代码还做两件稳定性工作：梯度总范数超过 `gradient_clip = 5.0` 时按比例缩放（`core/miner/nn.py:285-291`），以及 `patience = 20` 的早停——每轮把最优参数存下来，损失连续 20 轮不改善就回滚（`nn.py:293-308`）。尖峰厚尾标签下，这两项比换更大的网络更能决定训练是否收敛。

```python
# 通道物化 → 留出段排名 → 跨轮 Top-K（对应 my_custom_nn.py:298-334）
snapshot = model.clone()                          # 冻结快照，避免后续训练改写历史通道
artifact = snapshot.export_artifact()            # .npz 工件
model_version_id = "nn_" + sha256(artifact.payload).hexdigest()[:16]

heads = []
for channel_idx in range(hidden_dim):            # 每个隐藏通道物化为独立因子
    head = MyNNExpression(model_version_id, channel_idx, model_instance=snapshot)
    head.logic_hash = sha256(f"{model_version_id}:{channel_idx}".encode()).hexdigest()
    heads.append(head)

# 训练在 mine_period；排名优先用 test_period 留出段的 fitness
valid_heads = self._score_heads(heads, train_data, train_returns,
                                test_data, test_returns)
for head in valid_heads:
    self._head_archive[head.logic_hash] = head   # 跨轮累积，不只留最后一轮
self.state.population = self._select_diverse_heads(
    list(self._head_archive.values()))           # max_corr 0.95 过滤 + Top-K
```

`_score_heads`（`my_custom_nn.py:202-254`）会检查 `mine_period` 与 `test_period` 是否相交，相交即抛错（`:281-289`），并只在 `mine_period` 计算 fitness、在留出段做排名；`_select_diverse_heads`（`:159-200`）按 fitness 降序、以 `max_corr=0.95` 剔除数值冗余，最多留 `top_k_factors=5` 个。这套「训练 / 留出分离 + 跨轮档案」的设计，正是让 fitness 不至于沦为过拟合数字的关键：留出段只裁决一次，权重与标准化参数从未见过它。

| **qlib** | 无自动挖掘器，是算子 / 数据 / 模型 / 回测执行平台 | 模型层（LGBM / NN）做预测，不产出公式因子 | `TopkDropoutStrategy` 等执行层组件 | 价值在算子历史数据依赖契约、子表达式级缓存与 AST 白名单解析；自动挖掘外包给 RD-Agent，无代码级集成 hook |
| **FactorMiner NN** | 纯 NumPy 单层 MLP，无 PyTorch 依赖；`tanh` 隐藏通道即候选因子 | 基础模型 `MSE + L2 + Gram`；教学模板 `MSE + Pearson IC Loss`（α=0.7） | 通道物化后按 `test_period` 样本外 fitness 排名，`max_corr=0.95` 去冗余，跨轮保留全程 Top-K | 工件 `.npz` 可完整重载，模型格式 `numpy_mlp_factor_v1` / `numpy_temporal_ic_mlp_v1`；规模最小但边界最清晰 |

读表要点：AlphaForge 用生成—预测双阶段把「搜索」与「打分」解耦，AlphaGen 用 RL 直接优化组合增量，qlib 干脆不做挖掘；FactorMiner 选的是最朴素的一条——把每个通道当普通因子送进既有评估与闸门，好处是与 GP / RL / LLM 共用同一套 fitness、去重和入库链路，坏处是表达力与组合层都远不及前两家。

### 9.5 FactorMiner 实现

**模型核心**在 `core/miner/nn.py:193-411` 的 `NumpyMLPFactorModel`，`MODEL_FORMAT = "numpy_mlp_factor_v1"`（`:196`）、`SCHEMA_VERSION = 1`（`:197`）。初始化用 He 式正态 `rng.normal(0, sqrt(2/(input_dim + hidden_dim)), (input_dim, hidden_dim))`（`:214-219`），随机种子默认 42（`:204`）；`_forward` 即 `channels = tanh(normalized @ W1 + b1)`、`prediction = channels @ W2 + b2`（`:237-241`）。`train` 参数为 `epochs`、`learning_rate`、`l2=1e-4`、`diversity=1e-3`、`gradient_clip=5.0`、`patience=20`（`:243-253`），损失为 MSE + L2 + Gram 去相关（`:271-283`）。`predict_channel`（`:311-316`）、`export_artifact`（`:356-362`，产出 `.npz`）、`from_artifact`（`:364-385`）、`register_nn_model_loader()`（`:393-400`）与 `load_nn_model`（`:403-411`）共同构成共享引擎只认的协议：`predict_channel` / `clone` / `export_artifact`（`NNFactorModelProtocol`，`:31-42`）。

**真正的 Miner** 在 `user_workspace/custom_miners/my_custom_nn.py`，以 `@MinerRegistry.register("NN")` 注册（`:46`）。默认超参集中在 `initialize_search_space`（`:51-81`）：`hidden_dim 8`、`learning_rate 0.01`、`nn_training_epochs 50`、`nn_l2 1e-4`、`nn_diversity_penalty 1e-3`、`nn_min_samples 30`、`top_k_factors 5`、`max_corr 0.95`，另含 `nn_gradient_clip 5.0` 与 `nn_early_stopping_patience 20`（`:67-70`）。`update_model`（`:256-349`）从数据客户端取 `get_data()` / `get_returns()` 与 `get_test_data()` / `get_test_returns()`，检查训练段与测试段时间索引无交集（`:281-289`），在 `NNDataAdapter.prepare` 之后要求至少 30 个对齐样本（`:291-296`），训练、导出、物化、排名、写入跨轮 `_head_archive`（`:330-334`），并覆写 `_get_best_factors` 让 NN 自己持有全程档案而非退回基类策略（`:351-353`）。

**教学模板** `my_custom_nn_temporal.py` 演示了「独立特征路径」该怎么写。`TemporalFeatureAdapter.FEATURE_NAMES` 列出 **20 个过去式特征**（`:28-49`）：1/3/5/15/30/60 分钟收益、5/15/60 滚动波动、`volume_log` 与 1/5 期成交量变化、20/60 期量价 z-score、`intrabar_range` 与 `candle_body` 两类 K 线振幅、`minute_sin` / `minute_cos` 时间周期——全部由 `pct_change`、`rolling`、`clip` 等只看当期与历史的运算构造（`:60-110`），不含任何 `shift(-n)`。标签由 `target_from_config` 生成，`target.horizon_bars` 默认 **5**（`:379-387`），即 1 分钟面板下预测未来 5 分钟前瞻收益。`TemporalICFactorModel.MODEL_FORMAT = "numpy_temporal_ic_mlp_v1"`（`:120`），`ic_loss_weight` 默认 0.7（`:127`）；`_predict_all` 用 `np.column_stack([prediction, channels])`（`:257`）把**第 0 通道作为直接预测组合**，其余通道是带 Gram 去相关约束的隐藏表征，正好对应 `README.md:469` 的说明。`from_artifact` 连同 `register_nn_model_loader`（`:325-364`）保证这一自定义格式可完整重载。

### 9.6 模型工件与谱系

`.npz` 不是「把权重 pickle 一下」，而是一份自描述的可恢复模型包。`_artifact_payload`（`core/miner/nn.py:340-354`）写入 `metadata`（`json.dumps(get_model_spec(), sort_keys=True)`）、`W1` / `b1` / `W2` / `b2`、`feature_mean` / `feature_std`；`get_model_spec`（`:328-335`）给出 `schema_version`、`features`（特征顺序）、`hidden_dim`、`mining_mode`（数据模式）、`random_seed`。教学模板的 payload 额外写入 `target_mean` / `target_std`（`my_custom_nn_temporal.py:299-315`），spec 里再增加 `feature_version`、`output_channels`、`prediction_horizon`、`ic_loss_weight`（`:286-297`）。特征顺序必须随工件保存，否则换一列顺序就会让同一组权重算出完全不同的因子——这是黑盒因子最隐蔽的复现风险。

两个存储细节也服务于同一目标。`from_artifact` 一律用 `np.load(..., allow_pickle=False)`（`core/miner/nn.py:366`、`my_custom_nn_temporal.py:327`），因为模型工件会进入因子档案、可能被 Inspector 或 API 重新加载，若允许 pickle 就等于在读取路径上开了一条任意代码执行的口子——第 9 章用 AST 白名单挡住 LLM 源码，这里用格式约束挡住反序列化，二者是同一种 fail-closed 思路。`metadata` 之所以存成 JSON 字符串（`json.dumps(..., sort_keys=True)`，`core/miner/nn.py:346`）而不是一个 Python 对象数组，也是为了让 schema 可被人读懂、可被版本比较、且不绑定具体类定义；`sort_keys=True` 还保证字段顺序变化不会改变摘要，只有真正的内容变化才会让 `model_version_id` 跳动。教学模板在 `from_artifact` 里进一步校验 `feature_version`（`my_custom_nn_temporal.py:334-341`），把「特征工程定义变了」与「权重变了」区分成两种不同的不兼容。

版本戳由内容决定：`model_version_id = "nn_" + sha256(artifact.payload).hexdigest()[:16]`（`my_custom_nn.py:311`）。权重变一点、特征顺序改一项，版本就变，通道谱系不会错认；每个通道另有由 `{"model_version", "channel"}` 导出的 `logic_hash`（`:319-321`），用于全局硬去重。元数据层统一为 `nn_channel / model_version / channel`（`README.md:453-454`、`core/storage/factor_storage.py:244`），历史 `dl_channel` 档案继续兼容读取（`factor_storage.py:262`），API 与 Inspector 会把旧类型归一化为 `nn_channel`（`api/main.py:260,274,294-295`）。`FactorExpressionTensor.get_source()` 返回 `{"model_version": ..., "channel": ...}`（`core/miner/expressions.py:163-164`），`to_display_string` 输出 `NNModel(v=<weights-hash>) [Ch: <n>]`（`:185`），也就是一条训练结果在界面上显示为 `NNModel(v=nn_…) [Ch: 3]`，而不是一段公式。

更换网络结构或工件布局时，必须升级 `model_format` / `schema_version` 并调用 `register_nn_model_loader()` 注册对应加载器（`README.md:459-462`）；否则 `from_artifact` 会因 `metadata.get("schema_version") != cls.SCHEMA_VERSION` 抛 `Unsupported NN model schema`（`core/miner/nn.py:368-371`），`load_nn_model` 也会因格式未注册而报 `Unknown NN model format`（`:403-411`）。`DL` 是弃用名：`DEPRECATED_MINER_ALIASES = {"DL": "NN"}`（`core/startup_validation.py:21`），旧配置被就地改写并打 warning（`:29-35`），`core/miner/paradigms/dl_miner.py:12-26` 则直接抛错拒绝运行——别名只做兼容，不提供第二套实现。

### 9.7 工程陷阱与本章小结

**工程陷阱**

1. **训练张量与可保存因子的边界混淆。** `channel=-1` 的 `NNTrainingTensor` 只是为了让评估器返回带梯度的原始输出，若把它当因子入库，档案里会出现一个没有面值、无法计算 RankIC、Inspector 也展示不了的对象。判据很简单：只有能被 `predict_channel(data, k)` 重算出对齐 `Series` / `DataFrame` 的通道，才有资格进入 `state.population`。
2. **全样本 fit scaler 造成泄漏。** `fit_scaler` 必须只用 `mine_period` 的 `X`（`core/miner/nn.py:259-260`、`my_custom_nn.py:291`），标签标准化同理（`my_custom_nn_temporal.py:167-175`）。若先在全样本上求均值方差再切训练 / 测试，测试段的分布信息已经进入权重，样本外 fitness 会系统性偏乐观；`test_period` 只应参与排名，不参与任何拟合。
3. **跨轮只保留最后一轮。** 多轮训练里，最后一轮权重未必 fitness 最高。`MyCustomNN` 用 `_head_archive` 按 `logic_hash` 累积全部历史通道，再由 `_select_diverse_heads` 统一排序（`:330-334`）；若改成每轮覆盖 `state.population`，等于把早停之前的最优快照丢掉。
4. **特征面板含未来信息（`shift(-n)` 误用）。** 教学模板全部用 `pct_change`、`rolling`、`clip` 与当日高低开收构造「过去式」特征（`my_custom_nn_temporal.py:60-110`）。一旦某列用 `shift(-5)` 把未来收益拉回当期，网络会以极低的 MSE 学到恒等式，样本内 IC 接近 1、样本外瞬间归零。前瞻收益只能作为标签 `y`，绝不能作为输入 `X` 的一列。
5. **旧模型重载失败与 schema 漂移。** 改结构却不升级 `schema_version`、不注册 loader，历史 `.npz` 会在重启后集体失效。更隐蔽的是只改特征顺序而忘记它已写进 `metadata.features`——能加载、不报错，但因子值全变。版本戳取工件摘要（`:311`）正是为了让这类改动无法悄悄发生。
6. **NN 独立特征路径尚未接入，黑盒因子缺少归因。** 引擎侧一等终端目前仍以 OHLCV 为主，RL / NN 的 `required_streams` 默认只有 `close` 与 `volume`（`my_custom_nn.py:54`），`docs/research/platform_maturity_gap.md:126` 把「NN 独立特征路径」列为未解决项；20 维时序特征是教学模板在用户侧自行构造的，不是引擎自动供给。与此同时，通道为何有效无法归因到终端与算子，闸门只能用 RankIC、fitness、HAC t 与成本后收益从外部证伪，无法从内部解释——上线前必须把这一缺口连同可解释性限制一并写进档案。

**本章小结**

1. 把因子定义为「可微函数的一个输出通道」，是端到端范式的起点：终端变成输入列、算子变成矩阵乘与非线性，表达式树塌缩为计算图；换来表示能力，付出可解释性与可复现性。
2. `L = (1−α)·MSE + α·(1−corr(pred, y))`（α 默认 0.7）之所以比纯 MSE 更贴近交易，是因为组合只消费排序；相关系数有闭式解析梯度 `∂r/∂pred = ŷ/(‖p̂‖‖ŷ‖) − r·p̂/‖p̂‖²`，整条反向传播可用纯 NumPy 写出，无需 PyTorch。
3. 「模型权重不是一个可以直接评分的因子」：训练阶段用 `channel=-1` 的临时模型组保留计算图，训练后把冻结快照的每个隐藏通道物化为 `FactorExpressionTensor(model_version_id, channel_idx)`，Gram 去相关负责让这些通道彼此不同。
4. 可复现性由工件而非公式保证：`.npz` 收录权重、偏置、特征顺序、标准化参数、数据模式与 schema 版本，`model_version_id = "nn_" + sha256(artifact)[:16]`，元数据统一 `nn_channel / model_version / channel`，历史 `dl_channel` 兼容读取，`DL` 弃用名映射到 `NN` 并告警。
5. FactorMiner NN 的取舍是「最小模型 + 最清晰边界 + 共用既有闸门」：训练只在 `mine_period`，`test_period` 的样本外 fitness 决定排名，跨轮 `_head_archive` 保留全程 Top-K；代价是表达力、组合层与独立特征路径都明显弱于 AlphaForge / AlphaGen，黑盒归因缺口必须显式管理而非掩盖。
