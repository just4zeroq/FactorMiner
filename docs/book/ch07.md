## 第 7 章 遗传规划：把公式当作可演化的语法树

> 本章回答：为什么「找因子」能改写为在表达式树空间上的随机搜索，以及一次朴素的交叉与变异，为何会连带引出膨胀、去重与多重检验一整串工程后果。我们先讲清树表示、闭包性质与初始化，再给出遗传算子的概率推导和主循环伪代码；随后用 gplearn、gpquant、AlphaGen 与 FactorMiner 的默认值对照说明参数如何改变结果，最后落到 `gp_miner.py` 的四契约实现与真实陷阱。

### 6.1 原理与推导：符号回归是在树空间上的随机搜索

因子（Alpha）在工程上是一个把行情面板映射为截面打分的确定性函数：给定面板 X（时间戳 × 标的 × 字段），输出因子面值 f，再用 f 与下一期收益 r 的截面秩序关系计算 RankIC。人工挖因子是「指定一个 f，再验证它」；遗传规划（Genetic Programming，GP）反过来，把 f 本身当作搜索变量。这一步改写的价值在于：公式虽然离散、不可导、长短不一，却有一个统一的代数结构——抽象语法树（AST）——而树的集合上可以定义「邻近」与「变异」，于是连续优化里用不上的梯度，被替换成了结构上的随机游走。

形式化地，设算子集 F = {op₁, …, op_m}，每个算子带一个元数 arity(op) ∈ {1, 2}；终端集 T 由行情字段与临时常数（ephemeral constant）组成。一棵合法的表达式树递归定义如下：叶子取自 T；内部节点取自 F，且其子节点数恰等于该算子的 arity；根的输出即因子面值。以前缀式 `add(close, sub(close, 0))` 为例，根是二元 `add`，左子树是终端 `close`，右子树是以 `sub` 为根的二元子树，其两个叶子分别为 `close` 与常数 0。前缀写法与 AST 一一对应，FactorMiner 用字典嵌套来存它：`{"op": "add", "left": "close", "right": {"op": "sub", ...}}`，因此 `get_source()` 返回的就是 AST 本身，而不是一段需要二次解析的字符串——这一选择在第 8 章会显示出价值。

闭包性质（closure）是这套构造能成立的唯一前提：每个算子的输出类型，必须能作为任意其它算子的输入。在因子挖掘里所有节点都输出「与面板同形的数值序列」，类型看似统一，闭包几乎自动满足；但这恰恰是最容易被忽略的判断点。时序算子输出逐标的的时间序列，截面算子输出逐截面的秩序或标准化值，若把 `cs_rank` 的结果再喂给 `ts_mean`，语法合法、类型也合法，语义却把「截面排名」当成「价格序列」来滚动，求出的东西没有金融含义。gplearn 用 `make_function` 校验 arity 与输出 shape，并对全 0 / 全 −1 输入检查算子是否仍给出有限输出，同时内置 17 个算子加 5 个保护算子（`_protected_division/sqrt/log/inverse/sigmoid`），本质都是同一件事：闭包不只是「能跑通」，还包括「在退化输入上不崩」（`docs/research/industry_factor_mining_survey.md:609`）。FactorMiner 的对应做法是按 arity 建树（`core/miner/paradigms/gp_miner.py:130-132`）：一元算子只挂 `left`，二元算子挂 `left` 与 `right`。

搜索空间有多大？若最大深度为 d、二叉算子占多数，深度 ≤ d 的树形数量由 Catalan 数给出，再乘上每个内部节点的 |F| 种选择与叶子的 |T| 种选择，规模是 |F|^n · |T|^(n+1) 量级。这个数量在 d = 4 时已远超可枚举范围，所以 GP 只能是随机搜索，不是穷举；「随机」体现在初始化与变异，「搜索」体现在 fitness 引导的选择压力。二者缺一不可：只有随机是蒙特卡洛采样，只有选择会立刻收敛到初始种群里的局部最优。

初始化决定游走的起点，经典有三种方法。full 法在深度未达上限前一律取算子、到上限才取终端，长出形状规整的满树；grow 法在每一层都以一定概率提前取终端，树形参差、平均深度更浅；half-and-half 让一半种群用 full、另一半用 grow，并用不同的深度上限铺开，目的是同时覆盖「深而窄」与「浅而宽」两类形状。gplearn 默认 `init_method='half and half'`、`init_depth=(2,6)`，正是这个考虑（`docs/research/industry_factor_mining_survey.md:602`）。FactorMiner 的 `_random_ast()`（`core/miner/paradigms/gp_miner.py:123`）是 grow 的一个变体：一旦 `depth >= max_depth` 就强制返回终端（:124-125），否则均匀抽一个算子、按 arity 递归生成子节点（:126-133）；终端又以 `const_prob = 0.2` 的概率取 `round(uniform(-2, 2), 3)` 的临时常数（:117-121）。它没有实现 full，因为 `max_depth = 4` 已经把深度压得很紧，形状多样性主要靠加密种子与变异来补。

最后把评价写成式子，注意 GP 全程不要求它可导：

```
f       = Eval(tree, X)                    # tree: AST，X: 行情面板，f: 因子面值
RankIC  = (1/T) · Σ_t spearman(f_t, r_{t+1})
fitness = Φ(RankIC, RankIC_oos, coverage, turnover, …)
```

其中 t 遍历截面日期，f_t 是第 t 期截面上各标的的因子值，r_{t+1} 是下一期收益，spearman 是截面秩相关，Φ 是评价器把多个指标折成单个标量的函数。GP 只用到 Φ 的序关系——哪个个体的 fitness 更大——这一点决定了后续所有设计：选择、交叉、变异都在树的离散结构上操作，而 fitness 的数值只用于排序与记账。

### 6.2 算法与伪代码：遗传算子四件套与 GP 主循环

选择算子的职责是把 fitness 的序关系翻译成繁殖概率。锦标赛选择（tournament selection）是 GP 里最常用、也最容易调错的一种：从 N 个个体里随机抽 k 个（k 即 tournament size），让其中调整后 fitness 最高者获得一次繁殖资格。它既不需要 fitness 的绝对量纲，也不用像轮盘赌那样处理负数，只要能两两比较即可——这正好契合 GP 只用序关系的前提。

设个体按调整后 fitness 降序排名为 i = 1 … N（1 最优）。用无放回抽样（FactorMiner 的 `random.sample`，`core/miner/paradigms/gp_miner.py:163`）时，个体 i 赢得一次锦标赛，当且仅当 k 个样本全部来自排名不差于 i 的 N−i+1 个个体、且至少包含 i 本身：

```
P(i 被选中) = [ C(N−i+1, k) − C(N−i, k) ] / C(N, k)        # 无放回，精确
            ≈ ((N−i+1)/N)^k − ((N−i)/N)^k                    # 有放回近似
```

C(·,·) 是组合数，N 是种群规模，k = tournament size，i 是排名。每代要做 N 次锦标赛来产生 N 个父代名额，所以个体 i 的期望繁殖次数是 N · P(i)。这个式子直接给出调参判断：k 越大，选择压力越强，分布越向头部集中。取 gplearn 默认 N = 1000、k = 20，最优个体的期望次数约为 k = 20，而排名中位数（i = 500）的期望次数约 10⁻⁴ 量级——几乎全体后代都来自前百分之几的精英。FactorMiner 的 N = 20、k = 3（`core/miner/paradigms/gp_miner.py:43,78`）温和得多：最优个体期望 3 次，排名 i = 10 的个体 P = [C(11,3) − C(10,3)] / C(20,3) = (165 − 120) / 1140 ≈ 0.039，期望 0.79 次，中等个体仍保有繁殖机会。结论很硬：小种群必须配小 k。若把 gplearn 的 k = 20 直接搬到 population_size = 20 上，等于每代只让同一两棵树繁殖，两三代内种群基因型就同质化，交叉与变异再花哨也没有素材。

子树交叉（subtree crossover）在两棵父代树上各随机取一个子树并交换。闭包性保证交换结果仍是合法 AST：被换进来的子树输出的是同类型序列，父节点按 arity 接收，不多不少。但交叉也是 bloat 的主要来源，因为它倾向于把两棵树的深度相加，而不是相消。变异分三种：点变异逐节点以小概率把算子换成同 arity 的另一个算子、或把终端换成另一终端 / 常数；子树变异随机选一个子树整棵重生成；hoist 变异从树内再取一个子树上提替换原树，直接缩短树高，注释里明确写「helps to control bloat」。复制（reproduction）则是原样带入下一代，是精英保留的弱化形式。gplearn 的 `_parallel_evolve` 按累积概率五选一，默认 `p_crossover = 0.9, p_subtree = 0.01, p_hoist = 0.01, p_point = 0.01`，余下约 7% 是复制；`point_mutation` 逐节点以 `p_point_replace = 0.05` 替换，函数按同 arity 更换（`docs/research/industry_factor_mining_survey.md:590,597`）。

把四件套装进主循环，得到 FactorMiner 四契约（initialize / generate / evaluate / update）的伪代码：

```python
# GP 主循环：initialize → generate → evaluate → update，四契约逐一对应基类抽象方法
def gp_mine(data, cfg):
    P = initialize_population(cfg)            # grow 随机树 + 加密种子，见 6.5
    num_trials = 0                            # 试验次数：每评价一个 AST 就 +1
    for gen in range(cfg["generations"]):
        # 1) evaluate：AST → 面值 → RankIC → fitness；每次评估 = 一次假设检验
        scores = [(t, evaluate(t, data)) for t in P]
        num_trials += len(scores)

        # 2) 精英保留：按「简约调整后」fitness 取前 e 个，原样带入下一代
        elites = [t for t, _ in sorted(scores,
                      key=lambda x: adjusted(x[1], t=x[0]), reverse=True)
                  [:cfg["elite_count"]]]

        # 3) generate：锦标赛 → 交叉 → 变异 → 默认复制，凑满种群
        offspring = []
        while len(offspring) < cfg["population_size"] - len(elites):
            p1 = tournament(P, k=cfg["tournament_k"])          # 选择
            p2 = tournament(P, k=cfg["tournament_k"])
            child = copy(p1)                                    # 复制是缺省分支
            if rand() < cfg["crossover_prob"]:
                child = subtree_crossover(copy(p1), copy(p2))  # 子树交叉
            if rand() < cfg["mutation_prob"]:
                child = mutate(child)                           # 点 / 子树 / hoist
            offspring.append(child)

        # 4) 去重：源码 MD5 硬去重 + 面值相关软去重；精英豁免，见 6.6
        offspring = dedup(offspring, preserved=elites)

        # 5) update：精英 + 子代按原始 fitness 截断，必须写回 state.population
        P = rank(elites + offspring, key=raw_fitness)[:cfg["population_size"]]
        state.population = P                                    # 不写 = 零产物
        if converged(P, patience=cfg["patience"]):
            break                                               # 早停
    return hall_of_fame, num_trials
```

注意第 2 步与第 5 步用的是两个不同的分数：选择时取 `adjusted`（简约调整后 fitness），归档截断时取 `raw_fitness`。这不是笔误，而是有意分工，6.3 与 6.5 会展开。

### 6.3 Bloat、简约压力与收敛：给公式收费，给评估记账

如果 fitness 对「语义等价的表达式」给完全相同的分，选择就没有偏好，树会在中性漂移里不断长大，这就是 bloat（表达式膨胀）。`add(close, sub(close, 0))` 在数学上恒等于 `close`，但节点数从 1 变成 4；`sub(close, close)` 恒等于 0。这类无效式不会被 fitness 主动惩罚——它们的 RankIC 与 `close` 一样——于是交叉越频繁，种群平均深度越涨。代价有四层：求值变慢、过拟合自由度变大、可读性归零，以及最隐蔽的一层：退化成常数的面值在逐截面相关计算里会产生 NaN 或虚高读数，这属于 6.6 要专门处理的工程陷阱。

简约压力（parsimony pressure）就是给长度收费。两种实现值得对照。gplearn 用加法惩罚：

```
fitness = raw_fitness − c · len(program) · sign(metric)
```

`raw_fitness` 是 `metric(y, execute(X))`；`len(program)` 是前缀程序的节点数；`metric.sign` 取 +1 或 −1，取决于该 metric 是越大越好（如 R²）还是越小越好（如 MSE）——乘上它是为了保证无论朝哪个方向优化，惩罚项都让 fitness 变差；c 即 `parsimony_coefficient`，默认 0.001。它还有一个自适应档：

```
c = Cov(length, fitness) / Var(length)          # parsimony_coefficient = 'auto'
```

即长度与 fitness 的回归斜率：若当前种群里长树平均确实更好，惩罚自动变小；若长树无益，惩罚自动放大（`docs/research/industry_factor_mining_survey.md:606`）。这个设计的判断很到位——简约系数不该是拍脑袋的常数，因为「多长算过长」依赖于当下种群。

FactorMiner 用乘性折扣（`core/miner/paradigms/gp_miner.py:143-146`）：

```
_adjusted_fitness = fitness / (1 + parsimony · depth)          parsimony = 0.05
```

`depth` 由 `_depth()` 递归取左右子树最大值加一（:136-141），是树深而不是节点数；`parsimony = 0.05`（:81）。乘性形式对 fitness 的量纲不敏感，调参更省心，但上限有限：深度再大，折扣也不会让分数低于 0，因此单靠它压不住无限膨胀，真正兜底的是 `_random_ast` 里的 `max_depth = 4` 硬截断（:74,124）。gplearn 则未找到子代树深硬截断，bloat 仅靠 hoist 与 parsimony 软控制（`docs/research/industry_factor_mining_survey.md:611`）——这是两者最实质的差别。还要强调：`_adjusted_fitness` 只在 `_tournament()` 里用于选择（:166），而 `update_model()` 排序与写入 `state.population` 用的是原始 `fitness_score`（:252,256,259-260）。选择时偏简约、归档时看真实表现，这个分工避免了「因为短所以被记住」污染名人堂。

收敛与早停有三个可信信号：连续若干代最佳 fitness 不提升；种群基因型方差跌破阈值；以及去重后本代新候选为零——`BaseFactorMiner.mine()` 在 `candidates` 为空时会打出 "All candidates filtered out as redundant" 并跳过整轮（`core/miner/paradigms/base.py:291-295`），这其实是多样性枯竭最可靠的信号。精英保留（elitism）保证最优解不丢，但精英数 e 太大会加速同质化，FactorMiner 取 `e = max(1, population_size // 10) = 2`（`core/miner/paradigms/gp_miner.py:82`）。种群多样性靠两级去重维持：MD5 硬去重挡「完全相同的写法」，面值相关软去重挡「同一信号的不同写法」，两者都在压 `num_trials` 的有效分母。

现在讲本章最需要记住的判断：**GP 的每一次评估都是一次假设检验**。每生成并评价一个 AST，就是在同一份数据上检验一次「该公式与未来收益相关」的假设。population 20 × 20 代 = 400 次，gplearn 1000 × 20 = 20000 次。若不记录 num_trials，最佳 fitness 服从的是 20000 个随机变量最大值的分布，天然远高于单个假设的零分布；把它当成「发现了一个显著因子」就是过拟合。更糟的是，两个常被引用来缓解过拟合的机制其实不构成 OOS 保护：gplearn 的 `oob_fitness_` 是 `max_samples < 1` 时的样本内子采样，不是时间切分（`docs/research/industry_factor_mining_survey.md:607`）；gpquant 的 `[:400]/[400:800]` 是固定单次切分，也没有 walk-forward 与多重检验（:621）。结论是：GP 的算力预算同时就是统计预算，任何增大种群或代数的「性能调优」都在同步抬高过拟合风险；`num_trials` 必须与种群规模、代数、去重后实际通过数一起记账，这是后续章节处理多重检验的伏笔。

最容易被误读的一列是「种群越大越好」。gplearn 1000、gpquant 2000 是通用符号回归面向低维单序列拟合的默认值：一次评估只需算几百个标量。因子挖掘的每次评估要在 20 币 × 数百期的面板上逐截面算 RankIC，成本高一到两个量级，而且评估次数直接进入 num_trials 分母。FactorMiner 把种群压到 20、代数默认 5（`core/miner/paradigms/base.py:254`），不是算力妥协，而是把统计预算显式收紧。另一处值得判断的是 fitness 口径：gpquant 直接优化回测 Sharpe，等于把交易成本与仓位口径焊进了搜索目标，看似端到端一致，实则让搜索可以直接攻击回测口径的自由度；FactorMiner 停在单因子 RankIC，把组合留到末层独立处理（`docs/research/industry_factor_mining_survey.md:698`）。这两种取舍的后果，会在第 8 章 reward 设计里再次出现。

### 6.5 FactorMiner 实现：四契约、行号与默认值

`BaseFactorMiner` 定义了四个抽象方法：`initialize_search_space`（`core/miner/paradigms/base.py:204`）、`generate_candidates`（:211）、`evaluate_candidates`（:219）、`update_model`（:228）。主循环 `mine()`（:249）固定按「提案 → 去重 → 判卷 → 名人堂 → 学习」执行（:282-311）：`raw_candidates = generate_candidates()`，交给 `DiversityFilter.filter_redundant()`（:286-290），再 `evaluate_candidates()` 得到 `EvaluationFeedback`（:298），把成功候选写入 `hall_of_fame`（:300-308），最后 `update_model()`（:311）。**四契约之外还有第五条隐式契约**：`update_model` 更新完模型后，必须把最终通过筛选的候选写入 `self.state.population`（或 `replay_buffer`）。README 第 4 条把它说得很直白——「仅更新模型并不等于发现因子」，`BaseFactorMiner` 最终只从 population / replay_buffer 读产物，否则任务会正常完成，但 Tracker 显示没有可保存的有效因子（`README.md:339-341`）；`_get_best_factors()` 优先读 `hall_of_fame`，否则回退 `state.population`（`core/miner/paradigms/base.py:537-545`）。

GP 子类逐项如下，行号以当前源码为准。

`initialize_search_space()`（`core/miner/paradigms/gp_miner.py:39`）读取 `population_size = 20`（:43）；终端从 `TERMINALS_DEFAULT = ["close","open","high","low","volume"]` 这 5 个 OHLCV 起步（:23,46），经 `crypto_terminals(self.terminals, panel)`（:52，`core/miner/crypto_features.py:395`）把面板里实际存在的加密原生流（funding / OI / basis / liquidation）提升为一等终端；`crypto_seed_ratio = 0.3`（:57），`crypto_windows` 默认取自 `DEFAULT_CRYPTO_WINDOWS = (6, 12, 24, 48)`（`core/miner/crypto_features.py:369`），由 `build_crypto_feature_asts()`（:61-65，`core/miner/crypto_features.py:443`）预生成资金费率 / 持仓量 / 基差 / 清算模板 AST。其余默认值：`max_depth = 4`（:74）、`const_prob = 0.2`（:75）、`windows = [5,10,20,60]`（:76）、`powers = [1.0,2.0,3.0]`（:77）、`tournament_k = 3`（:78）、`crossover_prob = 0.8`（:79）、`mutation_prob = 0.3`（:80）、`parsimony = 0.05`（:81）、`elite_count = max(1, 20//10) = 2`（:82）、`survival_count = 10`（:83）。

`_initial_population()`（:95）先放 `round(20 × 0.3) = 6` 个加密种子 AST，其余 14 个用 `_random_ast()` 填满（:99-107）。`_random_ast()`（:123）、`_depth()`（:136）、`_adjusted_fitness()`（:143）已在 6.1 与 6.3 说明。`generate_candidates()`（:213）计算 `n_offspring = max(1, 20 − 2) = 18`（:220），每个子代调用两次 `_tournament()` 选父代（:223-224），按 `crossover_prob` 走 `_crossover()`（:226-227）、按 `mutation_prob` 走 `_mutate()`（:228-229），并用 `parent_ids` 记录双亲血缘（:233-236）。`_tournament()`（:162）用 `random.sample(population, min(3, len))` 抽 k 个，按 `_adjusted_fitness` 取 max（:166）。`_crossover()`（:168）深拷贝 p1，从 `_all_subtrees(p2)`（:152）随机取一个子树，替换 child 中随机选定的目标节点（:172-178）。`_mutate()`（:181）以 0.5 概率重生成整棵子树，否则用 `sample_operator_params(op)` 重采样窗口 / 幂 / 滞后参数（:199），并以 0.3 概率换成同 arity 的另一个算子、清掉旧参数键再重采样（:201-207）。

`evaluate_candidates()`（:241）委托 `self.evaluator.evaluate(candidates)` 返回 `EvaluationFeedback`。`update_model()`（:246）从 feedback 收集 `succeeded` 候选及其 `fitness_score`（:248-252）；从上一代 `state.population` 按**原始** `fitness_score` 降序取 `elite_count` 个精英（:254-257）；把精英与本代 scored 合并成 pool，按原始 `fitness_score` 排序截断到 `population_size`，写回 `self.state.population`（:259-261）。链路因此在 :261 闭合，符合 README 第 4 条。

两处值得点破的实现细节。第一，`survival_count = 10`（:83）虽在初始化里定义，当前 `update_model` 的截断直接取 `population_size`（:261），并未按 survival_count 二次截断；读配置时不要把它当成生效的存活数。第二，精英在 `DiversityFilter.filter_redundant()` 里通过 `preserved_set` 豁免两层去重（`core/miner/paradigms/base.py:122,130-133`），但其面值仍会 `_remember` 进 archive，用来定义后代「什么算冗余」（:124-127）——豁免的是重复判定，不是质量检查。

### 6.6 工程陷阱

1. **常数 / 全零因子在 corrwith 下产生虚高或 NaN，必须在指标之前拦截。** 评价器逐截面算 `factor_values.corrwith(returns, axis=1, method='pearson').mean()`（`core/evaluation/evaluator.py:313-314`）。若某期因子面值是常数（`sub(close, close)` 恒为 0，或膨胀式里的恒等分支被常数污染），该截面标准差为 0，Pearson 分母为 0 → NaN；`.mean()` 默认跳过 NaN，于是 IC / RankIC 由极少数「碰巧有效」的截面决定，读数虚高。若全部截面都退化，指标维持默认 0.0（:305），既不报错也不产信号，却白占一次试验预算。防御是评估层的 Anti-Bloat 拦截（`docs/FactorMiner_PRD.md:13` 列为动态防重复过滤）、`_validate_metric_inputs` 的「至少含一个有限值」检查（:394-395），以及架构文档里对「GP 膨胀产生的常数无效因子」的健壮性告警屏蔽（`docs/architecture/v4_architecture_design.md:153`）。判断：只在 fitness 里惩罚长度是不够的，退化判定必须发生在指标计算之前。

2. **源码 MD5 去重与面值相关软去重必须同时开，且要实测确认生效。** MD5 只看 `str(cand.get_source())`（`core/miner/paradigms/base.py:136-139`），`rank(close)` 与 `zscore(close)` 哈希不同、截面排序却完全一样；软去重把面值按截面 rank 展平后与 archive 比 |Pearson|，超 `dedup_value_threshold = 0.99` 即拦截（:141-153；默认见 `README.md:255` 与 `core/miner/paradigms/base.py:272`），archive 容量 40（:273）。真实 20 币、2 代 GP 实测：`rejected_by_value = 46`（约 30%），`max_observed_corr = 1.000`（`TODO.md:42`、`user_workspace/reports/engineering_hardening.md:70-73`）——三分之一「新因子」其实是同一假设换写法。代价是每代从 26s 涨到约 68s，换来更干净的 num_trials 分母。还有一个静默失效坑：第一版把 `RealDataClient` 对象直接传给 `compute()`，签名全为 `None`，去重静默失效且不报错，直到 `archive=0` 才暴露（`engineering_hardening.md:75`）；现由 `_factor_panel()`（`core/miner/paradigms/base.py:237-247`）统一取面板。

3. **精英必须写入 population，否则任务「成功但零产物」。** `update_model` 只更新策略、只打印每代日志而不写 `state.population`，任务会正常跑完，但 `_get_best_factors()` 取不到候选（`core/miner/paradigms/base.py:537-545`），Tracker 显示无有效因子（`README.md:339-341`）。GP 之所以没踩这个坑，是因为 `core/miner/paradigms/gp_miner.py:261` 明确写回了种群；自定义 Miner 照抄四契约时最容易漏掉这一步。

4. **参数化窗口变异让搜索空间爆炸，伪多样性会吃满试验预算。** `_mutate` 的 `sample_operator_params(op)`（`core/miner/paradigms/gp_miner.py:199`）会重采样 window / p / lag，配合 `windows = [5,10,20,60]`、`powers = [1.0,2.0,3.0]`（:76-77）与 59 个算子中 30 个带参数的事实，同一树形「形状不变、参数不同」就能裂出几十上百个候选。它们 MD5 各不相同，却往往是同一信号，会迅速占满 archive 容量与 num_trials。判断：参数扰动比换算子更容易制造伪多样性，必须计入试验预算，不能当作免费探索。

5. **精英豁免会污染 archive。** `filter_redundant` 对 `preserved_set` 里的精英跳过两层去重，但仍把其面值 `_remember` 进签名库（`core/miner/paradigms/base.py:124-127`）。若精英本身是常数因子或退化式，archive 会被无效签名占据，后续正常候选反而被误判为冗余。精英保留豁免的是重复判定，不是质量检查——这一点与陷阱 1 是同一枚硬币的两面。

### 6.7 本章小结

1. 遗传规划把「找因子」改写为在 AST 树空间上的随机搜索；闭包性质（每个算子的输出类型能作其它算子输入）是交叉、变异合法的前提，而 GP 全程只用 fitness 的序关系、不要求可导。
2. 锦标赛选择的强度由 k 与 N 共同决定：`P(i) = [C(N−i+1,k) − C(N−i,k)] / C(N,k)`。小种群必须配小 k，FactorMiner 的 N = 20 / k = 3 与 gplearn 的 N = 1000 / k = 20 是两种压力 regime，不可互抄参数。
3. bloat 源于「语义等价式 fitness 相同」下的中性漂移；gplearn 用加法惩罚 `raw_fitness − c·len·sign(metric)` 与 `'auto'` 的 `Cov/Var`，FactorMiner 用乘性折扣 `fitness/(1 + 0.05·depth)` 并靠 `max_depth = 4` 兜底，且简约分只用于选择、原始分用于归档。
4. **GP 的每一次评估都是一次假设检验**：population 20 × 20 代就是 400 次检验，最佳 fitness 是多重比较下的最大值。必须把 `num_trials` 与种群规模、代数、去重后实际通过数一起记账；gplearn 的 `oob_fitness_` 与 gpquant 的 `[:400]/[400:800]` 都不是 OOS 保护。
5. 工程上真正消耗预算的不是树本身，而是「同一信号的多种写法」：20 币 2 代实测 46 个候选（约 30%）被面值软去重拦下、`max_observed_corr = 1.000`。只读 MD5、只更新模型不写 `state.population`、放任参数化窗口变异，都会让试验预算与产物链路同时失真。
