## 第 14 章 留出纪律：让「验证」成为可消耗、可审计的预算

> 本章回答：闸门再严，如果验证数据被反复看过，结论依然无效。本章把数据当成一种**会耗尽的资源**：三段切分的角色分离、purge 与 embargo 的时间隔离、逐折重拟合的真 walk-forward、一次性揭示账本、滚动预注册窗口、标的维度留出，最后用一个「阳性对照」回答一个几乎所有系统都回避的问题——闸门有没有硬到连真信号都拦掉？

### 13.1 三段切分与「信息暴露」会计

标准角色分离（`research-protocol.md` §6）：

| 段 | 角色 | 允许做什么 | 被读取次数 |
| --- | --- | --- | --- |
| 训练 / 挖掘段 `mine_period` | 拟合模型、scaler、执行候选搜索 | 可以反复读 | 无上限（计入 `num_trials`） |
| 验证段 `test_period` | 选超参、选公式、定停止条件 | 有限度使用 | **`val_read_count`（正式 run = 87）** |
| 最终留出 `strict_holdout` | 方案冻结后只评估一次 | 只评估，不调任何东西 | **1 次，永久消耗** |
| 滚动复评窗口 | 检验跨期稳定性 | 不替代最终测试 | 每窗 1 次 |

「一次」的定义是本章最重要的概念：

> 最终测试的「一次」按**信息暴露**计算，而不是按成功命令次数计算。错误公式、失败流水线、调试脚本或不完整报告只要展示过该区间的结果，也会消耗该留出集。

这条规则落地成代码就是 `consumed_before_read`：`LLM-Alpha-Mining-Framework` 的 `claim_evaluation` 在**读 holdout 之前**以独占方式写账本，失败评估也消耗窗口。FactorMiner 的 `HoldoutLedger`（`core/evaluation/experiment_trace.py:64-175`）把揭示记录为 `_Reveal(period_key, start, end, at, note)`，`_overlaps = a0 <= b1 and b0 <= a1`，对已 reveal 的 `period_key` 或重叠窗口直接抛 `HoldoutReuseError`。

项目里的真实账本只有一条：`holdout_2025H2_2026`，区间 `2025-07-01 → 2026-11-13`，在 P0 实验里一次性揭示。这意味着**这段数据永远不能再用来「再跑一次看看」**。`TODO.md` 反复写「2025-07→2026-11 已消耗，不可复用」，就是在维护这本会计账。

一个容易混淆的点，§11.3 已提及但要在这里说透：`evaluator.py:398-470` 的 `oos_exponent=0.5` 混合的是 **`test_period` 验证段**（如 `configOOSHoldout.json` 的 2025-01-01..2025-06-30），最终 holdout 由独立脚本重算、不进 fitness。所以 `docs/research/platform_maturity_gap.md` §4.2 的准确表述是：**验证集被每代每候选反复读取用于选优，缺的是试验次数折减与 gap/embargo/逐折重拟合；不是「最终 holdout 已泄漏」**。误写成后者会导致开错药方——前者可以靠时间隔离修复，后者只能换数据。

### 13.2 purge 与 embargo：把标签重叠和序列相关隔离掉

设标签前瞻 `h = horizon_bars`，验证段起点 `v0`。两个边界问题：

- **purge（净化）**：训练段末尾的样本，其标签 `r_t = close[t+h]/...−1` 会用到 `t+h` 的价格。若 `t+h ≥ v0`，训练样本的标签里就含有验证段的价格信息。因此训练段的有效终点必须往前退 `h`：

```
train_end = v0 − h − 1
```

- **embargo（禁运期）**：验证段结束之后，序列相关（波动率聚集、资金费周期、未平仓信息的滞后影响）仍可能把验证段的信息带到训练里。因此在验证段之后再留 `e` 根 bar 不用于训练：

```
embargoed_start = v0 + len(val) + e
```

`core/experiment/walk_forward.py:35-76` 的 `build_folds()` 用扩张窗口实现：`min_train = max(n·0.40, 60, 2)`，`train_end = val_start − horizon_bars − 1`，`embargoed_start = val_start + embargo_bars`，`gap_bars = embargoed_start − train_end − 1`。默认 `DEFAULT_WF_CFG`：`n_folds=5`、`embargo_bars=5`、`min_train_frac=0.40`、`min_train_bars=60`、`ridge_alpha=5.0`、`cost_rate=0.0018`、`quantile=0.20`。正式 run 里 **5 折的 gap 全为 6 bars**（purge 1 + embargo 5）。

`crypto-factor-lab` 的对应做法是 `purge_bars = forward_horizon`（默认 4h 标签时等于重叠长度），并在 `segments()` 里对两处边界前挖空；`Alpha-Research-Discovery` 的 `WalkForwardValidator` 同时实现 `test_start = train_end + embargo + 1d` 与 `effective_train_end = train_end − purge_td`，引用 López de Prado (2018) §7.4——可惜那 30 个 alpha 实际都用朴素 70/30 切分，这套实现**没被用上**。

### 13.3 真 walk-forward 与假 walk-forward

这是本章最值得警惕的一节。**「有折」不等于「逐折重拟合」**。

`AlphaMaster` 的 `engine.py:95-124` 确实做了 5 折 rolling + `WF_GAP=20`，看起来很严谨；但 `:354` 把**同一个公式在全样本一次性算完**，`:367-403` 各折只是切片评分，**没有逐折重拟合**。更糟的是 `tests/unit/test_walk_forward_gap.py:45-51` 只测索引算术，还断言 `train_start` 恒为 0，与当前 rolling window 实现互相矛盾——测试已与实现脱节。

FactorMiner 的 `walk_forward_validate()`（`:196-251`）逐折执行：

```python
for fold in build_folds(panel, target_spec, cfg):
    # ① 标准化参数只在 TRAIN 上拟合，再应用到 val
    Xtr, Xva = _standardise(fit_on=fold.train, apply_to=fold.val)
    # ② 权重只在 TRAIN 上重新拟合
    w = _fit_ridge(Xtr, ytr, alpha=cfg.ridge_alpha)     # (XᵀX + αI)w = Xᵀy
    # ③ 用本折权重在 val 上算 RankIC 与净收益
    ric = _rank_ic(Xva @ w, yva)
    net = _net_return(Xva @ w, yva, cost_rate=cfg.cost_rate)
```

输出里除了 `mean_rank_ic / min_rank_ic / mean_net_return / positive_folds / all_folds_positive / direction_consistent`，还有两个自证字段：`refit_per_fold = True` 与 **`weights_differ_across_folds`**（`:248-250`，用 `len({tuple(weights)}) > 1` 显式验证权重确实逐折变化）。**让系统自己证明它没有偷懒**，比在文档里写一句「我们做了 walk-forward」有用得多。

样本不足时 `_fit_ridge` 退化等权；`_net_return` 用 top/bottom `q` 分位多空、换手按 `changed/(2k)` 计、净收益 `gross − cost_rate·turnover`。逐折重拟合同时杜绝了另一种泄漏：全样本算完再切片，等于让训练段的标准化参数、权重、甚至特征选择都看过验证段。

### 13.4 一次性 holdout 守卫：从库函数到产品能力

`core/evaluation/holdout_guard.py:59-274` 的设计要点：

| 项 | 值 / 行为 |
| --- | --- |
| 模式 | `strict`（默认）/ `audit` / `off` |
| 优先级 | 显式传参 > `evaluation.gates.holdout_mode` > 环境变量 `FACTORMINER_HOLDOUT_MODE` |
| `purpose` | `explore` / `final`；`final` 必须显式给 `--start/--end`，开放式边界用 `0000-01-01` / `9999-12-31` |
| 唯一账本 | `user_workspace/.holdout_ledger.json`（路径由 `parents[2]` 固定到项目根，避免 cwd 分叉） |
| 访问日志 | `reports/holdout_access.jsonl` |
| 逃生口 | `--allow-holdout-reuse` 强制写不可变审计行 `reports/holdout_overrides.jsonl` |
| 入口 | `commands/backtest.py`、`commands/inspect.py`、`director.run()` 开头 fail-fast |

P0-b 这次改造修掉的是**「没配 `strict_holdout` 就静默跳过」**：守卫默认 `strict`，且接入所有 CLI 入口与 Director 开头。`tests/test_holdout_guard.py` 里还有「入口接线断言」，防止以后新增 CLI 命令时漏接——这类断言的价值在于，安全机制的退化往往发生在新增路径上，而不是原有路径上。

`guard_config()`（`:296-325`）区分两种配置：有 `strict_holdout` dict 走 `final`，否则 `test_period` 全部走 `explore`。一个同源 bug 也被修掉：`.gitignore` 原本忽略 `.holdout_ledger.json`，fresh clone 会从空账本起步，守卫形同虚设；现在账本移出忽略列表，从 `.gitignore` 移出以免 clone 后账本变空。

产品化接线同样重要：早期 `api/` 全目录检索 `holdout|ledger|reveal` 零命中，Web 用户看不到哪些窗口已烧，可能在 Launchpad 上重复选到消耗过的区间。补上 `GET /api/gates/holdout`（返回已揭示窗口 + 预注册窗口进度）后，守卫才从「库函数」变成「平台能力」。

### 13.5 滚动预注册：把静态大窗口改成可累积的小窗口

最初的预注册是静态的：`experiment_window.json` 写死 `start=2026-12-01`、需要 90 根 1d bar、ETA 2027-02-28。这暴露了三个问题（`TODO.md` §3e）：**数据预算一次性烧光无分层留出**、**预注册是静态批处理而非滚动**、以及**把「方法正确性」和「经济 alpha」捆成同一个验收条件**。

`core/experiment/windows.py:46-301` 的滚动方案：

```
rolling = true,  start = "auto",  window_bars = 30,  embargo_bars = 5
锚点      = 最后一次非 rolling_ 前缀 reveal 的 end + 1 天   （当前 2026-11-14）
时间轴    = 所有 OHLCV 文件 date 列的【真实交集】，不是日历天数
stride    = window_bars + embargo_bars = 35
period_key= "rolling_{lo}_{hi}"，每窗只 reveal 一次
```

三个设计决定值得记：

1. **锚点自动推导**：不再硬编码月初，于是 11-14→11-30 的新 bar 不再被丢弃；首个可用窗口 ETA 从 **2027-02-28 提前到 2026-12-13**。
2. **按真实 bar 交集分块**：修掉了 `freshness.py:213` 用日历天数当 bar 数的错误。加密市场 7×24，日历天数与 bar 数不是一回事；且必须「所有标的都有该 bar」才算一根，否则单币缺数据会让窗口虚胖。
3. **滚动揭示不推移动锚点**：预注册边界必须固定。若每揭示一窗就把锚点往后挪，等于允许无限次重新定义「未见过的数据」。

规划器是**纯只读**的（`python -m core.experiment.windows`），真正揭示必须走 `holdout_guard(purpose="final")` 写账本。`GET /api/data/freshness` 与 `GET /api/gates/holdout` 都返回滚动计划，界面用进度条展示「下一次预注册验证还差多少根 K 线」，而不是依赖研究者记忆——**这是「干净 holdout」与「偷看」之间唯一的实体屏障**。

### 13.6 第二根轴：universe holdout（标的维度留出）

时间不是唯一的数据预算维度。若某批标的从未参与过挖掘，它们天然构成干净样本。

`core/experiment/universe.py:56-322` 提供两种切分：显式 `universe_holdout` 列表，或按 `universe_holdout_frac` 做种子确定性切分。关键语义是 `clean` 标志：

```
clean = True   仅当保留 symbols 与 mining universe 完全不相交
clean = False  leave-K-out 式子集切分 → 强制在报告里标注「仅验机制，不是独立证据」
```

两侧各需 ≥ 3 资产；`require_fresh` 可硬拒绝不干净切分；一次性账本 `.universe_ledger.json` 防止反复偷看同一批预留标的，`split_hash = hash_json({"train":..., "holdout":...})`。流水线里挖掘阶段用 train-only 配置，OOS 重算与回测用独立预留 client，**方向仍从样本内库学习**（`orientation_db_root`），避免用预留池反推符号。

正式机制验证 run `run_20261114T125520Z_2722fb`：14 训练 / 6 预留、`clean=False`（仅验机制）、6 币 OOS 快照、`funding_source = crypto_streams (6 assets)`、75 笔交易、**−20.53%**。附带修掉一个静默错误：`run_backtest` 默认 5 多 / 5 空 / `min_assets=10`，6 币预留池下每次调仓都被拒 → **0 交易、0% 收益却报成功**。`adapt_book_to_universe()`（`backtest_engine.py:442-466`）按实际资产数自适应：`k = min(n_long, n_short, max(1, available//3))`，6 币 → 2/2 / `min_assets=4`，20 币仍是 5/5/10 行为不变；回归测试用真实价格文件锁定「必须真的成交」。

真正干净的留出入口是 `scripts/download_universe_holdout.py`：下载与训练池不重叠的新币历史，默认拒绝伪留出。这条路不依赖等时间，是「时间预算」之外的第二个选择。

### 13.7 阳性对照：闸门自己也需要被证伪

此前项目只有阴性记录：「84/84 全拦住」「0 promoted」。但**从没验证过闸门在真信号存在时能否放行**——于是「0 promoted」无法区分「因子都不行」与「闸门硬到连真信号都拦掉」。`core/experiment/gate_calibration.py` 补上这一环。

半合成 DGP（`:91-137`）：

```
R[t,a] = vol · ( market_frac · market[t] + ρ · z_F[t,a] + √(1−ρ²) · eps[t,a] )
z_F    = AR(1)（persistence=0.30）后行标准化
eps    = 行标准化噪声
market = (T,1) 共同冲击（在截面秩与 dollar-neutral 多空中抵消）
ρ      = 已知真实 IC，是唯一被控制的自变量
```

默认 `n_bars=641`、`n_assets=20`、`n_oos_bars=181`、`vol=0.03`、`market_frac=0.6`；`DEFAULT_SIGNALS = (0, 0.02, 0.04, 0.06, 0.10, 0.15, 0.25)`，`DEFAULT_TRIALS = (1, 20, 100, 182, 787)`，`n_repeats=12`、`n_perm=30`、`power_target=0.80`。in-sample 与 OOS 是同一 DGP 的独立抽样——**这是对闸门最有利的情形**，因此检出率是上界。

关键在于校准不是「手填指标」：所有 `hac_t / p_value / cost_adj_return / ls_t / sr / RankIC_oos / null_tstats` 都经**生产函数**计算，历史假设族用 `Uniform(0,1)` 的 `n_trials−1` 个零 p 值补齐，再交给真实的 `apply_promotion_gates`。MDE 定义为检出率首次 ≥ 0.80 的真实 ρ。

实测（`user_workspace/reports/gate_calibration.md`）：

| `n_trials` | 1 | 20 | 100 | 182 | 787 |
| --- | --- | --- | --- | --- | --- |
| MDE（真实 IC） | 0.06 | 0.10 | 0.10 | **0.10** | 0.15 |
| DSR 每期门槛 | 0.0000 | 0.0968 | 0.1200 | 0.1275 | 0.1444 |

虚警率（ρ=0）**0.0%**；主要瓶颈是 `dsr_pass`（169 次失败）与 `fdr_pass`（67 次）。正式 run 的 `n_trials=182` 需要真实 IC ≥ 0.10，**远高于加密日频现实 IC 0.02–0.05**（源码常量 `real_ic_hi = 0.05`）。

结论必须按报告原文写清楚：

> 「0 promoted」至少有一部分是**功效不足**，不能再全归因于因子都不行。报告证明的是**统计校准**，不是挖到 alpha；不触碰 holdout 账本，不构成正向 OOS 证据。

这把第 1 章那个「方法正确性 vs 经济 alpha」的捆绑拆开了：可以单独证明「方法是校准过的」，同时承认「还没有正向结果」。`TODO.md` 把它记为「R=1 这个乘数里『方法没验过』的那部分被清掉了」，但 R 本身仍为 1。

如何提升功效？从 `σ_SR·√(2 ln K)` 看只有三条路：**减少 `K`**（廉价 gate 前置、去重、更小的搜索空间）、**增加 `n_obs`**（更长的干净数据、滚动窗口累积）、**提高 `sr`**（降低换手成本、在合适的交易周期上挖）。第 3 条正是 P0.5 的结论：必须在交易周期上挖。

### 13.9 工程陷阱

1. **按命令次数而不是信息暴露计「一次」**。调试脚本展示过留出区间也算消耗；修完 bug 必须换新区间或把旧区间降级为诊断数据。
2. **有折无重拟合**。用 `weights_differ_across_folds` 之类的自证字段让系统自己证明没偷懒；只测索引算术的单测会与实现脱节。
3. **用日历天数当 bar 数**。7×24 市场必须按所有标的的真实 bar 交集分块。
4. **滚动揭示推移动锚点**。预注册边界一旦可重定义，「未见过的数据」就没了意义。
5. **leave-K-out 当成干净留出**。`clean=False` 必须在报告里大声标注「仅验机制，不是独立证据」；真正干净要么等新时间，要么下载不重叠的新标的。
6. **账本被 gitignore / 存在内存中 / 只在 CLI 生效**。守卫必须覆盖所有入口（含 API），并有入口接线断言防新增路径漏接。
7. **小标的池的静默空回测**。`min_assets` 不自适应会让 6 币池产出「0 交易 0% 收益却报成功」——这类错误比亏钱更危险，因为它看起来像「策略不亏不赚」。
8. **只做阴性对照**。没有阳性对照，「0 通过」永远无法区分「没挖到」和「闸门把什么都拦了」。

### 本章小结

1. 数据是会耗尽的资源。「一次」按信息暴露计，不是按成功命令计；`consumed_before_read` 是这条纪律的正确实现。
2. purge 宽度应 ≥ `horizon_bars`（防标签重叠泄漏），embargo 处理序列相关；FactorMiner 用 purge=1 + embargo=5，5 折 gap 全为 6 bars。
3. 真 walk-forward 必须逐折重拟合标准化参数与权重；AlphaMaster「全样本算完再切片」是明确的反面样板，`weights_differ_across_folds` 是有效的自证手段。
4. 一次性 holdout 守卫要默认 `strict`、覆盖 CLI 与 API 全部入口、账本可提交、逃生口强制留审计行；「功能做完但没接进主流程」是成本最低也最该先补的一类差距。
5. 滚动预注册（锚点自动、30 根/窗、5 根 embargo、按真实 bar 交集）把首个干净窗口 ETA 从 2027-02-28 提前到 2026-12-13，且从第 30 根起即可累积证据。
6. universe holdout 提供时间之外的第二根干净数据轴，`clean` 标志与 `require_fresh` 防止把 leave-K-out 误当独立证据。
7. 闸门需要阳性对照：虚警率 0.0%、`n_trials=182` 下 MDE=0.10 > 现实 IC 0.02–0.05，证明「0 promoted」含功效不足成分。提升功效只有三条路：减少 `K`、增加 `n_obs`、提高 `sr`。
8. 留出纪律再完整也只保证「不骗自己」。R（结果产出）是乘数，这一项不动，A/D 再高也只是「一套很严谨的、暂时还没挖到东西的研究工具」。
