## 第 6 章 手工公式库与确定性枚举：从 Alpha101 到 Alpha360

> 本章回答：机器开搜之前，人该先写下什么。手工公式库是基线、对照与消融材料，不是挖掘成果。本章从 Alpha101 的算子语义走到 qlib 的 Alpha158/360 模板，拆开确定性枚举怎样变成多重检验分母，再落到 29 个加密模板与播种：一份 FDR 0/56 的阴性报告说明，分母就是结论。

### 5.1 为什么先讲手工公式：假设驱动与搜索驱动的分工

**原理与推导。** 因子挖掘有两条起点，顺序不能颠倒。

**搜索驱动**是第 5 章那套语言的自然延伸：给定算子集 `O`、终端集 `T` 和组合规则 `G`，让 GP、RL 或 LLM 在表达式空间里游走，产出候选，按 fitness 排序后再交给闸门证伪。**假设驱动**反过来：先写下一条可证伪的经济命题，再把它翻译成一条公式。两者的产出物看起来一样——都是一条 AST、一个 `s_t`、一个 RankIC——但认识论地位完全不同：前者的候选数是 `num_trials` 分母的一部分，后者是分母之外的**参照系**。

手工公式库因此有三重身份，缺一不可：

- **基线（baseline）**：简单动量、反转、波动率、价量相关这类「已知答案」的因子。搜索结果若连这些都超不过，所谓「挖到 Alpha」就是循环论证。
- **对照（control）**：与主候选只差一个成分的公式，用来隔离某个成分到底有没有贡献。
- **消融材料（ablation）**：把模板按 `字段 × 算子 × 窗口` 拆开，逐组关闭，看哪一类在留出段上退化最严重，从而做**过拟合归因**。

写成统计量更清楚。设一个假设 `H` 对应一组公式 `{F_1, ..., F_m}`，每条给出评价统计量 `T(F_i)`（通常是 RankIC 的 NW t 值），闸门则问：

```
H_0:  E[T(F_i)] = 0            无信息零假设
N_trials = m                   该假设族实际评估过的候选数
q_i = BH(p_(i), N_trials)      BH-FDR 校正后的 q 值，p_(i) 为第 i 小的原始 p
```

其中 `m` 不是「最终写进报告的那几条」，而是**实际算过的全部次数**。手工公式库的 `m` 小而可控，正好用来校准闸门；搜索驱动的 `m` 动辄几百上千，若还用单条公式的 `p < 0.05` 去判显著，等于把「在噪声里撞到的最大值」当成 alpha。这就是本书把手工公式放在搜索之前的原因：先有一个分母干净、语义清楚的基线，再去判断机器搜出来的东西是否真的越过了它。

判断是：**公式库不是挖掘结果**。它的价值不在于这 101 条或 158 条能不能赚钱，而在于给「好」与「坏」提供了一个不随搜索过程漂移的标尺。一个连基线都没有的研究流程，RankIC +0.02 既可能是不错的边际，也可能纯属 56 次试验里的最大值——没有参照系，这两者无法区分。

### 5.2 WorldQuant 101：算子语义与两条公式的经济学

Kakushadze (2016) 的 *101 Formulaic Alphas* 把「公式化因子」这件事变成了一门有固定词汇的 DSL。项目调研报告 §5.2 逐条核对过它的实现：`101Alpha_code_1.py` 顶部 18 个 `def` 扣除 2 个回调得 **16 个封装算子**，再加上内联原语，**合计约 24 类算子**：

| 类别 | 算子 | 语义 |
|---|---|---|
| 截面 | `rank` | 截面百分位 |
|  | `scale` | `x·k / sum|x|`，使截面绝对值和归一 |
| 时序位置 | `ts_argmax` / `ts_argmin` | 窗口内最大/最小值出现的位置（距今天数） |
|  | `ts_rank` / `ts_min` / `ts_max` | 时序分位与极值 |
| 时序统计 | `stddev` / `sma` / `ts_sum` / `product` | 标准差 / 均值 / 求和 / 连乘 |
|  | `correlation` / `covariance` | 双序列滚动相关 / 协方差 |
|  | `delay` / `delta` | 滞后 / 差分 |
| 加权 | `decay_linear` | 线性加权，权重 `i / (d(d+1)/2)` |
| 逐点 | `SignedPower` / `sign` / `abs` / `log` / 幂 `^` | 保号幂与变换 |
| 其它 | `adv{d}` / 三元 `? :` / `||` / 比较 | 平均美元成交量、条件分支、逻辑或 |

`adv{d}` 值得单说：它是过去 `d` 日平均成交金额，本质是一个**流动性尺度**，把成交量类因子从「绝对手数」变成「相对基准」，与 qlib Alpha158 里的 `VMA/VSTD/WVMA` 是同一思路。三元 `? :` 则是这批公式的骨架——大量 alpha 靠「条件成立取 A，否则取 B」来编码 regime 判断。

下面两条公开公式做逐项拆解。重点不是背公式，而是看清每个算子承载了什么经济假设，以及它能否在 FactorMiner 里原样落地。

**Alpha#1**

```
rank(Ts_ArgMax(SignedPower(((returns < 0) ? stddev(returns, 20) : close), 2.), 5)) - 0.5
```

由内向外读：`returns` 是当日收益；`returns < 0` 时取 `stddev(returns, 20)`（过去 20 日收益波动），否则取 `close`（收盘价）；`SignedPower(·, 2.)` 保号平方，既保留方向又放大幅度；`Ts_ArgMax(·, 5)` 返回近 5 日里该序列最大值出现在**距今几根 bar**；`rank` 把这个位置做截面百分位；最后 `- 0.5` 把取值中心化到 `[-0.5, 0.5]`。经济含义是：下跌日的高波动被当作「恐慌强度」，取近 5 日该强度峰值出现的**时点**做横截面排序——峰值离今天越近，越像刚发生一次的抛售；这是一条「波动率状态 × 时序位置」的反转信号，而非简单的价格动量。这条公式同时依赖 `returns` 终端、`stddev` 与三元 `? :`，恰好落在调研报告 §5.2 列出的 FactorMiner 缺口上（缺条件/分支、缺 `vwap/adv/returns/amount` 终端），因此它只能作语义参照，不能原样复现。

**Alpha#6**

```
-1 * correlation(open, volume, 10)
```

`correlation(open, volume, 10)` 是过去 10 日开盘价与成交量的时序相关系数，`-1` 把符号取反。经济含义是经典的价量背离假设：价量同步抬升通常对应放量追涨，取负号赌其随后短期回落；若价升量缩（相关为负），反而给正分。这条在 FactorMiner 里几乎可以直译——`ts_corr`（`core/miner/operator_runtime.py:397`）对应 `correlation`，常量终端 `-1` 配合 `mul` 完成取反，前提是终端集里有 `open` 与 `volume`（`TERMINALS_DEFAULT` 确有这两列）。

两条公式放在一起，能读出三件事。第一，**Alpha101 的遗产是 DSL 语义，不是 101 个答案**：`rank/scale/ts_argmax/signed_power/decay_linear` 这套词汇被 qlib、AlphaGen、FactorMiner 沿用，连命名都能追到它。第二，**「实现」与「注释」会分叉**：报告 §5.2 指出 `code_1.py:131-132` 把 `rank(axis=1, pct=True)` 注释掉了，实际走 `df.rank(pct=True)`，未按截面分组，与「Cross sectional rank」的注释不符；FactorMiner 的 `cs_rank`（`operator_runtime.py:124-128`）用 `rank(axis=1, pct=True)`，在这点上更正确。第三，**分支与终端是表达力的真瓶颈**：`signed_power` 已有等价实现，但三元 `? :`、`adv{d}`、`returns` 终端的缺失，使多数 Alpha101 公式无法进入我们的表达式空间——第 5 章说的「表达力看四个维度」，在这里得到了具体印证。

### 5.3 qlib Alpha158 / Alpha360：模板即特征工程

qlib 把手工公式推到了另一个极端：不是写 101 条公式，而是写一套**可声明式展开的模板**。定义真身在 `qlib/contrib/data/loader.py`，两代因子集都是「枚举」而非「搜索」的产物。

**Alpha360**（`loader.py:4-58`）：6 组字段 `CLOSE/OPEN/HIGH/LOW/VWAP/VOLUME` × 60 个时间位移（历史 `1..59` 加当期），全部除以最新 `$close`（成交量除以 `$volume+1e-12`），使 `CLOSE0` 恒为 1。于是

```
Alpha360 = 6 字段 × 60 位移 = 360 维
```

把所有价格归一到「相对当前收盘」的比值，等价于一次性把水平量、趋势、量能都摊平成固定长度的特征向量，交给下游模型（LGBM/NN）去学。它不含任何「挖掘」成分，纯粹是特征工程。

**Alpha158**（`loader.py:61-310`）更有结构：

```
kbar    9  个  K 线形态（KMID / KLEN / KUP / KSFT ...）      :104-126
price   4  个  价格位置                                        :127-133
rolling 29 组 × 5 窗口 [5,10,20,30,60] = 145                  :139
合计 9 + 4 + 145 = 158
```

29 组含 `ROC/MA/STD/BETA/RSQR/RESI/MAX/MIN/QTLU/QTLD/RANK/RSV/IMAX/IMIN/IMXD/CORR/CORD/CNTP/CNTN/CNTD/SUMP/SUMN/SUMD/VMA/VSTD/WVMA/VSUMP/VSUMN/VSUMD`——本质就是「算子 × 窗口」的笛卡尔积。标签是 `Ref($close,-2)/Ref($close,-1)-1`（`handler.py:89-90`），即 T+1 到 T+2 的收益；注意这里的负位移 `Ref(·,-2)` 是**标签**，qlib 的 `Ref(feature,N)` 语义里 `N<0` 取未来（`ops.py:781`），把它误写进特征就是前视——这正是 5.6 要列的坑。

真正值得抄的是 `get_feature_config(config)`（`loader.py:72-82`）：它接受 `kbar/price/volume/rolling` 四组与 `windows/include/exclude`，于是**消融是声明式的**。逐组关闭某一类窗口，看哪一类在留出段上退化最严重，就能把「过拟合」归因到具体的特征族，而不是笼统地说「模型太复杂」。调研报告 §2.1.6 把这一条列为对 FactorMiner 最有价值的借鉴点之一：「把因子集做成 `字段 × 算子 × 窗口` 配置，用于过拟合归因」。

**竞品对照。** 把声明式模板与确定性枚举放在一起横向看，几个框架的分野很清楚（数字取自调研报告 §6.1 / §4 与成熟度评估报告 §4.1）：

| 框架 | 模板 / 枚举规模 | 窗口 | 去冗余 | 统计闸门 | 可声明式消融 | 加密适配 C |
|---|---|---|---|---|---|---|
| qlib Alpha158/360 | 158 / 360 维声明式特征 | `[5,10,20,30,60]` / 60 位移 | 由配置 `include/exclude` | ❌ 平台层不含闸门 | ✅ 四组开关 | 2 |
| WorldQuant Alpha101 | 101 条硬编码公式 | `d` / `adv{d}` | ❌ | ❌ | ❌ | 1 |
| crypto-factor-lab | 21-op DSL + 手工 6 因子 | `(2,4,8,12,24,48,96)` | `|corr|≥0.95` 贪心 | ✅ 17 道，BH + 置换零假设 | ⚠️ 五族均衡抽样 | **8** |
| alpha-factor-mining-crypto | 13 核心 + 40 窗口 + 40 组合，预算 80 | 多窗口 | Spearman `0.75` | ❌ 样本内自证 | ❌ | 6 |
| FactorMiner 加密模板 | 29 模板 × 4 窗口，实测 56 AST | `(6,12,24,48)` | ✅ AST 签名去重 | ✅ 累积 FDR + 闸门 | ✅ 按流过滤 | 7 |

表里最刺眼的是右下角两家：`alpha-factor-mining-crypto` 因子清单最实用、能跑，却是「样本内选因子 + 样本内回测」（`pipeline.py:225-230,301`）；`crypto-factor-lab` 只有 BTC 单品种、21 个算子里只有 `funding_rate` 一个加密字段，却是 20 个外部框架里唯一「能跑 + 加密原生 + 统计纪律完整」的组合（成熟度 M=8、加密适配 C=8）。这说明**模板数量与结论可信度几乎无关**——决定可信度的是分母、留出与非方向语义，下一节就把分母这件事算清楚。

### 5.4 确定性枚举：组合爆炸如何变成多重检验分母

确定性枚举没有「搜索」的随机性：给定模板集、参数网格与预算，按固定顺序产出全部候选。crypto-factor-lab 的 21-op DSL（`expression.py:15-19`：二元 4、一元 4、窗口 10、结构 3）配 `GeneratorConfig(fields=(close,volume,funding_rate), windows=(2,4,8,12,24,48,96), max_depth=3, max_complexity=6, max_candidates=5000)`（`generator.py:28-38`），按 5 族均衡抽样；AI 提议与公式枚举**共享同一 200 候选总预算**（`service.py:756-777`），这个「预算」就是把分母显式写进配置。另一头，`alpha-factor-mining-crypto` 用 13 个核心因子（`factors.py:69-104`）扩出 40 个多窗口版本，再用 top-16 两两 × `add/sub/mul` 组合最多 40 个，`FACTOR_MAX_COUNT=80`（`settings.py:45`），去冗余靠 Spearman `corr_threshold=0.75`（`evaluation.py:28-136`）。

参数网格的代价是乘性的。设模板数 `M`、窗口集 `W`、字段集 `F`、组合深度 `D`：

```
N_trials ≈ M × |W| × |F| × C(D)     实际评估过的候选数（试验次数分母）
E[max_i |t_i|  |  H_0]  随 N_trials 单调上升   噪声里撞出「显著」的概率
q_(i) = BH(p_(i), N_trials)        校正后 q；未通过即不可晋升
```

其中 `N_trials` 是全部评估次数（含失败、含被去冗余淘汰的），`p_(i)` 是排序后的原始 p 值，`q_(i)` 是 BH-FDR 校正值，`H_0` 为无信息零假设。三个推论直接决定实验设计：

1. **窗口扫描就是隐式多重检验**。把同一个 `ts_rank(basis)` 在 `{6,12,24,48}` 上各跑一次，不是 4 次独立验证，而是 4 次试验；它们高度相关，BH 在正相关下偏保守，但分母仍必须记全。用「多窗口都显著」当独立佐证，是系统性低估 p 值。
2. **去重必须在记账之前**。窗口无关模板（`sign(funding_rate)`、`basis_funding_spread`、净爆仓失衡）若按窗口重复展开，同一条公式被算 4 次却只记 1 次，分母被人为压低，闸门被放松。
3. **分母就是结论**。AlphaMaster 的病因链是最好的反例：`TRAIN_STEPS=9000 × BATCH_SIZE=192`，理论上界 172.8 万次候选，每个候选都在同一批验证折上打分、每步刷新冠军并写盘，而全仓 `num_trials` / BH / Holm / DSR / 随机零分布 **0 命中**（`alphamaster_competitor_review.md` §2.4）。反过来，FactorMiner 的 `gate_validation.md` 显示 6 个旧因子在 `n_trials=787` 下被 DSR 全部拦下，而 `n_trials=1` 时有 5 个能过——同一批因子，只改分母，结论翻转。

**算法与伪代码。** 下面这段伪代码把「枚举 → 去重 → 记账」的正确顺序固化下来，它对应 `core/miner/crypto_features.py:406-440` 的 `iter_crypto_features()`，也是调研报告 Phase 0.2 要求的 `ExperimentTrace` 行为：

```python
def enumerate_templates(templates, windows, panel):
    trials = 0                       # 试验次数分母，跨 run 累加，含失败候选
    seen = set()
    out = []
    for tpl in templates:
        if not tpl.applicable(streams_in(panel)):   # 按实际存在的流过滤，
            continue                                # 缺文件静默降级为 OHLCV
        for w in windows:
            ast = tpl.build(w)                      # 纯 window -> AST 的构造子
            sig = json.dumps(ast, sort_keys=True)   # 规范签名：与顺序无关
            if sig in seen:                          # 窗口无关模板只发一次；
                continue                             # 去重在前，分母才不会被污染
            seen.add(sig)
            trials += 1                             # 每次评估都记一次，
            out.append((tpl.name, w, ast))          # 返回模板名与窗口便于归因
    return out, trials                             # trials 交给 BH-FDR / DSR
```

注意 `trials` 在去重**之后**才自增，且 `applicable()` 过滤掉的模板不计数——因为没进过评价器，就不该占分母。反过来，凡是真的送进 `evaluate_ast` 算过 RankIC 的，哪怕后来因有效率数不足被排除出排名，也必须计入：调研报告 Phase 0.2 明确要求「跨 run 记录全部评估过的候选（含失败的）」，累积 FDR 才成立。

统计纪律的横向差距，用调研报告 §6.3 与成熟度评估报告的口径并列最直观：

| 框架 | purge/embargo | FDR/Holm | HAC/NW t | 随机零假设 | `num_trials` 分母 | 一次性留出 |
|---|---|---|---|---|---|---|
| crypto-factor-lab | ✅ `purge_bars=horizon` | ✅ BH | ✅ `hac_lags=1` | ✅ 100 次置换 | ⚠️ 候选预算 | ✅ holdout ledger |
| LLM-Alpha-Mining-Framework | ✅ | ✅ BH/Holm/RW | ✅ 21 滞后 | ✅ 随机语法池 | ✅ 全部尝试 | ✅ consumed-before-read |
| alpha-factor-mining-crypto | ❌ | ❌ | ❌ iid t | ❌ | ❌ | ❌ |
| AlphaMaster | ⚠️ 仅 gap=20 | ❌ | ❌ | ❌ | ❌ 全仓 0 命中 | ❌ val 每步复用 |
| FactorMiner（当前） | ⚠️ 待补 | ✅ BH + Holm + 累积 FDR | ✅ NW-HAC | 有实现、未接入晋升 | ✅ 跨 run `ExperimentTrace` | ✅ `HoldoutLedger` |

### 5.5 FactorMiner 的对应机制：29 模板、去重、播种与一份阴性报告

**FactorMiner 实现。** 第 5 章留了个尾巴：FactorMiner 的终端只有 OHLCV 五个，这是表达力的真瓶颈。Phase 3A 的加密原生特征库（`docs/research/optimization_plan.md:47-55`）就是冲着它去的，而且刻意**复用现有 59 个算子、不新增算子**——判断很清醒：缺的是「读什么流」，不是「加什么函数」。

`core/miner/crypto_features.py` 的 `CRYPTO_FEATURE_TEMPLATES`（`:152-361`）共 **29 个**参数化模板，每个都是纯 `window -> AST` 构造子，按经济先验分五类：

| 类别 | 数量 | 代表模板 | 编码的先验 |
|---|---|---|---|
| funding | 7 | `funding_zscore` `funding_rank` `funding_delta` `funding_rel_change` `funding_ema_gap` `funding_sign` `funding_vol_adj`（`:154-196`） | 极端正费率 = 多头拥挤付费，反转信号；费率**变化**领先持仓 |
| open_interest | 7 | `oi_zscore` `oi_rel_change` `oi_momentum` `oi_rank` `oi_volume_divergence` `oi_price_divergence` `oi_ema_gap`（`:198-243`） | 价涨 OI 涨 = 新杠杆趋势；价涨 OI 跌 = 空头回补弱趋势 |
| basis | 6 | `basis_zscore` `basis_rank` `basis_delta_scaled` `basis_vol_adj` `basis_funding_spread` `basis_funding_gap`（`:246-287`） | 永续溢价 = carry / 情绪，过高先于去杠杆 |
| liquidation | 5 | `liq_pressure` `long_liq_zscore` `short_liq_zscore` `liq_volume_ratio` `net_liq_delta`（`:289-321`） | 强平流标记局部极值，净失衡最干净 |
| interaction | 4 | `funding_oi_squeeze` `oi_liq_interaction` `basis_oi_carry` `funding_liq_reversal`（`:323-360`） | 拥挤度 × 杠杆/强平方向的确认 |

7 + 7 + 6 + 5 + 4 = 29。数值安全沿用第 5 章的契约：`EPS = 1e-9`（`:79`）、`_safe_denom(expr) = add(abs(expr), 1e-9)`（`:97-98`）、`_liq_pressure_ast()` 用「多头减空头 / 总量 + 1e-9」把净失衡压进 `[-1, 1]`（`:101-105`）。窗口阶梯 `DEFAULT_CRYPTO_WINDOWS = (6, 12, 24, 48)`（`:369`），在 1h 上覆盖日内、在 1d 上约对应一周到两月。

三处机制值得逐行说清：

**按实际流过滤**。`crypto_streams_in()`（`:375-387`）从面板推断有哪些加密流，`applicable_templates()`（`:390-392`）用 `template.required` 取交集；`build_crypto_feature_asts()`（`:443-478`）因此在一台没有 funding/OI 文件的机器上「少给几个种子」而不是报错。数据侧 `crypto_streams.py` 只做 past-only `ffill`、绝不 backfill（optimization_plan.md:48），对齐本身就是防前视的一部分。

**按 AST 签名去重**。`iter_crypto_features()`（`:406-440`）对每个窗口调用 `template.build(w)`，再用 `json.dumps(ast, sort_keys=True)` 做规范签名（`:436`），命中 `seen` 就跳过。注释写得很直白：窗口无关模板（如 `sign(funding_rate)`、`basis_funding_spread`、`liq_pressure`）本会被每个窗口重复发一次，"a trial is never counted twice (which would bias multiple-testing corrections)"（`:414-416`）。它同时返回 `(template, window, ast)`，便于把结果归因到具体模板与窗口——这正是 5.3 说的可消融性。

**`crypto_terminals()` 只接 GP 与 RL，且两者有差异**。`crypto_terminals(terminals, data)`（`:395-403`）把实际存在的加密流追加进终端列表；全项目只有两个挖掘器调用它：`gp_miner.py:52` 与 `rl_miner.py:79`。但 GP 还额外用 `build_crypto_feature_asts()` 播种初始种群（`gp_miner.py:61-65,95-107`），RL 只扩充终端、不播种——`rl_miner.py:70-73` 的注释自述 "RL used to stay on the 5 OHLCV columns"，补的正是这一层。LLM 侧仅在 system prompt 注入可用字段与加密语义（optimization_plan.md:51 明确「仅数据感知，不是 RD-Agent 闭环」），NN 未接；`TERMINALS_DEFAULT` 仍是五个 OHLCV（`gp_miner.py:23`、`rl_miner.py:19`）。播种比例 `gp.crypto_seed_ratio` 默认 **0.3**（`gp_miner.py:57`），`n_seed = min(len(crypto_asts), round(population_size × ratio))`（`:100`）：默认 `population_size=20` 时约 6 条来自模板，其余由随机树补足；`crypto_windows` 默认取 `DEFAULT_CRYPTO_WINDOWS`（`:58-60`）。

**真实验证结果**（`user_workspace/reports/crypto_features_validation.md`、optimization_plan.md:53）必须原样引用，因为它是本章论点最硬的证据：20 个标的、1d、2023-01→2026-11、次日收益、未计成本；可用 **56 个 AST**，25 个因有效 IC 期数不足 30 被排除出排名（多为 OI/爆仓类，Binance 公共接口的 OI 只保留约 30 天，liquidation 无免费接口）。按 |mean RankIC| 排序：

```
ts_rank(basis, 48)      mean RankIC +0.0178   ICIR +0.076   NW t +2.79   BH q 0.197
sign(funding_rate)      mean RankIC -0.0153   ICIR -0.062   NW t -2.51   BH q 0.197
BH-FDR(q≤0.05) 通过 0/56，最小 q≈0.197  →  不可晋升
```

`sign(funding_rate)` 为负，方向上符合「费率为正即多头拥挤、次日回落」的先验；`ts_rank(basis,48)` 的 NW t = 2.79，若孤立地看一次检验，几乎会被当成显著。但放进 56 次试验的分母里，BH 校正后最小 q 仍有 0.197——**没有一个能过闸门**。报告的结论也很克制：这次验证的是「加密原生流的接入、对齐与可评估性」，表中 RankIC 只是「第一眼读数」，要进 `INSPECTED` 仍须过 Phase 1 的 BH-FDR / DSR / OOS 强度。端到端 Director 运行（20 标的、2 轮 × 种群 10、cross-asset 1d）返回 4 个候选，闸门判定 1 `INSPECTED` / 3 `DISCOVERED_UNVERIFIED`，候选里出现 `abs(mul(basis, close))` 与 `ts_rsi(cs_rank(funding_rate))`，证明模板确实进了挖掘与评估链路——但这不等于信号成立。

一句话判断：**分母就是结论**。第 5 章把 `num_trials` 立为契约，这一节给出了它兑现后的样子：t 值没变、公式没变、数据没变，只是把「试了 56 次」如实记进去，显著性就消失了。

### 5.6 假设驱动的实验设计与工程陷阱

有了基线、模板和分母，最后一步是把假设本身设计得可证伪。研究协议（`skills/factorminer-research-architect/references/research-protocol.md` §3）给了一个可直接套用的模板：

> 在流动性过滤后的 BTC 永续 5 分钟数据中，相对成交量异常且价格突破过去窗口高点的信号，对随后 3 根 bar 的收益具有正向 RankIC。

关键在于「至少设计一个反向或替代解释」：极端成交量代表短期耗竭而非延续；信号只是波动率暴露；收益来自少数行情阶段；结果由交易时段、资产规模或流动性驱动；因子只是已有基线的重复表达。对应的**对照优先**包括：只使用价格突破、只使用相对成交量、信号取反、打乱不破坏时间块结构的安慰剂检验、不同窗口/horizon/行情阶段、与简单动量/反转/波动率因子比较。

这四组对照各自回答一个不同问题：单成分对照做**消融**（复合信号里哪一半在贡献）；取反做**方向**检验（若取反后同样显著，说明原信号只是某种暴露的线性投影）；安慰剂做**零分布**校准——注意必须「打乱时间块」而不是逐行打乱，否则会破坏收益的自相关结构，把零分布人为压窄、把闸门调松；不同窗口与行情阶段做**稳定性**检验，防止结果由一段行情撑起来。研究协议 §4 还要求每条特征记录字段来源、公式、窗口与 `min_periods`、是否滞后、缺失/零值/极值/除零处理、标准化方式及拟合样本、时序或截面语义、索引对齐，标签则须写明价格基准、entry/exit、horizon、简单或对数收益、是否去市场/行业暴露、重叠标签与幸存者偏差处理。

**工程陷阱（可直接照做）**：

1. **模板去重不足导致试验分母虚低**。`iter_crypto_features` 已按 AST 签名去重，但若在外部脚本里自己 `for w in windows` 再展开窗口无关模板，同一条 `sign(funding_rate)` 被算 4 次、分母却只记 1 次，BH 校正被人为放松。去重必须在记账之前，并合并跨 run 的 `num_trials`（累积 FDR）。
2. **窗口扫描等于隐式多重检验**。`ts_rank(basis,{6,12,24,48})` 是 4 次试验，不是 4 次验证；窗口间高度相关，别拿「多窗口都显著」当独立佐证。分母按**全部评估过的候选（含失败的）**记。
3. **模板里 `shift(-n)` 误用**。`Ref($close,-2)` 这类负位移只许出现在标签；一旦写进特征，就把未来收益灌进了 `F(X_{≤t})`。研究协议 §4 把「`shift(-n)` 被用于特征而非标签」列在代码审查第一条，同批还要查 `center=True` 的滚动窗口、向后填充（bfill）、resample 后把未完成高周期 bar 提前可用、merge 未用 as-of 语义。
4. **全样本标准化后切分**。「不得先在全样本计算均值、方差或分位点，再切分训练测试」；应优先用滚动或训练期拟合的标准化。`funding_zscore` 这类模板走 `ts_zscore` 滚动窗口，统计量只在历史窗口内取，正是为了守住这条。同理，训练/回测/实时三端不能共享缓存或拟合权重。
5. **资产池幸存者偏差**。`alpha-factor-mining-crypto` 用**当下**成交额 top30 选币（`data_loader.py:32-55`），明确有偏；FactorMiner 固定 20 币、横截面 IC 只在当期有数据的标的上计算并以 `min_assets` 过滤极窄截面（validation 报告 §6），但仍非 point-in-time，结论不能外推到已退市/未上市标的。
6. **样本内选因子 + 样本内回测**。`alpha-factor-mining-crypto` 用同一份 `market_df` 既评价又回测（`pipeline.py:225-230,301`），未来收益 `close.pct_change(h).shift(-h)` 无 purge；这类「自证」会让 RankIC 好看，却没有留出可言，因子对所有时间段都拟合过一遍。

### 5.7 本章小结

1. **公式库是基线、对照与消融材料，不是挖掘结果**。没有它，RankIC +0.02 既可能是不错的边际，也可能是 56 次试验里的最大值——「搜索有效」会退化成循环论证。
2. **手工公式的真正遗产是 DSL 语义**：`rank/scale/ts_argmax/signed_power/decay_linear`、三元 `? :` 与 `adv{d}` 定义了后人怎么谈因子。Alpha101 的 101 条与 qlib 的 158/360 都是**枚举**而非搜索，其价值在可声明式消融，不在单条公式的收益。
3. **确定性枚举的候选数就是多重检验分母**：`N_trials ≈ M × |W| × |F| × C(D)`，每加一维分母乘一个因子；窗口扫描是隐式多重检验，去重必须在记账之前，且分母要含失败候选、跨 run 累加。
4. **FactorMiner 的 29 模板复用 59 算子、按 AST 签名去重、按实际流过滤、以 `crypto_seed_ratio=0.3` 播种**，是「假设驱动」的冷启动而非搜索产物；`crypto_terminals()` 只接 GP 与 RL（GP 额外播种、RL 只扩终端），LLM 仅数据感知，NN 未接。
5. **20 标的 1d 的 56 个 AST 给出了最干净的一课**：`ts_rank(basis,48)` RankIC +0.0178、NW t 2.79 看着显著，`sign(funding_rate)` -0.0153 也符合拥挤度先验，但 BH-FDR 0/56（最小 q≈0.197）全数拦下，不可晋升。分母就是结论，第一眼读数不是可上线结论。
6. **可证伪的实验从主候选 + 反向/消融/安慰剂对照起步**，并守住四条边界：去重先于记账、`shift(-n)` 只进标签、标准化只用训练期、留出一次且记入账本；再补上 purge/embargo，才能让「显著」真正指向样本外。
