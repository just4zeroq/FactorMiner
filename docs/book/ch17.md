## 第 17 章 系统架构：把四种范式装进同一个闭环

> 本章回答：GP、RL、LLM、NN 的产物形态天差地别，凭什么跑在同一条主循环里？类型污染会拖出怎样的分支地狱，控制反转与统一中间体如何收敛它？四个契约各管什么，为何仅更新模型不等于发现因子？分层架构、注册表与工程契约怎样保证能力真正接进主流程？工程成熟度能否替代方法论成熟度？

### 15.1 设计哲学：控制反转、统一中间体与 FactorExpression 协议

把"挖掘"这件事从四种范式里抽出来，剩下的骨架只有一句话：**生成候选 → 评价 → 模型更新 → 再生成**。GP 的交叉变异、RL 的策略采样、LLM 的反思改写、NN 的前向传播，都是"生成"这一个动作的不同实现；IC、RankIC、fitness、loss 张量，都是"评价"这一个动作的不同返回形态。控制反转（IoC）在这里的含义很具体：主循环的调度权归框架，范式只实现四个钩子，不允许某个范式自带一套 `for epoch in range(...)` 的循环。`FactorMinerDirector` 因此成为唯一对外网关，研究员面对的是声明式配置，而不是继承层级。

这个闭环可以写成一组递推，符号先交代清楚：

```
Cₜ = G(Mₜ₋₁)                      生成：由上一轮模型状态产出候选集
Fₜ = E(Cₜ, D_in)                  评价：在样本内面板 D_in 上算指标或保留计算图
Mₜ = U(Mₜ₋₁, Cₜ, Fₜ)             更新：把反馈写回种群 / 记忆 / 策略 / 权重
A  = read(state.population ∪ state.replay_buffer)     终态产物
```

符号解释：`Cₜ` 是第 t 代候选集；`Mₜ` 是模型状态，对 GP 是种群、对 LLM 是成功/失败反思池、对 RL 是策略与回放缓冲、对 NN 是权重；`D_in` 是样本内面板；`Fₜ` 是统一反馈体 `EvaluationFeedback`（既有标量指标，也可携带带梯度的 `raw_outputs / raw_targets`）；`G / E / U` 对应四契约中的三个动作；`A` 是最终交给落库与回测的研究产物。最后一行是关键判断：**产物只从 `state` 读取，不由 `update_model` 就地返回**。一个范式把网络权重练得再好，如果没有把已评分候选写进 `state.population` 或 `replay_buffer`，Director 就没有任何可持久化的东西——这正是 `README.md:334-341` 反复强调的第 4 条结果契约。

为什么非要一个统一中间体？看类型污染的代价就够了。设系统有 P 种范式、Q 个下游消费者（并行评估器、存储层、Inspector、实盘编译器、Web 摘要）。若候选类型是 `candidates: List[Any]`，每个消费者都必须写 `if isinstance(cand, FactorExpressionAST) ... elif isinstance(cand, str) ... elif isinstance(cand, np.ndarray) ...` 来分派，分支总数随 `P × Q` 增长；新增一种范式，所有 Q 个消费者都要改。这就是所谓的 `isinstance` 地狱，它不是代码丑，而是**耦合度随规模相乘**。引入 `FactorExpression` 协议后，每个范式只需实现一次适配（O(P)），每个消费者只针对协议编程（O(Q)），总复杂度收敛为 `O(P + Q)`。控制反转的收益在这里是可以算出来的，不只是设计口味。

`core/miner/expressions.py:6-44` 定义了这个协议，四个方法各司其职：`compute(data)` 统一计算入口；`get_source()` 返回底层真正逻辑（AST 字典 / 代码字符串 / 模型版本与通道 / 动作序列）；`get_complexity()` 给出可读的复杂度标签（`Depth: 5`、`LoC: 10`、`Params: ...`）；`to_display_string()` 产出终端与 UI 表格里的精简字符串。四个方法合起来保证：下游不需要知道因子是怎么被生成的，也能算、能存、能展示、能比较。

五个子类把四种范式和一个组合层收进同一协议：

```python
# core/miner/expressions.py 的协议骨架（带注释，示意）
class FactorExpression(ABC):
    def compute(self, data): ...        # 统一计算：AST 遍历 / 沙盒执行 / 前向传播
    def get_source(self): ...          # 稳定的逻辑表达，也是 MD5 去重的输入
    def get_complexity(self): ...      # 复杂度标签，供 Anti-Bloat 与展示使用
    def to_display_string(self, max_length=50): ...

# 五个子类
# ① FactorExpressionAST (:62-98)      GP：ast_dict，compute 调 operator_runtime.evaluate_ast
# ② FactorExpressionCode (:100-145)   LLM：code_str + 显式 sandbox
# ③ FactorExpressionTensor (:147-188) NN：model_version_id + channel_idx
# ④ FactorExpressionAction (:190-210) RL：action_sequence
# ⑤ LinearCombinedFactor (:213-279)  组合层：sub_expressions + 固定 weights

# 两个能力标签（MixIn），按需多重继承，不进主继承链
# LineageTrackableMixIn (:46-52)  → get_lineage_parents()，支撑谱系追溯
# LLMReflectableMixIn   (:54-60)  → get_reflection_history()，承载反思记忆
```

有两处安全与语义边界必须讲透，它们都是"看起来该给个兜底、其实绝不能给"的地方。

其一是 `FactorExpressionCode`（`expressions.py:100-145`）：`compute()` 在 `:117-123` 检查 `self.sandbox`，没有显式传入 `RestrictedSandbox` 时直接抛 `RuntimeError("...unsafe exec fallback is disabled")`。**不存在退回裸 `exec()` 的兼容路径**。字符串关键字黑名单不是安全边界，`docs/architecture/v4_architecture_design.md:402-418` 明确写了四层边界：AST 白名单、禁止 import/循环/函数定义/文件访问、短生命周期 `spawn` 子进程加墙钟与资源限制、返回前校验类型/索引/列/dtype/有限值/对齐。顺序模式要求 `factor` 是与输入索引一致的 `pandas.Series`，`cross_asset` 模式要求是与时间索引和资产列完全一致的 `pandas.DataFrame`。这是 fail-closed：宁可让一个候选算不出来，也不能让生成代码在评估进程里跑起来。

其二是 `FactorExpressionTensor`（`expressions.py:147-188`）：`compute()` 在 `:155-161` 训练阶段直接 `return None`，注释写明"NN 训练阶段不在这里截断计算，需要保留梯度图"。原因是 NN 的评价不能走"算出面值再算 IC"这条路——那会切断计算图，`loss.backward()` 就无从谈起。`EvaluationFeedback` 因此同时携带 `metrics` 与 `raw_outputs / raw_targets`（`v4_architecture_design.md:65-71`），`evaluate_candidates` 把带梯度的张量原样回传，`update_model` 再执行反向传播。训练中间产物（`channel = -1` 的完整模型输出）不是可落盘因子；每轮更新后必须把冻结快照的各个输出通道物化为独立的 `FactorExpressionTensor`，才成为研究产物（`:714-720`）。把"训练用的张量"与"可交易的因子"混为一谈，是 NN 范式最容易踩的架构坑。

### 15.2 四契约、Director 与主循环

`BaseFactorMiner`（`core/miner/paradigms/base.py:169-332`）把闭环固定成四个抽象方法，契约边界非常干净：

- `initialize_search_space()`（`:203-208`）：初始化种群、环境、Prompt、网络与优化器，**只读配置，不读候选**。
- `generate_candidates()`（`:210-216`）：严格返回 `List[FactorExpression]`，不许返回裸字符串或张量。
- `evaluate_candidates()`（`:218-225`）：委托 `self.evaluator.evaluate(candidates)` 取得 `EvaluationFeedback`；NN 在此保留计算图。
- `update_model()`（`:227-235`）：把反馈写回 `self.state` 或模型参数；GP 更新种群、LLM 追加反思、RL 更新策略、NN 执行 `loss.backward(); optimizer.step()`。

`FactorMinerDirector`（`core/miner/director.py:21-111`）做组装而非调度：`:26-47` 实例化统一 `ParallelEvaluator`、按 `MinerRegistry` 或内置四大流派选出 Miner、把 evaluator 与 storage 注入 Miner；`:96-111` 的 `run()` 先 `_enforce_holdout()` 做一次性留出守卫，再 `self.miner.mine(...)`，最后 `_save_excellent_factors()` 与结果表。**主循环不在 Director 里，在基类里**，这是控制反转的落点：Director 换范式不用改一行，范式换实现也不用碰调度。

`mine()`（`base.py:249-332`）的完整骨架如下，带注释的伪代码对应真实实现：

```python
# core/miner/paradigms/base.py:249-332 主循环骨架（伪代码，带注释）
def mine(self, n_iterations, progress_callback=None):
    self.initialize_search_space()
    # 跨轮硬去重：把全库历史逻辑哈希注入过滤器，避免重复消耗 num_trials
    initial_hashes = self.storage_client.get_all_logic_hashes()
    div_filter = DiversityFilter(
        max_corr=0.7,
        initial_hashes=initial_hashes,
        value_threshold=self.config.get('dedup_value_threshold', 0.99),  # 设 0 关闭
        value_archive_limit=int(self.config.get('dedup_value_archive', 40)),
    )
    panel = self._factor_panel()          # 统一取真实面板，不把 client 对象传进去
    for epoch in range(n_iterations):
        raw = self.generate_candidates()
        # ① 拦截：精英父代保留，其余过两级去重（MD5 + 面值相关）
        candidates = div_filter.filter_redundant(
            raw, panel, preserved_candidates=self.state.population)
        if not candidates:
            continue
        # ② 判卷：统一评估器，NN 在此保留计算图
        feedback = self.evaluate_candidates(candidates)
        # ③ 名人堂：容量 100，按 MD5 去重，只收已评分且成功的候选
        for cand in candidates:
            r = feedback.for_candidate(cand)
            if r and r.succeeded and r.metrics:
                cand.metrics = r.metrics
                self._update_hall_of_fame(cand, r.metrics['fitness_score'])
        # ④ 学习：写回 state / 权重；产物必须在 population 或 replay_buffer 里
        self.update_model(candidates, feedback)
        self._log_epoch(epoch, candidates, feedback.metrics)
    self.dedup_summary = div_filter.summary()      # 让"去重是否生效"可自证
    return self._finalize(self._get_best_factors())
```

三处实现细节值得单独点出。`_update_hall_of_fame`（`base.py:184-201`）容量 `max_hof_size = 100`，按 `hashlib.md5(str(get_source()))` 去重后依 fitness 降序截断，是跨代精英的兜底记忆；`_get_best_factors()`（`:539-540`）优先从名人堂取，否则从 `state.population` 取。`_finalize`（`:334-364`）由配置 `finalize_method` 选择 `"linear"`（默认）或 `"alphapool"`，两者都只在样本内拟合权重，保证 evaluator 之后算出的 OOS RankIC 是诚实的。`ParallelEvaluator` 的线程数由 `evaluation.max_workers` 读取并校验在 1–64、默认 8，单候选超时 `evaluation.timeout_seconds` 默认 120 秒，超时标记 `status=timeout` 并继续整轮，不阻塞挖掘。

`_save_excellent_factors`（`director.py:161-371`）是闭环的出口：`:203-209` 把 `apply_promotion_gates` 接到含随机目标置换零分布的晋升判定，`:268-269` 把每次试验写进跨 run 的 `ExperimentTrace`，`:276` 给整批候选预分配 `fac_{uuid[:8]}` id，`:308-369` 按五类表达式分流落库，`:371` 再写 Phase II 快照。它同时把 `p_adj / dsr / n_trials / empirical_p / gate_pass / gate_checks` 写回因子档案（`:282-291`），让"这个因子当时为什么被放行/拦下"可追溯。

最后回到第 4 条契约，它是这一节最该被记住的判断：**仅更新模型不等于发现因子**。`update_model` 里调了 `optimizer.step()`、改了 Prompt、更新了策略，任务仍会正常打印"Mining Completed"、退出码为 0，但 `state.population` 为空，Director 没有可保存的研究产物，Tracker 显示零个有效因子。这类"功能做完了却没接进主流程"的失败不抛异常——它比崩溃更难发现，也正是下一章要用 manifest 和阶段账本去治理的对象。

### 15.3 分层架构与配置驱动的扩展机制

FactorMiner 的分层不是按文件夹随便切的，每一层都有明确的"不许跨层"边界。下表按数据流向列出十层：

| 层 | 模块 | 职责 | 关键实现 |
|---|---|---|---|
| 数据 | `core/data_feed/` | Feather 读取、`RealDataClient` 按 `mine_period/test_period` 切片、`panel_validator`、`crypto_streams` 过去式前向对齐、`freshness`、增量更新 | `real_client.py`、`panel_validator.py`、`freshness.py` |
| 表达与挖掘 | `core/miner/` | `FactorExpression` 协议、注册表、算子运行时、Director、四范式基类与实现 | `expressions.py`、`operator_runtime.py`、`director.py`、`paradigms/` |
| 评价 | `core/evaluation/` | `ParallelEvaluator`（8 线程）、fitness hook、`significance`、`holdout_guard`、`code_sandbox` | `evaluator.py`、`significance.py`、`code_sandbox.py` |
| 存储 | `core/storage/` | `FactorMetadata` 与 `factor_db/` 的 `metadata / values / weights / models` 四类产物 | `factor_storage.py` |
| 审查 | `core/inspector/` | 白盒详情、滚动 IC、分位收益、换手率、批量生命周期更新 | `inspector/` |
| 回测 | `core/backtest/` | ml4t 事件驱动、`resolve_signal_weights` 权重贯通、真实 funding | `backtest_engine.py` |
| 实验 | `core/experiment/` | manifest / registry / budget / costs / walk_forward / pipeline 八阶段编排 | `manifest.py` … `pipeline.py` |
| 服务 | `api/` | FastAPI **22 个端点** + WebSocket 进度广播、任务状态与取消 | `main.py`、`task_store.py` |
| 工作台 | `web/` | React SPA：Dashboard / Launchpad / Inspector / Backtest / Data Center | `web/src/pages/` |
| 入口 | `core/cli.py`、`core/commands/` | `mine / download / inspect / backtest / experiment` 五个命令 | `cli.py` |

边界写得很直白（`v4_architecture_design.md:925`）：`core/` 只承担研究执行，`api/` 负责服务与任务可观测性，`web/` 负责研究工作台，`user_workspace/` 是策略、算子与评分的用户扩展面，`factor_db/` 只保存可追溯的研究产物。这条边界的用处是：重启 FastAPI 只丢内存里的 `TaskManager` 任务历史，不影响 `factor_db` 的 metadata 与 values 快照。

扩展机制是"物理隔离 + 动态加载"的 Freqtrade 范式。`user_workspace/` 下四个目录 `custom_miners / custom_operators / custom_fitness / configs` 在启动时被 `DynamicLoader` 扫描，`@MinerRegistry.register`、`@OperatorRegistry.register`、`@EvaluatorRegistry.register_fitness_hook` 三个注册表把实现挂进运行时。关键是**注册即生效**：`OperatorRegistry` 里的内置与用户算子由同一套 AST runtime 消费，GP/RL 按注册时的 `arity` 生成一元或二元节点，`FactorExpressionAST.compute()` 再按节点名分发回注册表，所以新增算子会真正参与候选生成与求值，而不是停在"被发现了"这一步（`v4_architecture_design.md:910-916`）。

启动校验是这套机制的可信度来源。CLI 与 Launchpad 在**读取数据之前**汇总模块导入错误、未知 Miner、缺失的必填数据流、算子名与 arity、以及未知 Fitness Hook，一次性返回聚合错误（`README.md:562-564`、`v4_architecture_design.md:918-923`）。算子 arity 只允许 1 或 2，函数签名必须覆盖声明参数个数；Fitness Hook 必须接收 `factor_values, returns, base_metrics` 三个参数；未知配置一律失败并给出可行动的错误，**绝不静默回退为零因子或默认评分**。`tests/test_cli_smoke.py` 用临时 Feather 数据实跑 MyCustomGP、MyCustomRL、MyCustomLLM、NN 各一轮，验证的是"注册 → 生成 → 求值 → fitness → 落盘"整条链路，而不是"模块能 import"。

Config-Driven 把与流派无关的环境全部抽到 `config.json`，核心段如下（摘自 `v4_architecture_design.md:804-820` 与 `README.md:246-260`）：

```json
{
  "data_feeds": {
    "exchange": "binance",
    "instrument_type": "futures",
    "timeframe": "1d",
    "pairs": ["BTC/USDT:USDT", "SUI/USDT:USDT"],
    "mine_period": [["2023-04-01", "2024-12-31"]],
    "test_period": [["2025-01-01", "2025-06-30"]],
    "mining_mode": "sequential_single",
    "required_streams": ["close", "volume"]

  "search_space": {"allowed_operators": ["add", "custom_ts_decay", "rolling_zscore"]},

  "evaluation": {"max_workers": 8, "timeout_seconds": 120},
  "data_quality": {"strict": true, "min_coverage": 0.90},
```

判断是：配置驱动的价值不在"少写代码"，而在于把研究意图变成一份可哈希、可 diff、可归档的输入——这恰好是下一章 `config_hash` 能够成立的前提。若关键参数散落在各个 Miner 类的字面量里，可复现身份就无从谈起。

### 15.4 工程契约：让研究结果不随进程重启而蒸发

架构层再漂亮，若"结果"定义在进程内存里，平台就只是脚本集合。FactorMiner 用一组硬契约把研究结果锚定到磁盘。

**Phase II 快照是唯一数据来源**。每个入库因子在 `factor_db/values/<factor_id>.parquet` 保存与评估切片对齐的因子值和未来收益，标准 schema 为 `timestamp, asset（截面模式）, factor, forward_return`；`FactorMetadata.data_lineage` 同时记录数据源、交易对、市场类型、周期、输入流、样本范围、规范化 `target` 与精确收益公式（`v4_architecture_design.md:1053`、`README.md:574`）。Inspector 的 API **只从该 parquet 生成**滚动 IC、分位平均未来收益与换手率；没有快照就明确返回"请重新挖掘"，**严禁以模拟曲线、补造数据或前端演示图占位**（`README.md:124`）。这条契约把"图表好看"和"证据真实"彻底分开。

**指标唯一契约**。落库指标只认 `metrics.IC`、`metrics.RankIC`、`metrics.Turnover`、`metrics.fitness_score` 四个稳定键名；CLI、Launchpad、Dashboard、Inspector 一律直接消费这些原始字段，**不使用小写别名**，更不能把缺失值误呈现为零（`README.md:128`、`v4_architecture_design.md:923`）。`0` 可以是某个候选的真实评分，但一批新因子若全部为零，先检查后端是否已重启到最新 Python 代码，而不是去前端找图表问题。多套口径是分布式系统里最隐蔽的 bug 来源：同一指标在三个页面显示三个数，研究员会以为因子衰减了。

**生命周期状态机**。`DISCOVERED → INSPECTED → PAPER_TRADING → LIVE → RETIRED` 由 `PATCH /api/factors/{id}/lifecycle` 显式持久化（`v4_architecture_design.md:189,1049`），不依赖任务内存；全库重审时 6 个旧 `INSPECTED` 被降级为 `DISCOVERED_UNVERIFIED`，说明状态是可被证据推翻的，不是一次性印章。

**服务与部署的单点约束**。API 跑 uvicorn **单 worker**：任务状态与 WebSocket 广播都在进程内存里，多 worker 会各自回答一份任务列表（`README.md:309`）。Docker 用多阶段 `Dockerfile`（`frontend` → `api` / `web` 两个 target），把 `data/`、`factor_db/`、`user_workspace/`、`logs/` **四个状态目录** bind mount 到宿主，重建镜像不丢研究产物（`:311`）。CI 在 `.github/workflows/ci.yml` 上用 Python 3.12 跑全量 `pytest`、Node 20 跑 `npm ci && npm run build`（`tsc -b` 先行，类型错误直接让 job 失败），`requirements.txt` 把 `ml4t-backtest` 指向固定提交的公开仓库，保证 CI 与本地使用同一份回测引擎（`:316`）。

**三语界面的边界**。前端支持 `zh / en / de`，初始语言跟随浏览器并写入 `localStorage`，词典集中在 `web/src/i18n.tsx`。语言层只负责操作性 UI 文案；因子 ID、逻辑哈希、交易对、AST/表达式、代码、模型版本、权重文件，以及 `IC / RankIC` 等研究指标缩写一律作为**不可翻译的原始工件**保留，后端也绝不向 API 注入某一种自然语言的业务文案（`v4_architecture_design.md:1061-1065`）。这条边界看着只是 i18n 细节，实质是"可复制性与可追溯性优先于本地化"的取舍。

### 15.5 竞品架构对照：工程成熟度不等于方法论成熟度

把五个系统放在同一张表上，工程与方法论两列分开看，结论会相当反直觉。

| 系统 | 定位 | 工程成熟度 | 方法论 / 结果成熟度 | 关键证据 | 对 FactorMiner 的判断 |
|---|---|---|---|---|---|
| qlib | 算子 / 数据 / 执行的事实标准 | 9/10，工程与生态第一 | **本体不含自动因子挖掘器**：`gplearn\|genetic programming\|factor mining\|symbolic regression\|deap\|alphagen` 全目录零命中；README 把自动挖掘明确外包给 RD-Agent，未找到代码级集成 hook | `industry_factor_mining_survey.md:115,178`、`framework_maturity_crypto_fit.md:55,225` | 数据/执行层的成熟不能换算成挖掘能力；分层是合理分工，别照着它补"平台功能"来追产出 |
| RD-Agent（微软） | LLM 结构化闭环挖掘器 | 顶级：v1.0.0、839 文件、166 测试、CI/Docker、53 篇文档 | **M4 = 0**：无任何多重检验校正；`prompts.yaml:187-190` 鼓励"任何微小改进都替换最佳结果"，工程越成熟越能高效地把验证集用穿 | `framework_maturity_crypto_fit.md:148,227,259`、`industry_factor_mining_survey.md:896` | 反例最尖锐：CI 与测试数无法替代统计证伪，反而会放大过拟合 |
| AlphaMaster | L5 产品化层最完整 | Web 控制台 **39 端点**、断点续训（每 20 步原子写 ckpt，存模型+优化器+两个池+best_snapshot+history，词表版本戳校验）、训练包导入导出、6 类数据源（MT5 / TradingView / OKX / A股 / 通达信 / 国内期货）、`drop_forming=True` 全源强制只用已收盘 K 线 | 因证伪为零退化成 91.8% 做多的 beta；另有安全隐患：明文硬编码数据源账号口令、解压 zip 未做 zip-slip 校验、`torch.load(weights_only=False)`、traceback 回传客户端、CORS 全开 | `alphamaster_competitor_review.md:204-209,217,269` | 两个可直接搬的契约（`drop_forming`、三端共用信号函数）；照搬训练包导入时必须连安全项一起修 |
| trade-learn | 下游验证 / 回测组件 | Rust 事件驱动快回测、内置 JupyterLab + MLflow | `CausalSelector`（PC / FCI）剥离伪相关，但文档明确"候选关系，不证明因果效应、收益或样本外有效性"；仍处 0.3.x、68 处 `NotImplementedError` | `industry_factor_mining_survey.md:648-651`、`framework_maturity_crypto_fit.md:289` | 值得作为组件接入（快回测 / 因果筛选 / 实验追踪），但它不是挖掘器，补不了 R 这一维 |
| FactorMiner | 四范式统一闭环 + 统计闸门 + 端到端流水线 | A 能力覆盖 8 / D 纪律可信 8 / O 运营可复现 6；22 端点 + WebSocket、CI/Docker、431 passed / 1 skipped / 56 subtests | **R 结果产出 = 1**：全库 84/84 为 `DISCOVERED_UNVERIFIED`，唯一严格 OOS 含成本 -6.40%，0 promoted | `platform_maturity_gap.md:40-51`、`TODO.md:3` | 工程纪律领先不等于闭环已证明能赚钱；R 是乘数，A/D 再高也只等于"很严谨、暂时没挖到东西" |

判断必须说透：**工程成熟度 ≠ 方法论成熟度 ≠ 结果产出**。qlib 是最成熟的平台却没有挖掘器，RD-Agent 工程生态顶级但 `M4 = 0`，AlphaMaster 产品化最完整却退化成 beta——三者从不同方向证明同一件事：CI、端点数、测试数、断点续训这些指标，衡量的是"系统能不能被别人稳定地复用"，而不是"结论在样本外站不站得住"。`platform_maturity_gap.md:51` 把四项评分写成"R 是乘数"是有分量的：R = 1 时，A/D 再高也只是一套很严谨、暂时还没挖到东西的研究工具。这也解释了本项目的路线图排序——先接线、再让验证可持续、再补数据面、等新数据拿正向证据，**最后**才谈实盘、分布式与多用户；在 R 破之前堆工程规模是负 ROI。

### 15.6 工程陷阱

1. **功能做完但没接进主流程**，这是成本最低、最该先补的一类。`platform_maturity_gap.md:57-61` 记了三例：随机公式零分布 / 目标置换 / 经验 p 三个函数定义在 `significance.py:147,169,208`，全仓非测试引用为 0，前序报告却把它算作领先项；一次性 holdout 账本在 CLI 与 `director.run()` 已接，但 `api/` 下零命中，Web 用户看不到哪些窗口已烧，守卫还不是产品能力；`.fdr_ledger*.jsonl` 与 `.experiment_trace.jsonl` 被 `.gitignore` 忽略，换台机器 clone 后 `num_trials` 归零，DSR 分母被系统性低估。**有实现 ≠ 闸门已启用 ≠ 换机器仍成立**，三者要分别验证。
2. **Web 层模拟图表**。一旦 Dashboard 或 Inspector 为了视觉效果生成虚构曲线，整个证据链就断了：研究员分不清哪条线来自 `factor_db/values/*.parquet`、哪条来自前端占位。契约必须写死——没有快照就返回明确的重新挖掘提示，绝不以模拟结果替代。
3. **指标多套口径**。同一评估链路若同时存在 `IC` 与 `ic`、`fitness_score` 与 `fitness` 两套键名，前端读小写别名时把缺失值呈现为 `0`，一批真实评分为正的因子会集体"变成零"。唯一契约不是命名洁癖，是防止跨层数据被静默改写。
4. **单 worker 扩成多 worker，会各答一份任务列表**。任务状态与 WebSocket 广播在进程内存里，多进程之间没有共享；直接加 worker 数不会提升吞吐，只会让 `/api/dashboard` 在不同请求间给出互相矛盾的任务视图。要扩先外置状态，而不是改启动参数。
5. **只更新模型、不写 `state.population / replay_buffer`**。`update_model` 里反向传播、Prompt 更新、策略更新都做了，任务正常完成、退出码 0，Director 却读不到任何可保存产物。这类失败不抛异常，只能靠 `tests/test_cli_smoke.py` 那样"实跑一轮并断言至少一个因子元数据落盘"的端到端用例挡住。
6. **训练张量误当因子落盘**。NN 的 `channel = -1` 完整输出是为保留计算图而存在的临时产物，不是可查看或可交易的单因子；必须物化成带 `model_version / channel` 的 `FactorExpressionTensor` 并附可恢复模型包，否则 Inspector 与实盘都无法重建。

### 15.7 本章小结

1. 四种范式能共用一条主循环，靠的是控制反转把调度权收归框架，以及 `FactorExpression` 统一协议把 `O(P × Q)` 的 `isinstance` 分派收敛为 `O(P + Q)` 的适配。
2. 闭环 `Cₜ = G(Mₜ₋₁) → Fₜ = E(Cₜ, D_in) → Mₜ = U(...)` 的终态 `A` 只从 `state.population / replay_buffer` 读取；**仅更新模型不等于发现因子**，这是 README 第 4 条结果契约的数学表达。
3. 两个 fail-closed 边界不可退让：`FactorExpressionCode` 无显式沙盒直接抛错、禁止裸 `exec` 回退；`FactorExpressionTensor` 训练阶段 `compute()` 返回 `None` 以保留计算图，训练张量与可落盘因子必须分开。
4. 分层架构（data_feed / miner / evaluation / storage / inspector / backtest / experiment / api 22 端点 / web 五页面 / CLI 五命令）与三个注册表、启动前聚合校验共同保证"注册即生效、未知即失败"，而不是静默回退。
5. 工程契约把结果锚定在磁盘：Phase II parquet 快照是 Inspector 唯一数据来源、指标只用 `IC / RankIC / Turnover / fitness_score`、生命周期显式持久化、API 单 worker、四个状态目录 bind mount、CI 双 job、三语界面但研究工件保持原文。
6. 竞品对照给出最重要的判断：**工程成熟度 ≠ 方法论成熟度 ≠ 结果产出**。qlib 无挖掘器、RD-Agent 的 M4 = 0、AlphaMaster 退化成 beta、FactorMiner 的 R = 1，都在说明"能稳定复用"与"样本外有效"是两件事；在 R 破之前堆工程规模是负 ROI。
