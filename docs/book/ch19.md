## 第 19 章 反面模式清单：十八条源码级教训

> 本章回答：把 21 个框架和 FactorMiner 自己踩过的坑摊开，有哪些反复出现的失败模式？本章不是「最佳实践」的空泛罗列，而是把每条教训绑定到具体的 `路径:行号`、具体数字与具体后果，并给出可执行的检查动作。这些模式的共同特征是：**它们都不会让程序报错，只会让结论悄悄变好。**

### 18.1 一条贯穿全书的病因链

先把散落在各章的反面模式串成因果，这是理解其余各条的骨架（`alphamaster_competitor_review.md` §2.4.2）：

```
9000 步 × 192 公式/步 = 理论上界 172.8 万次候选，无 num_trials 记录
        ↓
每个候选在【同一批 val 折】打分，val 与 train 只隔 20 bar、无 purge/embargo
        ↓
每步 val_score 刷新冠军 → 写盘 → 更新精英回放采样权重
        ↓
无 BH-FDR / 无 DSR / 无随机零分布 / 无一次性 holdout（全仓精确检索零命中）
        ↓
搜索直接优化 0.60~0.75 权重的【回测年化收益】
        ↓
max(170 万个噪声) 被当成 alpha
        ↓
index 组退化成 91.8% 做多的 beta；metals 年化 +117.7% 虚高；
组合 +35.52% 靠 1.37 年短数据放大
        ↓
作者自己在 STATUS_20250705.md 标注「❌ 不建议单独使用」「不是 alpha 而是 beta」
        ↓
但给用户的 AI 分析器 prompt 写着「不要轻易下『过拟合』结论」  ← 最后一环最危险
```

FactorMiner 早期 `OOS −11.18% / Sharpe −1.14 / 6 因子全部不通过` 是**同一个失败模式**：搜索强度足够、证伪机制为零。差别只是它做了严格 OOS 并当场发现，AlphaMaster 是事后在状态档案里诊断。**一个能诚实证伪自己的系统，比多 20 个算子更有价值。**

### 18.2 数据与时间类

**模式 1 · README 声称的流水线在源码里不存在**

`AlphaForge-Crypto/src/factor_pipeline/__init__.py:9` import 一个不存在的 `pipeline.py`，`run_backtest.py:32-41` 全是 TODO，`register_factor` 全仓无定义；`Alpha-Research-Discovery/alpha_01:69-84` 从 `data_fetcher` import 一堆未定义符号、`framework/` 目录不存在。
→ **检查动作**：以源码为准，不用 README 选型；先跑通主入口的最小示例再读文档。

**模式 2 · 参数定义了但从未使用**

`AlphaForge-Crypto/backtest.py:107` 的 `exec_prices` 定义后未用，`leverage / maintenance_margin / position_fraction` 只出现在 dataclass 里。回测看起来「支持杠杆与保证金」，实际不生效。
→ **检查动作**：对每个配置项做一次「改值 → 结果是否变化」的敏感性断言。

**模式 3 · 样本内选因子 + 样本内回测**

`alpha-factor-mining-crypto/pipeline.py:225-230,301` 选因子与回测用同一份 `market_df`；`CosmosAlpha` 四个配置的 `start_date=2010-04-01, end_date=2019-05-31` 完全一致，因子在同一窗口内评估/选择/扩散。
→ **检查动作**：把「用于选择的数据」与「用于汇报的数据」在代码里做成两个不同对象，禁止同名。

**模式 4 · 未来函数进入特征或对齐**

典型形态：`shift(-n)` 用在特征侧、`center=True` 滚动窗口、全样本 `fit_transform`、bfill 把未来值传到过去、resample 后未完成高周期 bar 提前可用、merge 未用 as-of 语义。FactorMiner 的加密流用 `reindex(method="ffill")` **绝不 backfill**（`crypto_streams.py:522-529`），labels 逐切片构造（`real_client.py:135-224`）。
→ **检查动作**：属性测试「扰动未来 bar 后历史因子值逐位不变」；代码审查逐处追问 `shift(-` 与 `fillna(method=...)`。

**模式 5 · 脏数据静默进入留出集**

31 根重复 K 线曾混进 holdout，当时没有前置校验；另一条 30 MB 无时间轴的 1m 文件因「读不出就跳过」而完全隐形。`panel_validator.py` 与 `freshness.py` 的 `summary.unreadable` 是对应修复。
→ **检查动作**：`data_quality.strict=true` 让 critical 直接拒跑；无法解析的文件必须单独上报，不能静默跳过。

**模式 6 · 年化口径不一致**

`AlphaForge-Crypto/backtest.py:163` 用 `√252`，同仓 `bootstrap.py:17` 用 365；AlphaMaster 的索提诺下行 std 地板在三处有三种实现、`ppy` 一处数据驱动一处写死 6240。FactorMiner 早期全仓 6 处硬编码 252。
→ **检查动作**：年化因子单一来源（`annualisation.py`），并用测试锁定「改变年化不改变任何闸门判定」。注意别把 `lookback=252`（窗口长度）一起改掉。

### 18.3 搜索与评价类

**模式 7 · 验证集每步反复使用、每步写盘**

`AlphaMaster/engine.py:876-912,905,1038-1049` 每步用 `val_score` 刷新冠军、写盘、更新精英回放权重；`config.py:39-40` 的 9000×192 次候选全部落在同一批 val 折上。FactorMiner 自己的 `oos_exponent=0.5` 也是同型问题（但多一层独立 holdout 兜底）。
→ **检查动作**：记录 `val_read_count` 并写进报告（正式 run = 87）；验证段与训练段之间加 gap/embargo，逐折重拟合。

**模式 8 · 统计检验为零却在同一样本反复 sweep / rescue / 反向重测**

`WorldQuant-LLM/run_alpha_miner.py:1132-1133,1347` 筛选完全靠平台返回的 `sharpe≥1.25 & fitness≥1.0`，`Sharpe<-0.8` 自动取反，反复 sweep 无任何校正；`alphaminingv2/agent/config.py:63` 的 `enable_critic` 默认 `False`。
→ **检查动作**：`num_trials` 必须包含取反、重试、参数微调、失败候选。

**模式 9 · 鼓励「任何微小改进都替换最佳结果」**

`RD-Agent/scenarios/qlib/prompts.yaml:187-190` 原文鼓励 "Any small improvement ... set Replace Best Result yes"，且 hypothesis 阶段能看到历史 test 指标。**工程越成熟，越能高效地把验证集用穿。**
→ **检查动作**：prompt 层与报告层同样要接受「信息暴露」审计，不能只看训练代码。

**模式 10 · 直接优化回测年化收益**

AlphaMaster `backtest.py:600-626` 的实际 fitness 是 `0.60·年化收益 + 0.10·Sortino + 0.05·Calmar + …`（FTMO 模式 0.75·年化），而其文件头 `:5-13` 注释写的是「0.35 Sortino + 0.20 Calmar + … − complexity」——**文档与代码不符，复杂度惩罚实际不存在**。
→ **检查动作**：以源码权重为准；搜索目标不要直接对收益曲线做梯度上升，保留「挖因子 → 评价 → 组合 → 回测」的分层。

**模式 11 · 只记幸存者，试验分母归零**

只把短名单计入 `num_trials`，DSR 退化成普通 Sharpe 检验。实测：6 个旧因子在 `n_trials=787` 下被全部拦下，`n_trials=1` 时 5 个能过。FactorMiner Phase 1.6 修的正是 `deflated_sharpe_ratio(..., n_trials=1)` 空转。
→ **检查动作**：账本只增不减，含超时/报错/被去重拦下的候选；跨机器可提交快照。

**模式 12 · 同一指标多套口径**

三种 Turnover（原始因子变化、归一化变化、组合权重换手）、三种年化（252/365/8760）、三处索提诺地板。FactorMiner 因此把指标契约收缩到 `metrics.IC / RankIC / Turnover / fitness_score` 四个原始字段，CLI/Dashboard/Inspector 全部读同一处，不用小写别名。
→ **检查动作**：为每个指标写一句「统计单位 + 量纲 + 谁能用它」，写不出来的指标不要进报告。

**模式 13 · 覆盖率低却给高分**

`fitness_hook_guideline.md` 记的典型症状：「Fitness Score 30+，但真实覆盖率 5% 且 RankIC 为负」。嵌套极值算子让因子只剩几十根有效 K 线，再用少量样本算出夸张相关。
→ **检查动作**：`coverage < 0.20` 施加 `(coverage/0.20)²` 二次惩罚；Inspector 强制显示 Coverage 与 Lag 1–10 衰减。

### 18.4 验证与工程类

**模式 14 · Walk-Forward 有折无重拟合**

`AlphaMaster/engine.py:354` 同一公式在全样本一次性算完，`:367-403` 各折只切片评分；`tests/unit/test_walk_forward_gap.py:45-51` 断言 `train_start` 恒为 0，与 rolling window 实现互相矛盾。
→ **检查动作**：逐折只在 TRAIN 拟合 scaler 与权重，并用 `weights_differ_across_folds` 之类字段自证；单测要测行为不是测索引算术。

**模式 15 · 工具数量 / 文档与代码互相矛盾**

`alphaminingv2` README 写 15/16 个工具、prompt 表 12、dispatch 表 17、注释编到 Tool 16 且编号重复；`AlphaMaster/vm.py:127-130` 注释写「66 算子 / 131 词表」，实际 62 算子 / 127 词表。
→ **检查动作**：文档里的数字用脚本从注册表重新计数，不要手写。

**模式 16 · 测试含恒真空断言**

`AlphaMaster/tests/property/test_runner_props.py:185` 出现 `if False`、`:192-194` 出现 `or True`，属性测试看起来覆盖了关键性质，实际什么都没断言。
→ **检查动作**：属性测试必须能被故意注入的 bug 触发（变异测试思路）；优先覆盖「未来 bar 扰动不改变历史因子」「成本单调性」「账本幂等」三条数学性质。

**模式 17 · 功能做完但没接进主流程**

FactorMiner 三个真实案例：随机零分布三函数只有单测引用、主流程零调用；holdout 账本在 `api/` 零命中，Web 用户看不到已烧窗口；`.fdr_ledger*.jsonl` 与 `.experiment_trace.jsonl` 被 gitignore，clone 后 `num_trials` 归零。AlphaMaster 的 `rigorous_backtest_audit.py`（395 行独立审计器）也是手动 CLI、不被主流程调用。
→ **检查动作**：给每个安全/统计机制写「入口接线断言」，用全仓 Grep 列出所有调用点；能力盘点核对调用点而不是函数定义。

**模式 18 · 零交易 / 零产物却报成功**

`run_backtest` 默认 5 多 / 5 空 / `min_assets=10`，6 币 universe holdout 下每次调仓被拒 → **0 交易、0% 收益却报成功**；同类问题是 Miner 只 `update_model` 不把候选写进 `state.population`，任务「正常完成」但没有任何可保存因子。
→ **检查动作**：`adapt_book_to_universe()` 按实际资产数自适应；用真实价格文件的回归测试锁定「必须真的成交」；Director 对空产物 fail-loud。

### 18.5 报告层：最容易被忽略的一环

以上十八条里，最危险的不是任何一条技术缺陷，而是**统计诚实与对外解说被拆成两套**。

AlphaMaster 的 `strategies/STATUS_20250705.md:23-26,34-37,41-43` 与 `config.py:147-148` 里，作者主动写下「虚高」「不是 alpha 而是 beta」「短数据放大」「不建议单独使用」，并据此加了 beta 中性惩罚、前后一致性奖惩、算子链感染约束——**这是值得学的态度**。但 `web/ai_analyze.py:31,57` 给面向用户的 AI 分析器写的是：

> 「不要轻易下『过拟合』结论，尽量不要提过拟合」
> 「不要因训练分远高于验证分就建议停止」

如果报告层允许选择性呈现，P0 的全部统计闸门都会被话术从下游架空。这促成了项目里的一条纪律：**报告层禁止话术降级，所有显著性结论必须原样出现在用户可见报告里**。

正面案例有两个，都值得反复引用：

- `LLM-Alpha-Mining-Framework` 主动写「No significant search advantage after familywise correction」、最小 raw p=0.026 → Holm 后 0.13、Romano–Wolf 仅保留 24% 因子、并在 Limitations 里承认 holdout 不干净与 LLM 训练数据覆盖回测期；
- FactorMiner 把 `OOS −11.18% / Sharpe −1.14`、`含成本 −6.40%`、`验证段 −4.43%`、`84/84 全库重审 0 通过`、`0 promoted` 全部落盘为报告，并在 `docs/README.md` 明写「**绿色流水线只证明过程可复现、可审计，不等于挖到了赚钱的因子**」。

`optimization_plan.md` 的元建议可以作为本节的收束：把「OOS 全亏」与试验总次数写进一份固定基线报告，作为后续所有实验的分母；**一个能诚实证伪自己的系统，比多 20 个算子更有价值**。

### 18.6 如何做一次源码级审查

把上面的检查动作整理成可复用的流程，适用于评估任何第三方框架或自查：

```text
1. 数：脚本重新计数算子数 / 特征数 / 测试用例数，不信注释与 README
2. 跑：主入口最小示例能否跑通；ImportError / TODO / raise NotImplementedError 全仓检索
3. 追：每个配置项追到实际使用点，做一次改值敏感性断言
4. 切：找出 train / valid / test 的边界对象，检查 purge / embargo / 逐折重拟合
5. 数：找到 num_trials 的写入点，确认含失败者、跨 run 累积、可提交
6. 校：全仓 Grep bonferroni|holm|fdr|deflated|num_trials|embargo|purge|permutation
7. 接：对每个闸门函数列出全部调用点，确认主流程与所有入口（CLI / API / Web）
8. 价：定位成本常量的单一来源，核对 gate 成本与回测成本恒等式
9. 报：读面向用户的报告模板，确认没有抑制性指令、没有选择性呈现
10. 验：故意注入一个已知为真的信号（阳性对照），看闸门能否放行
```

第 10 步是绝大多数审查缺失的一步。前 9 步只能证明「系统能拦住坏因子」，第 10 步才能证明「系统没有连好因子一起拦掉」。FactorMiner 的 `gate_calibration.py` 就是补这一环：虚警率 0.0%，但 `n_trials=182` 下 MDE=0.10 高于现实 IC 0.02–0.05，于是「0 promoted」被重新解释为「功效不足 + 因子弱」而不是单纯的「因子不行」。

### 18.7 工程陷阱（元层面）

1. **把反面模式当成「别人家的 bug」**。本章十八条里，有六条来自 FactorMiner 自己的实施补记；能写进 TODO 的失败，比藏起来的失败值钱。
2. **按现象修而不按病因修**。「OOS 亏钱 → 加算子」「0 promoted → 调低阈值」都会放大搜索预算，让第 12 章的 `√ln K` 继续往上走。
3. **只做阴性审查**。审查看「有没有拦住噪声」，不看「有没有放行真信号」，结论必然偏向「闸门越严越好」。
4. **忽略时间戳**。三份竞品报告都是 2026-11-14 的快照，多处结论被同日实施补记收窄（holdout ledger 覆盖范围、随机零分布是否接线、成本口径是否闭合）。**读报告先读顶部的校准补记**。
5. **把「未找到」读成「绝对不存在」**。所有「未找到」都是全仓精确检索零命中后的如实结论，不等于上游没有；也不等于下一个版本没有。

### 本章小结

1. 十八条反面模式可归为五类：数据与时间（6 条）、搜索与评价（7 条）、验证与工程（5 条）、报告层诚实性、以及审查方法本身。
2. 共同特征是**静默**：不抛异常、不崩溃，只让结论悄悄变好。因此检查动作必须依赖断言、脚本计数与调用点清单，不能靠人工浏览。
3. AlphaMaster 的病因链是完整实证：172.8 万无分母候选 → val 每步复用 → 零统计闸门 → 直接优化回测收益 → 91.8% 做多的 beta；FactorMiner 早期 OOS 全亏是同一失败模式。
4. 最该抄的不是某个算子，而是两条纪律：**「以源码为准，不以 README 为准」** 与 **「报告层禁止话术降级」**。
5. 「功能做完但没接进主流程」是成本最低、最该先补的一类差距；用入口接线断言防新增路径漏接。
6. 正面案例的共同点是把失败写进报告：Holm 后 p=0.13、Romano–Wolf 保留 24%、含成本 −6.40%、84/84 0 通过、0 promoted。
7. 十步源码级审查里最常被跳过的是最后一步**阳性对照**；前九步只能证明「能拦坏因子」，第十步才证明「没连好因子一起拦掉」。
8. 按病因修，不按现象修。在 R=1 时提升搜索效率，只是把「重复采样」放大成「更高效的重复采样」。
