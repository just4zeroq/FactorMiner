## 第 13 章 统计闸门：从「打分」到「判定」

> 本章回答：一个候选因子拿到 `RankIC = 0.045`、`fitness = 5.04` 之后，凭什么可以被标成 `INSPECTED`？本章把 FactorMiner 的晋升判定拆成五层——稳健 t 统计量、族错误率校正、经验零分布、Deflated Sharpe Ratio、以及八道 promotion gates——逐层给出公式、默认阈值、源码位置与失败案例。这是全书技术密度最高的一章，也是把「研究工具」和「可证伪系统」分开的那一层。

### 12.1 闸门总览：描述量、判定量与状态

先把三类数字分开，这个区分贯穿全书：

| 类别 | 例子 | 用途 | 能不能单独下结论 |
| --- | --- | --- | --- |
| **描述量** | IC、RankIC、Turnover、Coverage、分位收益 | 描述因子长什么样 | ❌ |
| **排序量** | `fitness_score` | 驱动搜索 | ❌ |
| **判定量** | `hac_t`、`p_adj`、`dsr`、`empirical_p`、`gate_pass` | 决定能不能晋升 | ✅（但仍只是第 4 级结论） |

判定链路在 `core/miner/director.py:161-225` 的 `_save_excellent_factors()` 里闭合：

```
ParallelEvaluator.evaluate(候选)
   → hac_t / p_value / dsr / ls_* / cost_adj_return 写入 metrics
   → 汇总 family_p_values（历史 FdrLedger + 本轮全部原始 p）
   → 汇总 n_trials（ExperimentTrace + Budget + 本轮 total_evaluated）
   → 生成 null_tstats（60 个随机目标置换零样本）
   → apply_promotion_gates(...)
   → lifecycle_status = "INSPECTED" | "DISCOVERED_UNVERIFIED"
   → metrics.gate_checks / gate_pass / empirical_p 写回因子档案
```

注意状态只有两个值，没有「大概可信」这一档。全库重审 84 个存量因子得到 **0 通过**，6 个旧 `INSPECTED` 全部降级为 `DISCOVERED_UNVERIFIED`（备份在 `factor_db/metadata_pre_reaudit/`）。分母敏感性也做了：84 / 20 / 6 三种分母均 0 通过，`n_trials=1`（关掉多重检验）也仅 1/84 通过——**主因是成本后为负**，不是闸门设得任性。

### 12.2 第一层：Newey–West HAC t 统计量

`IC_t` 序列不独立，所以不能用 `t = mean/(std/√T)`。`core/evaluation/significance.py:79-102` 的实现：

```
ic_t      = spearman_row(f_t, r_{t+1})        逐期截面秩相关，len<3 返回 0
L         = floor( 4 · (T/100)^(2/9) )       NW (1994) 启发式滞后阶
γ_l       = 样本滞后 l 的自协方差
s         = γ_0 + 2 · Σ_{l=1..L} ( 1 − l/(L+1) ) · γ_l      Bartlett 核
var_mean  = s / T
t_HAC     = mean(ic_t) / √var_mean
```

`T < 4` 时返回 0。`(1 − l/(L+1))` 是 Bartlett 权重，保证 `s` 的估计非负；`L` 随 `T` 缓慢增长（`T=610` 时约 `floor(4·6.1^0.222) ≈ 5`）。`pvalue_from_t()`（`:340-347`）用 `math.erf` 实现 `p = 2·(1 − Φ(|t|))`，不依赖 scipy。

`core/evaluation/portfolio_eval.py:290-307` 的 `ls_t_stat()` 对**净收益序列**做同一件事，`lags = max(5, rebalance_bars)`。两者的差别是：`tstat_ic` 检验「排序有没有信息」，`ls_t` 检验「钱有没有赚到」，后者才与 DSR 的成本口径一致。

为什么必须两层都算？因为项目里真实出现过「OOS IC 同向显著（`|t|` 4.17–5.45）但含成本 −6.40%」的情况。IC 层面的 HAC t 回答不了经济价值问题。

### 12.3 第二层：BH-FDR 与 Holm

**Benjamini–Hochberg FDR**（`significance.py:114-126`）：把 `n` 个 p 值升序排列 `p_(1) ≤ … ≤ p_(n)`，

```
adj_(i) = min_{ j ≥ i } ( n · p_(j) / j )      从后往前累积最小值保证单调
reject  : p_adj ≤ q                             q = fdr_max = 0.05
```

代码里是 `adj = ranked * n / arange(1, n+1)`，再 `np.minimum.accumulate(adj[::-1])[::-1]`。**Holm**（`:129-141`）：`adj = ranked * (n − arange(n))` 再 `np.maximum.accumulate`，控制的是 FWER，比 BH 更严。

关键设计是**累积族**：`apply_promotion_gates()`（`:353-451`）在传入 `family_p_values` 时，对**历史 + 本轮全部假设**一起排序做 BH，再用 `np.searchsorted` 为每个候选取回自己的 `p_adj`；只有不传时才退化为本批 BH。这修掉了早期「BH 只在本轮保存的候选内校正」的缺口。

一个可复算的冒烟校验：10 个假设时，最小原始 p `0.000532` → `p_adj = 0.005321`，正好 ×10。`FdrLedger` 存 `.fdr_ledger.jsonl`，按 `run_id` 幂等；`budget_report()` 输出累计假设数 / 运行轮数 / 预算使用率 / 当前 DSR 门槛，使用率 ≥ 80% 时 Director 告警（`:254-262`）。

真实跑 2 代后的打印是：**99 tests → 基准 0.159 每期 SR（旧 252 口径年化 2.52，7×24 口径 3.03）**。这个数字应该出现在每一次实验报告里，因为它告诉研究者「你这次搜索把标尺抬到了多高」。

### 12.4 第三层：随机零分布与经验 p 值

参数检验依赖分布假设，而因子收益厚尾、截面相关、搜索过程又是自适应的，所以补一层**经验零分布**：

```python
# ① 目标置换：把 returns 的时间轴打乱，破坏与因子的对应关系
def target_permutation_tstats(factor, returns, n_perm=100, seed=0):
    for _ in range(n_perm):
        perm = rng.permutation(T)
        yield abs(newey_west_tstat(ic_series(factor, returns[perm])))

# ② 随机公式零分布：从合法语法池采随机表达式，取 max|t|（搜索运气基线）
def random_formula_null(...):  ...

# ③ 经验 p
def empirical_p(null_tstats, observed):
    return mean(null >= observed)      # 空分布返回 1.0
```

`significance.py:147-213` 三个函数齐备。第 ② 种尤其重要：它模拟的不是「一个随机因子有多显著」，而是「**搜了一堆随机因子后，最显著的那个有多显著**」——正好对应第 12 章的 `max of noise`。`LLM-Framework` 用 `random_max_critical` 的随机语法池做同一件事，`crypto-factor-lab` 用 `random_rank_ic_benchmark(trials=100)` 取 `absolute_rank_ic_95` 作为最终留出确认的比较基准。

FactorMiner 通过 `director._build_null_tstats()` 生成 **60 个零样本**，传给 `apply_promotion_gates(..., null_tstats=)`，得出 `empirical_p` 并受 `empirical_p_max` 闸门约束。正式端到端 run 里 **4/4 候选都算出了 `empirical_p`，其中 3 个被 `empirical_null_pass` 拦下**——这是这层闸门真实生效的证据。

**「有实现 ≠ 已接线」的案例**值得再强调一次：这三个函数一度只被 `tests/test_significance.py:10-12,80-102` 引用，主流程零调用，前序竞品报告因此把 FactorMiner 的这项能力高估了。校准后的正确表述是「已实现为库函数并有单测覆盖，但未接入 `apply_promotion_gates`」。**任何能力矩阵都应核对主流程调用点，而不是函数定义。**

### 12.5 第四层：Deflated Sharpe Ratio

DSR（Bailey & López de Prado, 2014, *Journal of Portfolio Management* 40(5), 94–107）把「试了 K 次」直接折进 Sharpe 的显著性判定。FactorMiner 的实现（`significance.py:219-295`）：

```
σ_SR          = 1 / √(n_obs − 1)                          每期 SR 估计量的抽样离散度
sr_benchmark  = sr_0 + σ_SR · √( 2 · ln(n_trials) )       E[max SR]，sr_0 = 0
denom         = √( max(1e−9, 1 − skew·sr + (kurt−1)/4 · sr² ) )
z             = ( sr − sr_benchmark ) · √(n_obs − 1) / denom
DSR           = 0.5 · ( 1 + erf( z / √2 ) )
```

默认 `skew = 0, kurt = 3`（正态），此时 `denom = √(1 + 0.5·sr²)`，即 Lo (2002) 的非正态方差修正。`multiple_testing_bar()`（`:232-264`）把门槛单独暴露出来：`bar_per_period_sharpe = σ_SR·√(2 ln n)`，`bar_annualised_sharpe = bar·√A`（后者**仅报告用**）。

**折减对象必须记准**：`sr = cost_adj_return / std_return`，是**已交易分位多空组合的每期净 Sharpe**，不是 IC-IR，也不是年化 Sharpe。项目 P1 做过一次关键改造——原先 DSR 折减 IC-IR，但 IC-IR 无量纲，会奖励「稳定但很小」的因子；改成策略净 Sharpe 后，门槛随真实边际增大，也随成本增大而变硬。这是一个把统计判定锚定到经济口径的正确方向。

对照基准是「搜索了 `n_trials` 个随机策略后期望能碰到的最大 SR」，按抽样离散度 `1/√(n_obs−1)` 缩放。因此：

- `n_trials ↑` → `sr_benchmark ↑` → DSR ↓；
- `n_obs ↑` → `σ_SR ↓` → `sr_benchmark ↓` → DSR ↑（**更长的数据是最有效的解药**）；
- 成本吃掉 `cost_adj_return` → `sr ↓` → DSR ↓。

一个来自 `gate_calibration` 的实测序列（`user_workspace/reports/gate_calibration.md`）：DSR 每期门槛在 `n_trials = 1 / 20 / 100 / 182 / 787` 下分别为 `0.0000 / 0.0968 / 0.1200 / 0.1275 / 0.1444`；MDE（80% 检出率所需的最小真实 IC）相应为 `0.06 / 0.10 / 0.10 / 0.10 / 0.15`。

### 12.6 第五层：八道 promotion gates

`DEFAULT_GATE_CFG`（`significance.py:301-332`）与 `promotion_gates()`（`:454-516`）：

| 闸门 | 默认阈值 | 判定 | 作用 |
| --- | --- | --- | --- |
| `hac_t_significant` | `hac_t_min = 2.0` | `|hac_t| > 2.0` | 稳健显著性 |
| `fdr_pass` | `fdr_max = 0.05` | `p_adj ≤ 0.05` | 累积多重检验 |
| `dsr_pass` | `dsr_min = 0.90` | `dsr ≥ 0.90` | 搜索偏差折减 |
| `oos_consistent` | `require_oos_consistent = True` | 样本内外符号一致 | 防方向翻转 |
| `cost_adj_positive` | `cost_adj_return_min = 0.0` | `> 0` | 成本后为正 |
| `ls_significant` | `ls_t_min = 0.0` | `ls_t ≥ 0` | 默认静默（等价于只要求非负） |
| `oos_strength` | `oos_rankic_min = 0.02` | `|RankIC_oos| ≥ 0.02` | **仅在配置 `test_period` 时激活** |
| `empirical_null_pass` | `empirical_p_max = None` | 传入才判 | 经验零分布 |

`g["pass"] = all(g.values())`，全绿才 `INSPECTED`。

`oos_strength` 是 Phase 1.5 补上的关键一环，值得单独讲：原闸门只检查 OOS **方向**一致性、不检查 OOS **幅度**，这正是 6 个因子当初「样本内漂亮、OOS 崩塌却仍被 INSPECTED」的根因。补上 `|RankIC_oos| ≥ 0.02` 后，方向没翻但衰减到 0.005 的因子也会被拦下。它只在配置 `test_period` 时激活，是为了向后兼容且**不静默地改变无验证段配置下的判定**。

`empirical_p_max` 默认 `None`（关闭），在端到端流水线里由 `gate_calibration` 明确设为 0.05。这体现了一个原则：**闸门默认值要保守，但任何被启用的额外闸门都必须在配置里显式出现**，不能靠代码隐式打开。

两家最严谨的框架各自留下了值得学的诚实记录：

- **LLM-Framework**：最小 raw p `0.026` → Holm 后 `0.13`；Romano–Wolf 仅保留 **24%** 的 LLM 因子；README 主动写「No significant search advantage after familywise correction」，并在 Limitations 里承认 holdout 不干净、LLM 训练数据覆盖 2018–2025、信号弱（IC 0.0005–0.0101）、无成本调整组合。
- **FactorMiner**：84/84 重审 0 通过、P0 OOS 含成本 −6.40%、P0.5 新收益口径复判 4 因子 0/4 通过、全库旧 `INSPECTED` 全部降级。

这两条记录的共同点是：**把「闸门没有放行任何东西」也当成有效的研究结果写进报告**。相比之下，AlphaMaster 的产品话术层要求「尽量不要提过拟合」，是同一光谱的另一端。

### 12.8 实现细节：一次判定到底读了哪些数

```python
# core/miner/director.py:_save_excellent_factors 的骨架（简化）
run_trials   = evaluator.total_evaluated                 # 含未入 shortlist 的
base_trials, family, snapshot = budget.resolve(
    trace.num_trials, fdr_ledger.cumulative(), evaluator.run_p_values)
n_trials     = base_trials + run_trials
val_read_count = run_trials
null_tstats  = _build_null_tstats(n=60)                  # 随机目标置换

for cand in shortlist:
    v = apply_promotion_gates(
            metrics      = cand.metrics,               # hac_t / p / sr / ls_* / RankIC_oos
            cfg          = gate_cfg,
            family_p_values = family,                  # 累积族
            n_trials     = n_trials,
            null_tstats  = null_tstats)
    cand.metrics.update({"empirical_p": v.empirical_p,
                         "gate_pass":   v.gate_pass,
                         "gate_checks": v.checks,
                         "dsr": v.dsr, "n_trials": n_trials})
    status = "INSPECTED" if v.gate_pass else "DISCOVERED_UNVERIFIED"
```

四个容易出事的接线点，项目都踩过并修了：

1. **`n_trials=1` 空转**：`_build_verdict` 里写死 1，DSR 退化成普通 Sharpe 检验 → 累计 `total_evaluated` 后重算并写回 `dsr/n_trials`。
2. **DSR 基准量纲错误**：`expected_max_sr` 未按 `1/√n_obs` 缩放，门槛量纲与每期 Sharpe 不匹配 → 在 `deflated_sharpe_ratio` 里把 `sigma` 固定为 `1/√(n_obs−1)`。
3. **负 IC 被符号误杀**：带符号 IC 直接算 DSR / 成本，负 IC 因子一律判死 → 先按样本内符号定向，记录 `orientation`，再算 IR 与成本。
4. **阈值没传进闸门 + CLI 无 `--iterations` 时 `None` 崩溃**：`evaluation.gates` 的配置未透传 → 修配置解析并补 CLI 默认值。

这四个 bug 的共同特征是：**它们都不会让程序报错，只会让判定悄悄偏向某个方向**。统计闸门的可怕之处不在于复杂，而在于它的错误是静默的。

### 12.9 工程陷阱

1. **把「闸门全绿」当成「因子有效」**。全绿只到第 4 级结论，离「含成本为正」还差一层，离实盘证据差两层。
2. **闸门越堆越多却不做阳性对照**。第 14 章会证明：在 `n_trials=182` 下 MDE=0.10，高于加密日频现实 IC 0.02–0.05，主要瓶颈就是 `dsr_pass`（169 次失败）。**「0 promoted」至少有一部分是功效不足**，不能全归因于因子不行。
3. **BH 只用本批 p 值**。必须累积历史全部假设，否则跨 run 搜索可以靠「分批跑」绕过校正。
4. **把年化值喂进 DSR**。`sr` 是每期净 Sharpe；`bar_annualised_sharpe` 只是展示字段。`tests/test_annualisation.py` 锁定 HAC t / p / DSR / gates 在 252↔365↔8760 下逐位相同。
5. **IC-IR 与策略 Sharpe 混用**。IC-IR 无量纲，会奖励稳定的小信号；DSR 应折减真实交易口径的净 Sharpe。
6. **零分布函数写好却忘了接主流程**。用「入口接线断言」类的测试防止以后新增 CLI / API 漏接（`tests/test_holdout_guard.py` 就含这类断言）。
7. **负号 / 方向处理不一致**。定向必须发生在 IR、成本、DSR 之前，且 `orientation` 要落库可审计。

### 本章小结

1. 描述量、排序量、判定量是三类不同的数字；只有 `gate_pass` 决定生命周期状态，且状态没有「大概可信」这一档。
2. 五层判定依次是：NW-HAC t（Bartlett 核，`L = floor(4(T/100)^(2/9))`）、累积 BH-FDR / Holm、经验零分布（60 个置换零样本）、折减**每期净策略 Sharpe** 的 DSR、八道 promotion gates。
3. DSR 的对照基准是 `σ_SR·√(2 ln n_trials)`，`σ_SR = 1/√(n_obs−1)`；试验次数越多、样本越短、成本越重，门槛越硬。
4. `oos_strength`（`|RankIC_oos| ≥ 0.02`）补上了「只看方向不看幅度」的缺口；`empirical_p_max` 默认关闭，启用必须显式出现在配置里。
5. 只有 `LLM-Framework` 与 `crypto-factor-lab` 两家在源码层接近完整闸门谱系；FactorMiner 的差异化在于**把 DSR 锚定到成本后的策略净 Sharpe**，并把三账本做成跨机器一致。
6. 闸门最常见的错误是静默的：`n_trials=1`、量纲不匹配、负号误杀、阈值未透传，都不会抛异常，只会悄悄改变结论。
7. 行业最值得学的不是闸门数量，而是把「0 通过」「Holm 后 p=0.13」「OOS 含成本 −6.40%」原样写进报告的诚实度。
