## 第 18 章 20+ 框架源码级横向全景

> 本章回答：业界到底做到哪一步？本章把 `docs/research/` 下三份源码实读报告（18+ 仓库调研、AlphaMaster 增量、21 框架双维度评估）压缩成一张可查的全景：L0–L5 分层、三档成熟度归类、算子 / 算法 / 闸门三张横向矩阵、成熟度 × 加密适配度象限，以及一份「什么该抄、什么别抄」的清单。所有判断以源码为准，README 与实现不符处显式标注。

### 17.1 分层全景：L0 到 L5

框架在因子研究流水线里的位置不是互斥分类，同一框架可跨层（例如 `crypto-factor-lab` 同时属 L1 / L3 / L4）。

| 层 | 职责 | 代表框架 |
| --- | --- | --- |
| **L0 数据 / 表达式执行 / 评价** | 算子、编译执行、PIT 对齐、单因子体检 | qlib、KunQuant-rs、alphalens、trade-learn |
| **L1 公式化挖掘器** | GP / RL / GAN 产生候选公式 | gplearn、gpquant、AlphaGen、AlphaForge、AlphaMaster |
| **L2 LLM / Agent 挖掘** | 假设→代码→反思、多智能体 | RD-Agent、EvoAlpha、CosmosAlpha、LLM-Alpha-Mining-Framework、WorldQuant-LLM、alphaminingv2 |
| **L3 加密货币 / 多品种** | 永续数据、funding、横截面因子 | crypto-factor-lab、alpha-factor-mining-crypto、AlphaForge-Crypto、Alpha-Research-Discovery |
| **L4 评价 / 统计闸门** | 多重检验、留出纪律、证伪 | crypto-factor-lab ★★★、LLM-Framework ★★★、FactorMiner、AlphaForge-Crypto ★ |
| **L5 产品化 / 交易终端** | Web 控制台、数据源、信号、断点续训 | AlphaMaster ★★★、FactorMiner（Web + CI/Docker） |

L5 是 AlphaMaster 增量报告补出来的维度——前 18 个框架基本没有这一层。**关键定位差异**：绝大多数框架是「横截面多因子 → 组合 → IC 评价」；AlphaMaster 是「单品种（或小组）时序 → 单条公式 → `tanh` 连续仓位 → 直接优化回测收益」，没有组合层、没有因子池权重优化，`strategies/best_forex.json` 这类产物只是 8 个 token 的一条公式。

| --- | --- | --- | --- | --- | --- |

| AlphaGen | 28 定义 / **22 启用** | ✅ `DeltaTime` token [1,5,10,20,40] | ⚠️ 唯一 `CSRank`（默认关闭） | ❌ | RPN 栈，长度上限 15 |

| crypto-factor-lab | 21 op | ✅ 7 窗口 (2..96) | ❌ | ❌ | 21-op DSL AST |
| alpha-mining-crypto | 13 核心 + 40 多窗口 + 40 组合 | ✅ | ✅ 全转截面 pct rank | ❌ | 硬编码公式 |

**「算子数量第一 ≠ 表达力第一」**是这张表最重要的读法。AlphaMaster 62 个算子把窗口固化成 `TS_MEAN_5/10/20` 这样的独立 token，生成器只输出 `vocab_size` 个 logits、没有参数头，VM 只按 arity 弹栈；配合 8 token 定长，组合空间反而远小于 FactorMiner 的 30 个连续/离散采样窗口。今后任何算子对比都应同时标注「窗口是否参数化」，否则会被数字误导。

真正拉开表达力差距的是**输入终端**：AlphaMaster 有 65 个预计算特征（GK / Parkinson / Yang-Zhang 波动率、RS_VOL、HURST_50、AMIHUD_ILLIQ、CS_RANK_RET5），FactorMiner 的 `TERMINALS_DEFAULT` 只有 OHLCV 5 个（虽有 60 个 funding/basis/OI 流在盘上，但只有部分接进终端，且 OI 文件各仅 25 行）。**补特征面板比再堆算子更能提升表达力**——这条被列进 P1 清单。

执行效率维度也值得单独一行：qlib 有三层缓存（表达式对象、以 `str(self)` 为 key 的内存结果缓存天然复用公共子式、磁盘 `ExpressionCache`）；KunQuant 把表达式 AOT 编译成 `.so`，`STREAM` 增量、`num_stocks` 必须是 8 的倍数以启用 SIMD；FactorMiner 的 `evaluate_ast`（`operator_runtime.py:594-629`）是**递归解释执行、每候选全量重算、无编译 / 无公共子式复用 / 无 SIMD**。在 20 标的规模下这不是瓶颈，但在候选数上量级后会先撞到这一层。

### 17.4 挖掘算法与目标函数矩阵

| 框架 | 搜索算法 | 优化目标 | 组合层 | 关键机制 |
| --- | --- | --- | --- | --- |
| gplearn | GP（5 种遗传算子、锦标赛 20） | `metric − c·len(program)` | ❌ | half-and-half 初始化、简约系数 auto |
| gpquant | 同构 GP | **回测 Sharpe** | ❌ | `sliding_window_view` 向量化 |
| AlphaGen | MaskablePPO + 动作掩码 | **加入池后的组合 IC 增量** | ✅ `MseAlphaPool` | mutual IC >0.99 拒收、`wᵀMw − 2wᵀc + 1 + α‖w‖₁` |
| AlphaForge | DCGAN + Conv Predictor + Gumbel-Softmax | `−mean(pred) + loss_simi + loss_potential` | ✅ 逐日 lstsq | predictor 代理减少真实 evaluate |
| AlphaMaster | REINFORCE + 自回归 Transformer + 动作掩码 | **0.60–0.75 权重的回测年化收益** | ❌ 单公式 → `tanh` 仓位 | 栈深 `delta=1−arity`、感染链、Top-60 精英堆 |
| RD-Agent | LLM 假设→规格→代码两段式 | validation IC / 平台 Sharpe | ⚠️ `TopkDropoutStrategy` | CoSTEER 单轮最多 10 次自纠错 |
| LLM-Framework | 4 算子进化 + 3 island + 18-niche MAP-Elites | validation IC（不回灌反馈） | ❌ 承认无成本组合 | 文本 gate 拒掉约 90% |
| CosmosAlpha | MCTS(UCT) + Graph Flow | Pareto `(|rank_ic_mean|, −rank_ic_std, top20_return)` | ❌ | 同窗口评估/选择/扩散 |
| crypto-factor-lab | 21-op DSL 确定性枚举 + 受约束 LLM 提议 | `abs(val_rank_ic) − 0.001·complexity` | ✅ greedy forward | 200 候选总预算、只做 1 轮 |
| **FactorMiner** | **GP + RL + LLM + NN 四范式** | 样本内外 RankIC 几何混合 fitness | ✅ 静态 AlphaPool / 岭回归 | 统一 `FactorExpression` 中间体 |

**结构性差异**：FactorMiner 的搜索目标是**单因子 fitness**，组合是事后独立一步；AlphaGen / AlphaForge 的搜索目标直接是**组合增量 / 代理打分**，搜索与组合耦合。这是「挖出一堆 IC 还行但组合起来亏钱」的结构性原因之一。但反过来，AlphaMaster 把「搜索」和「交易」直接焊死（reward 就是回测收益），等于把过拟合的自由度开到最大——**分层是对的，分层之上的证伪闸门才是关键**。

一个必须澄清的常见误读：AlphaMaster 全仓 `/chat/completions` 调用只有 2 处（`web/ai_providers.py:367`、`web/ai_fallback.py:108`），`model_core/` 与训练脚本**没有任何 LLM 调用**。它的 LLM 是「AI 解说员」，不是 L2 挖掘框架；5 层 fallback 链是产品韧性设计，与因子质量无关。

3. FactorMiner 早期回测 funding 是常数网格、与 fitness 成本不同源，后来才有 `costs.py` 恒等式与真实 8h 流。

### 17.6 成熟度 × 加密适配度：双维度评分与象限

`framework_maturity_crypto_fit.md` §1.3 定义两套各 5 项、每项 0/1/2 分的人为分档（**用于相对定位，不是绝对评价**）：

- **成熟度 M**：M1 工程规范（CI/依赖/LICENSE/Docker）、M2 测试与文档、M3 实现完整度、M4 **统计证伪纪律**（FDR/DSR/零分布/num_trials/一次性留出中 ≥3 项才得 2 分）、M5 维护与诚实度；
- **加密适配 C**：C1 数据可得性、C2 加密原生字段、C3 市场时钟与成本（7×24 年化 + 三段成本 + funding + 下一根 bar）、C4 资产池与风险（PIT）、C5 可直接用于加密。

| 框架 | M | C | 象限 / 定位 |
| --- | --- | --- | --- |
| qlib | **9** | 2 | 左上：工程生态第一，股票日频、无挖掘器 |
| **FactorMiner** | **9** | **7** | **右上：证伪 + 数据 + 工程最均衡，正向 OOS 未到手** |
| RD-Agent | 8 | 0 | 左上：挖掘器工程第一，CSI300 硬编码、M4=0 |
| LLM-Framework | 8 | 0 | 左上：统计纪律与诚实度第一，美股 + WRDS 授权 |
| crypto-factor-lab | 8 | **8** | **右上：加密象限唯一另一家双高，但仅 BTC 单品种** |
| gplearn | 7 | 2 | 左上：成熟 GP 范本，市场无关 |
| trade-learn / CosmosAlpha / alphalens | 6 | 1–2 | 左上 |
| AlphaMaster / AlphaGen / AlphaForge | 5 | 2 | 左下偏中 |
| alpha-factor-mining-crypto | 3 | 6 | **右下：能跑、加密原生、零测试零闸门** |
| AlphaForge-Crypto / Alpha-Research-Discovery | 2 | 3 / 1 | 左下：跑不通 |
| EvoAlpha | **0** | **0** | 左下：prompt 包装骨架 |

**三条结构性结论**：

1. **右上（双高）只有 `crypto-factor-lab (8,8)` 与 `FactorMiner (9,7)`**，共同点不是「算法强」，是**把证伪机制写进了主流程**。
2. **「最成熟」与「最适合加密」接近负相关**：M≥8 的 5 家里 4 家硬编码股票资产池（CSI300 / S&P500 / CRSP）；C≥6 的 3 家里 2 家 M≤6。四个加密专用框架里两个无法运行。加密原生 4 家平均 M 只有 3.3，M≥8 的 5 家平均 C 只有 0.8。
3. **不存在可以直接搬来用的「成熟加密因子框架」**。qlib 确实有 crypto 采集器，但只有 CoinGecko 日频价格/量/市值、无 OHLC，`crypto/README.md:12` 原文写着「only support Data retrieval function but not support backtest function due to the lack of OHLC data」，`examples/` 全仓 crypto 零命中。

`RD-Agent` 是「三者不等价」的最佳标本：工程与生态顶级（微软 v1.0.0、839 文件、166 测试、CI/Docker/53 篇文档），M4 = 0，方法论上还鼓励「任何微小改进都替换最佳结果」。**工程越成熟，越能高效地把验证集用穿。**

### 17.7 四维成熟度：为什么 R 是乘数

`platform_maturity_gap.md` §0.2 把「做一个成熟的因子挖掘平台」拆成四维（2026-11-14 21:00 后的评分）：

| 维度 | 得分 | 判据 |
| --- | --- | --- |
| **A 能力覆盖** | **8 / 10** | 4 范式、59 算子、Cross-Asset、静态 AlphaPool、事件驱动回测、22 API + React SPA、CI/Docker |
| **D 纪律可信** | **8 / 10** | NW-HAC t、累积 BH/Holm、DSR、num_trials、HoldoutLedger + 全局守卫、成本闸门、数据质量闸门、逐折重拟合、阳性对照 |
| **O 运营可复现** | **6 / 10** | run manifest + registry + 算子集版本戳 + 全局种子 + 阶段级 resume；缺 epoch 级续训、认证/调度/监控、属性测试 |
| **R 结果产出** | **1 / 10** | 84/84 未验证、唯一严格 OOS 含成本 −6.40%、正式 run 0 promoted；给 1 分而非 0 是因为有诚实的失败记录与预注册窗口 |

> **读法**：A 和 D 已经花完主要工程投入，边际收益最低；O 是低成本高收益（多为接线）；**R 是唯一决定「这是不是平台」的维度，且不能靠写代码补**。四项不是平均关系，R 是乘数：R=1 时 A/D 再高也只等于「一套很严谨的、暂时还没挖到东西的研究工具」。

这份评估最反直觉的一条是 §0.3：**已经有实现的三个能力，其实没接进主流程**——随机零分布（有实现+单测、零调用）、holdout 账本（CLI/Director 已接、`api/` 零命中）、累积试验分母（ledger 被 gitignore，clone 后归零）。这不是「还缺功能」，是「**功能做完了但没成为平台能力**」，成本最低、最该先补。

### 17.8 什么该抄，什么别抄

`industry_factor_mining_survey.md` §8 与 `alphamaster_competitor_review.md` §5 的清单，按优先级重整：

**P0（已完成，此处作为方法记录）**：一次性 holdout 揭示账本 ← crypto-factor-lab；多重检验校正与试验次数分母 ← LLM-Framework；purge + embargo + 多段 roll-forward ← crypto-factor-lab / Alpha-Research-Discovery；组合层升级（mutual-IC 去冗余 + 组合 IC 目标）← AlphaGen / AlphaForge。

**P1（值得按点抄）**：

| 建议 | 来源 | 落点 |
| --- | --- | --- |
| RL 动作掩码（栈深 `delta=1−arity` + logits `-1e9`）；可选「恒正算子感染链」防单边 beta | AlphaGen / AlphaMaster 两代实现 | `rl_miner.py` |
| 词表 / 算子集版本戳 `sha256(算子名序列)[:12]`，加载时校验不匹配即拒载 | AlphaMaster `vocab.py:48-58` | `operator_runtime.py` + OOS 重算 |
| **扩充输入终端到预计算特征面板**（波动率估计量、Amihud、Hurst、通道类，全部因果 left-pad） | AlphaMaster `features.py` 65 特征 | 新增 `feature_panel.py` |
| 便宜 gate 前置（约 90% 拒绝发生在碰 DataFrame 之前） | LLM-Framework `fitness.py` | 候选筛选链 |

**P2**：条件三元 / 通用二元幂 / `vwap,adv,amount` 终端 ← Alpha101 / gpquant；加密一等字段与 PIT 资产池 ← 加密框架；声明式「字段×算子×窗口」模板用于过拟合归因消融 ← qlib。

**明确不建议先做**（`survey.md` §0.3 与 `platform_maturity_gap.md` §5）：扩算子数量、堆范式、逐时间截面时变权重、实盘/下单/风控、Ray/Celery 分布式评估、认证与多用户、动态风险模型与归因层。理由一句话：**在统计闸门补齐且正向 OOS 到手之前，任何提升搜索效率或表达力的改动，都只会把「重复采样」放大成「更高效的重复采样」；而在 R=1 时堆平台功能，是把复杂度建在零产出上。**

纪律原文值得照抄：

> 阶段 2 的每次评估都必须先过 P0-1 的账本；任何「再跑一次看看」都必须消耗一段新的未见数据。**这条纪律比任何新算子都重要。**

### 17.10 工程陷阱

1. **按 star 数或 README 完整度选型**。AlphaMaster 720 star、Web 控制台做得相当完整，但四条统计闸门全缺、作者自己承认结果是 beta；`EvoAlpha` README 称「论文官方实现」，源码里 `quality.py` 自述 Placeholder、无回测无数据无算子白名单。
2. **把 qlib 当挖掘器**。它明确把自动挖掘外包给 RD-Agent（`README.md:35-39,45-50,67`），未找到代码级集成 hook。
3. **把「用了 LLM」当「LLM 挖因子」**。要核对 `model_core` / 训练脚本里有没有 `/chat/completions` 调用。
4. **把「算子数量」当表达力**。必须同时看窗口是否参数化、终端集大小、表达式长度上限。
5. **照搬 AGPL 代码**。机制可以学，代码要自己实现。
6. **用「象限位置」当绝对评价**。M/C 是人为分档，不同权重会改变名次，但不会改变「右上只有两家」的象限结构。
7. **忽略报告的时效**。三份调研都是 2026-11-14 的快照，其中多处结论已被同日的实施补记收窄或推翻；读报告要先读顶部的「基线校准 / 实施完成补记」。

### 本章小结

1. 全景分 L0–L5 六层；L5 产品化层是 AlphaMaster 补出来的维度，前 18 个框架基本空白。
2. 21 个框架分三档：工业级 6 家、研究级 7 家、骨架级 8 家；四个加密专用框架里两个跑不通。
3. 算子矩阵的关键不是数量而是「窗口是否参数化」：AlphaMaster 62 > FactorMiner 59，但组合空间反而更小；真正的表达力差距在 65 vs 5 的输入终端。
4. 算法矩阵的结构性差异是「单因子 fitness + 事后组合」vs「组合增量直接驱动搜索」vs「回测收益直接当 reward」。最后一条把过拟合自由度开到最大，是 beta 退化的病因之一。
5. 闸门矩阵显示：18 个仓库里只有 2 家把多重检验校正写进代码；RD-Agent 工程顶级但 M4=0。
6. 成熟度 × 加密适配度象限右上只有 `crypto-factor-lab (8,8)` 与 `FactorMiner (9,7)`，共同点是证伪机制进了主流程；「最成熟」与「最适合加密」接近负相关。
7. 四维评分 A=8 / D=8 / O=6 / **R=1**，R 是乘数。最该先补的不是功能，是「已实现的能力没接进主流程」。
8. 正确策略是「主干自有 + 机制按点抄」：抄 crypto-factor-lab 的 purge 与成本模型、抄 LLM-Framework 的统计闸门、抄 AlphaMaster 的动作掩码与 `drop_forming`、抄 AlphaGen 的 AlphaPool；在 R 破之前不扩算子、不堆范式、不做实盘与分布式。
