## 第 5 章 表达式语言：算子、终端与计算图

> 本章回答：因子在代码里究竟是什么。我们把因子写成从面板到截面打分向量的函数，拆成算子、终端、组合规则与类型契约，说明符号化表达式为何必须可执行、可序列化、可复现；再对比五种表示法、逐行对齐 FactorMiner 的 59 个算子与递归求值算法，最后落到截面算子的语义陷阱与执行效率。

### 4.1 因子是一个函数：打分向量、符号化定义与三性

**原理与推导。** 先把最容易含混的一个词钉死。在量化研究里，「因子」有时指一个字段，有时指一条公式，有时指一个已训练好的模型；在本章它专指一个**函数**：给定截至时刻 `t` 的面板数据，输出时刻 `t` 截面上每个标的的打分。写成

```
X ∈ R^{T×N×K}          面板：T 个时间截、N 个标的、K 个字段流
X_{≤t}                  仅含 t 及以前信息的数据切片（因果性约束）
s_t = F(X_{≤t}) ∈ R^N   打分向量：N 个标的各一个实数
R_{t+1} ∈ R^N           前瞻收益（标签），t+1 相对 t
RankIC_t = corr_rank(s_t, R_{t+1}) ∈ [-1, 1]
IC_t     = corr(F_t, R_{t+1})           Pearson 版本，作对照
```

其中 `F` 是因子表达式，`s_t` 是它在截面上的取值，`R_{t+1}` 是前瞻收益，`corr_rank` 是 Spearman 秩相关。为什么输出的是打分而不是直接预测收益？因为因子的用途是**排序**：打分只要保持相对次序，加一个常数、乘一个正数都不改变结论；秩相关因此天然去量纲、抗异常值，也让不同来源的因子能放进同一个 fitness 里比较。这也是后面所有闸门（留出、RankIC、试验次数 `num_trials`）都建立在「每个候选是一个可枚举的 `F`」之上的原因——若 `F` 是不可拆解的黑箱，就无法回答「你到底试了多少次」。

符号化因子把 `F` 写成一个表达式 `E`，而一门表达式语言由四件套决定：

```
E ::= t  |  o(E_1, ..., E_k)
O = {算子 o：带 arity、签名、语义}       算子集合
T = {终端 t：字段流名 / 数值常量}        终端集合
G = 组合规则（AST / RPN / 前缀 / 源码）  决定 E 如何拼装与变异
C = 类型契约（输入输出的形状、索引、NaN 语义）
```

`o` 的 `arity` 记为 `k`。这个递归定义看着朴素，却把三件工程上必须同时成立的性质逼了出来：

**可执行**。每条 `E` 必须有唯一、无副作用的计算语义，否则同一个公式在挖掘、重算、回测三段里会给出不同的 `s_t`。FactorMiner 的 `evaluate_ast`（`core/miner/operator_runtime.py:594-629`）就是这个语义的唯一入口，任何候选不论来自 GP、RL 还是 LLM，最终都收敛到同一个解释器。

**可序列化**。`E` 必须能脱离 Python 进程存在，才能进因子库、进报告、跨机器重算、做去重。AST dict 可以直接 `json.dumps(sort_keys=True)` 得到规范签名——`core/miner/crypto_features.py:436` 去重用它，`core/miner/expressions.py:14` 的 `logic_hash` 也靠它。可序列化还带来一个常被低估的好处：表达式串本身就是缓存键。

**可复现**。给定同一份 `X` 与同一条 `E`，`s_t` 必须逐位相同。这要求算子是纯函数、参数采样有显式种子、warm-up 边界有确定性规则。反过来，凡是「先在全样本算统计量再切分」或「运行时偷偷读未来一根 bar」的做法，破坏的都是这一条。

判断是：表达式语言的表达能力上界由 `O ∪ T` 与 `G` 共同决定，搜索算法只是在这个有限空间里游走；而闸门与 `num_trials` 分母之所以能算，是因为每次游走都留下一条可枚举、可哈希的 `E`。这解释了为什么本书先讲表达式语言、再讲搜索、最后讲证伪——顺序反了，分母就无从谈起。

### 4.2 五种表达式表示法：可搜索性、合法性与缓存代价

**竞品对照。** 同一棵计算图可以有五种写法。它们的差别不在「能不能表达」，而在**搜索时是否好变异、采样时是否能保证合法、以及能否复用子表达式**。这张表是后续所有取舍的坐标系。

| 表示法 | 代表框架 | 可搜索性 / 变异 | 合法性保证 | 缓存与去重 | 代价 |
|---|---|---|---|---|---|
| AST dict | FactorMiner（`expressions.py:62-98`） | 子树即指针，交叉/变异 O(1) 换子树 | 无内建保证，靠 `resolve_operator_specs` 校验 arity，非法式在 `evaluate_ast` 抛 `OperatorRuntimeError` | `json.dumps(sort_keys=True)` 即规范签名 | 需显式深度上限防 bloat（`gp_miner.py:74` `max_depth=4`） |
| RPN token 栈 | AlphaGen（`tree.py:7-88`）、AlphaMaster StackVM（`vm.py:221-251`） | 线性序列适合自回归采样，局部性差：改一个 token 可能改动整条栈语义 | **最强**：栈深 `delta = 1 - arity` + 动作掩码，AlphaGen `validate_op` 与 AlphaMaster 把非法位 logits 置 `-1e9`，语法 100% 合法 | 需规范化文本做键 | 定长（AlphaMaster 8 token）易生成但表达受限；窗口固化使词表膨胀 |
| 前缀 program 列表 | gplearn（`_program.py:165-223`） | 扁平列表，`get_subtree` 按 Koza 90% 函数/10% 终端选点，切片拼接 O(L) | 靠 arity 栈隐式保证；`point_mutation` 按**同 arity** 替换（`genetic.py:357-362`） | 列表可直接哈希 | 子树边界须扫描 arity，常数终端用 `isinstance(node, float)` 判定 |
| 字符串表达式树 | qlib（`base.py:13`、`utils/__init__.py:291-325`） | 运算符重载构树，改写字符串易破坏语法，需重新 parse | `ast.parse(mode="eval")` + 白名单，`expression_parser.py:50-124` 明令不执行任意 Python 代码 | **最优**：以 `str(self)` 为键，递归表达式串天然实现公共子式复用（`base.py:187`） | 每次变异要 parse |
| Python 源码 | LLM 范式（`expressions.py:100-145`）、RD-Agent | 表达力最强，LLM 最擅长 | **最弱**：必须沙箱。`FactorExpressionCode.compute` 明确 `"unsafe exec fallback is disabled"`，无 sandbox 直接抛错 | 靠源码哈希 | 复现依赖环境，归因与去重都困难 |

三条值得单独拎出来的判断。第一，**合法性与表达力是此消彼长的**：RPN 用掩码换来了「生成即合法、不浪费算力丢弃非法式」（AlphaGen 动作空间 `SIZE_ACTION=48`），代价是把公式压成定长 8–15 的 token 序列；AST dict 不承诺合法性，却换来任意深度、任意子树替换的自由。第二，**缓存能力是表示法的副产品**：qlib 之所以能用 `str(self)` 一把梭做三层缓存，是因为它的表达式对象天然可字符串化且结构稳定；AST dict 要额外做规范化（`sort_keys=True`），而 Python 源码几乎只能整体哈希。第三，**「窗口是否参数化」会反噬表示法**：AlphaMaster 把窗口固化成 `TS_MEAN_5/10/20` 三个独立 token（`ops.py:365-423`），VM 只按 arity 弹栈、不接收窗口实参（`vm.py:232-238`），于是词表变成 65 特征 + 62 算子 = 127，却没有参数头；FactorMiner 把窗口留在 AST 节点里，一个算子名配一个数值参数即可。

横向看多个开源框架，这张来自调研报告 §6.1、并按 AlphaMaster 增量报告 §3.1 补过一行的对照表，把「数量」与「表达力」分开列：

| qlib | 52 注册名 / 47 类 | ✅ 统一 `N` 语义 | ⚠️ 算子层无、Processor 层有 | ✅ `If/Gt/And/Or` | ✅ 数值常量 | 字符串表达式树 |

### 4.3 算子设计：arity、窗口、时序与截面、分支与数值安全

算子不是「一堆函数」的清单，它的四个设计维度共同定义了表达式空间的形状。

**arity 是一切的骨架**。一元算子（`ts_mean`、`sign`）压栈后栈深不变，二元算子（`add`、`ts_corr`）使栈深 -1；RPN 的动作掩码正是用 `delta = 1 - arity` 维护栈深，再配合「剩余步数能否归约到 1」的剪枝来保证语法合法。FactorMiner 只承认 `arity ∈ {1, 2}`（`registry.py:24-28`、`operator_runtime.py:553-558`），因此没有三元算子；AlphaMaster 的 `GATE`/`IF_GT` 是 arity 3 的例外，也正因为如此它的动作掩码要额外处理。arity 还决定了变异的粒度：gplearn 的 `point_mutation` 必须按同 arity 替换函数节点，否则整个前缀列表的栈平衡就崩了。

**参数化窗口 vs 窗口固化成 token**，是本章最该记住的一组对照。设窗口有 `W` 个候选取值、算子基数为 `M`：固化方案把词表撑成 `M × W` 个名字，采样只是「在更大的词表里选一个」，且变异若想改窗口，必须把整个算子 token 换掉——结构与尺度被绑死；参数化方案让算子名保持 `M` 个，窗口作为节点上的一个数值键，搜索可以单独对窗口做扰动而不动拓扑。FactorMiner 的 `OPERATOR_PARAM_SPECS`（`operator_runtime.py:460-491`）给 30 个算子配了 `(name, lo, hi, kind)`，绝大多数 `window ∈ [3, 60]`，`ts_delta`/`ts_momentum` 放宽到 `[1, 60]`，`ts_ref` 的 `n ∈ [1, 30]`，`signed_power` 的 `p ∈ [0.5, 3.0]`，`clamp` 的 `lo ∈ [-5.0, -0.5]`、`hi ∈ [0.5, 5.0]`，`ts_quantile` 还带一个 `q ∈ [0.1, 0.9]`。GP 用 `sample_operator_params()`（`:502-513`）按 `randint`/`uniform(round 4)` 采样，LLM 用 `default_operator_params()`（`:516-525`）取区间中点——后者刻意不引入随机性，为的是让「同一句 prompt 生成同一批候选」可复现。

**时序算子与截面算子的分野**，本质是 `axis` 的分野：时序算子沿时间轴滚动（`rolling(w)`、`shift(n)`、`ewm`），每个标的各算各的；截面算子沿标的轴操作（`rank(axis=1)`、`mean(axis=1)`），每个时间截各算各的。qlib 做了一个很克制的选择：`ops.py` 里**没有任何截面算子**，截面能力全部放在 `dataset/processor.py` 的 `CSZScoreNorm`/`CSRankNorm`（`groupby("datetime")`），形成「时序表达式层 / 截面后处理层」的刻意分层。FactorMiner 反其道而行，把 8 个 `cs_*` 放进算子层，好处是一条 AST 就能写到底，代价是单标的模式下语义会退化——这是 4.6 的重点。

**逐点变换与条件分支**是表达力里最容易缺的一块。`abs/sign/log/sqrt/exp/inv/sin/cos/tanh/sigmoid/clamp/scale` 属于逐点变换，保形、无状态；`greater/less` 名字像分支，实际返回 0/1 指示值，不是 `x > 0 ? a : b` 的三元选择。调研报告 §5.2 把这个列为 FactorMiner 相对 Alpha101 的结构性缺口：缺条件/分支算子、缺通用二元幂 `pow(x,y)`（我们的 `signed_power` 是单参数标量指数），也缺 `vwap/adv/returns/amount` 这类终端。缺分支的后果不是「少几个公式」，而是无法表达「 regime 切换 」这一类非线性——而加密市场的资金费率、基差恰恰是典型的 regime 变量。

**数值安全**常被当成防崩补丁，其实它保证的是**表达式空间的封闭性**：任意合法 AST 在任意输入上都必须产出有限、可比较的向量，不能中途变成 `NaN` 或 `inf` 让 fitness 失效。FactorMiner 的做法有三层：

```
除零：_safe_divide 把分母里的 0 换成 1e-9            :34-39
      _ts_zscore 分母 s + 1e-9、_ts_momentum 基数 + 1e-9   :61, :83
clip：_exp / _sigmoid 先 clip(-30, 30) 再算指数        :288, :308
      _ts_realized_vol 的 ratio.clip(lower=1e-9)        :213
      _clamp 默认 lo=-3.0, hi=3.0                       :311
保号：_log  = sign(x)·log1p(|x|)，_sqrt = sign(x)·√|x|  :279-284
```

`_log` 为什么写成 `sign(x)·log1p(|x|)` 而不是 `np.log(x)`？因为价格变化、资金费率、基差全都是带符号的实数，直接取对数会在负半轴整片变 `NaN`；保号变换既把定义域铺到全实数，又保留了方向信息，还顺带压住了尾部。同理 `_min_periods = max(2, window // 2)`（`:42-43`）规定窗口不足一半就给 `NaN`，避免用两三个样本估标准差——那会把噪声放大成看似极显著的 z-score。这不是洁癖：gplearn 的 `make_function`（`functions.py:49-121`）同样对全 0 / 全 −1 输入做闭包性检查，gpquant 的 `SyntaxTree` 用 `ttl_shift` 在 warm-up 前置 `NaN`（`SyntaxTree.py:103,190,226-236`），三家在同一处做了同一件事，说明它是表达式语言的硬性契约而非实现偏好。

### 4.4 FactorMiner 的 59 个内置算子：分解、注册与对齐契约

**FactorMiner 实现。** 把 `BUILTIN_OPERATORS`（`core/miner/operator_runtime.py:377-444`）逐条数清楚，是理解后续所有机制的前提。调研报告 §7.1 曾把 58 更正为 **59**，分解如下：

| 类别 | 数量 | 明细 | 源码位置 |
|---|---|---|---|
| 时序 `ts_*` | 30 | `mean/std/zscore/rank/delta/momentum/min/max/decay_linear/corr/cov/ema/ref/sum/product/ma_ratio/var/median/mad/skew/kurt/quantile/argmax/argmin/count_up/realized_vol/rsi/regression/max2/min2` | `:384-417`、`:419-422` |
| 截面 `cs_*` | 8 | `rank/zscore/mean/sum/min/max/mad/neutralize` | `:395`、`:437-443` |
| 二元算术 | 4 | `add/sub/mul/div` | `:379-382` |
| 逐点与其它 | 17 | `abs/sign/log/sqrt/exp/inv/sin/cos/tanh/sigmoid/clamp/scale/log1p_abs/signed_power/cumsum/greater/less` | `:393-394`、`:424-435` |

30 个时序算子恰好与 `OPERATOR_PARAM_SPECS` 的 30 个带参条目对应，这不是巧合：`WINDOWED_OPERATORS` 与 `POWERED_OPERATORS`（`:494-497`）直接由 spec 表派生（"含 `window` 的键"、"含 `p` 的键"），刻意避免两张清单各写一份而漂移；`PARAM_KEYS = ("window", "p", "n", "q", "lo", "hi")`（`:499`）则是采样与序列化时的白名单。

**arity 注册校验**走两条路径，都把错误挡在求值之前。内置路径 `resolve_operator_specs()`（`:541-560`）要求 `search_space.allowed_operators` 是非空字符串列表，逐个取 spec 并断言 `arity in (1, 2)` 且 `func` 可调用，否则抛 `OperatorRuntimeError`；自定义路径 `OperatorRegistry.register(arity=1)`（`registry.py:24-34`）先用 `inspect.signature(func).bind(*[object()] * arity)`（`:9-18`）验证函数真的吃得下这么多个位置参数，arity 不是 1/2 直接抛 `ExtensionRegistrationError`。两条路径的共同判断是：**宁可在注册时报错，也不要在几万次候选求值里偶发一个形状不对的节点**。

**索引对齐契约**是三条容易被忽略、却决定结果能不能比较的规则：

1. **缺失终端补零**。`_terminal_value()`（`:578-591`）遇到字符串终端：若 `data` 是 `{stream: DataFrame}` 字典且名字命中就返回对应面板，否则调用 `_zero_like_data()`（`:567-575`）造一个与样本同 `index`/`columns` 的全零对象；遇到数值常量则返回 `zero + node` 广播成同形向量。这是「静默降级」：GP 变异拼错字段名不会让整条公式报废，但也意味着拼错的字段会变成一个毫无信息的零向量，照样占一次 `num_trials`。
2. **强制返回 pandas 对象**。`evaluate_ast` 在末尾断言结果必须是 `pd.Series` 或 `pd.DataFrame`（`:625-628`），返回 numpy 数组或标量一律抛错。索引必须贯穿整棵树，否则上游的对齐、展平、相关性计算全都失去依据。
3. **DataFrame 按 C 序展平**。`_flatten_factor()`（`expressions.py:282-292`）用 `to_numpy(...).reshape(-1, order="C")` 把面板拉成一维，行主序即**时间主序**，保证每个子因子与前瞻收益的 `(time, asset)` 观察序严格一致；`_safe_corr()`（`:295-306`）要求形状相同且有限观测不少于 30 才计算相关系数；`fit_linear_combination()`（`:309-370`）在 in-sample 上以 `reg_lambda=1.0`、`min_obs=60` 做岭回归拟合固定权重，之后不再改动，OOS 的 RankIC 因此不会被样本内拟合抬高。

| `_clamp` 默认 | `lo=-3.0, hi=3.0` | `:311` | 尾部截断 |
| `_signed_power` 默认 `p` | 2.0 | `:102` | 平方保号 |
| `get_complexity` 深度 | `1+max(左,右)` | `expressions.py:77-85` | bloat 观测量 |

### 4.5 递归求值：evaluate_ast 的伪代码、kwargs 转发与复杂度

**算法与伪代码。** 把 `evaluate_ast`（`operator_runtime.py:594-629`）翻成伪代码，去掉异常包装后主干只有十几行，但每一行都对应一条设计决定：

```python
def evaluate_ast(node, data):
    # ① 叶子：终端是字段名字符串或数值常量。不是 dict / 没有 "op" 即递归出口
    if not isinstance(node, dict) or "op" not in node:
        return terminal_value(node, data)      # 缺失字段 -> 同形全零对象

    op   = node["op"]
    spec = get_operator_spec(op)              # 未注册 -> 列出可用算子并抛错
    if node.get("left") is None:
        raise OperatorRuntimeError(...)       # 缺左操作数，arity 契约不成立
    left = evaluate_ast(node["left"], data)   # 后序遍历：先算子树，再本节点

    # ② 关键：op/left/right 之外的键，一律作为 kwargs 转发给算子函数。
    #    于是 {"op":"ts_mean","left":"close","window":5} 与
    #    {"op":"ts_rank","left":"basis","window":48} 走同一套代码，
    #    AST 结构不需要为「带参 / 不带参」分叉。PARAM_KEYS 只是采样白名单，
    #    不是求值时的硬编码分派。
    params = {k: v for k, v in node.items()
              if k not in ("op", "left", "right")}

    if spec["arity"] == 1:
        args = (left,)
    else:
        args = (left, evaluate_ast(node["right"], data))   # 二元才递归右子树

    result = spec["func"](*args, **params)

    # ③ 类型契约：结果必须是 Series/DataFrame，索引才能向上传递
    if not isinstance(result, (pd.Series, pd.DataFrame)):
        raise OperatorRuntimeError(...)
    return result
```

**「额外键作 kwargs 转发」是整套实现里最省事、也最容易被低估的一招**。算子函数本就写成 `def _rolling_mean(series, window=20)`、`def _ts_quantile(series, window=20, q=0.5)` 这样的普通 Python 签名，节点上多出来的 `window`/`p`/`n`/`q`/`lo`/`hi` 直接对上形参名即可，解释器不需要为每种参数写 `if op == ...` 的分派表。它的另一面是：求值器**不校验参数范围**——`OPERATOR_PARAM_SPECS` 的 3–60 只是采样区间，手写一条 `{"op":"ts_mean","window":0}` 会一路走到 `rolling(0)` 才出事。参数合法性因此被推给了生成侧（`sample_operator_params` / `default_operator_params`）与注册侧，而不是求值侧，这是「快但薄」的取舍。

**复杂度与深度统计**。设表达式树有 `m` 个节点、深度 `d`，面板长度 `T`、标的数 `N`，窗口 `w`。后序遍历每个节点做一次 pandas 运算，向量化的 `rolling().mean()` 是 `O(T·N)`，而 `_ts_rank`（`:64-73`）、`_ts_decay_linear`（`:106-117`）、`_ts_argmax`（`:181-190`）走 `rolling().apply(..., raw=True)` 的 Python 回调，最坏 `O(T·N·w)` 且常数很大。整个候选即 `O(m · T · N · w)`。深度由 `FactorExpressionAST.get_complexity()`（`expressions.py:77-85`）以 `1 + max(左深, 右深)` 递归统计，GP 侧用 `max_depth=4`（`gp_miner.py:74`）约束 bloat，gplearn 则用 `fitness = raw_fitness − c·len(program)` 的简约系数软控制。

真正贵的不是单次求值，而是**没有子表达式复用**：同一棵树里重复出现的公共子树会被各算一遍，GP 种群中跨个体共享的子树更不会被缓存，调研报告 §2.1.6 与 §5.5 都直书「`evaluate_ast` 是纯递归解释、每个候选全量重算」。当候选数从几十涨到 `num_trials` 记下的几百上千时，算力几乎全耗在重复的滚动窗口上——这正是下一节三条执行路线的分歧点。

### 4.6 截面算子的语义陷阱与执行效率的三条路线

**截面算子的三个语义陷阱**必须逐条说清，因为它们在单标的回测里不会报错，只会悄悄给出错的数。

第一，**单标的 Series 上 `cs_*` 基本恒等**。`_cs_mean/_cs_sum/_cs_min/_cs_max/_cs_zscore/_cs_mad/_cs_neutralize`（`:334-375`）写的都是同一个模式：`if isinstance(series, pd.DataFrame): ...` 做截面统计，`return series` 直接原样返回。也就是说在默认的 sequential、单标的模式下，套一层 `cs_zscore` 什么都没做，只是把 AST 深度 +1、把试验次数 +1。唯一的例外是 `_cs_rank`（`:124-128`）：DataFrame 走 `rank(axis=1, pct=True)`，Series 却走 `series.rank(pct=True)`——**沿整条时间轴做全样本百分位排名**。这不只是恒等，而是把未来信息灌进了特征：第 `t` 行的分位取决于 `t` 之后有没有更大的值。同一组算子，七个里六个恒等、一个反而引入前视，这是最容易被「名字看起来一致」掩盖的坑。

第二，**`cs_mad` 实为减截面中位数**。`_cs_mad`（`:364-367`）只有 `series.sub(series.median(axis=1), axis=0)`，没有取绝对偏差、没有再求均值、更没有除以尺度；而同名的时序 `_ts_mad`（`:163-166`）却是 `(series − rolling_mean).abs().rolling(w).mean()`，是「平均绝对偏差」的正统实现。命名相同、语义不同，跨模式迁移模板时会误以为做了去极值。

第三，**`cs_neutralize` 实为去均值**。`_cs_neutralize`（`:370-374`）是 `series.sub(series.mean(axis=1), axis=0)`，只减掉截面均值，是市场中性化最弱的形式；它没有对行业、市值、波动率暴露做回归取残差。调研报告 §6.1 的结论也点明：8 个截面算子虽多，但「缺分组/行业中性化」，且仅在 `cross_asset` 模式下生效。

由此可以给出本章最重要的一个判断：**「算子数量第一 ≠ 表达力第一」**。表达力的正确口径是「终端集宽度 × 参数是否连续可采样 × 有无分支与二元幂 × 组合规则允许的深度」，而不是注册表长度。AlphaMaster 62 个算子听起来胜过 FactorMiner 59、gpquant 60，但窗口固化成 `TS_MEAN_5/10/20` 三个 token、VM 不接收窗口实参、公式定长 8、没有参数头（`alphamaster_competitor_review.md` §3.1）；它真正的表达力来自 65 个预计算特征终端，而非算子数。反过来，FactorMiner 的终端只有 OHLCV 五个（`gp_miner.py:23`），这才是表达力的真瓶颈——第 6 章的加密原生特征模板正是冲着这一点去的。

**执行效率**上，业界给了三条层次分明的路线：

| 维度 | qlib | KunQuant | FactorMiner |
|---|---|---|---|
| 执行 | 解释 + 三层缓存 | AOT 编译成 `.so`，module 复用 | 递归解释，逐节点 kwargs 透传 |
| 计算 | pandas 对象 | 连续 `f32` 矩阵 + 8 股对齐 SIMD | pandas `rolling(w).apply(...)` |
| 子式复用 | ✅ `str(self)` 为键，递归表达式串天然去重 | ✅ STREAM 增量 + `buffer_handles` 复用 | ❌ 每候选全量重算 |
| 窗口 | 运行期统一 `N` 语义（`N>0` rolling / `N=0` expanding / `0<N<1` ewm） | 编译期固化 | 运行期传参 |
| 边界处理 | 每个算子声明 `get_longest_back_rolling` / `get_extended_window_size`，Provider 把区间扩成 `[start-lft, end+rght]` 再切回 | 编译期推导 | 手写 `WARMUP_START` 魔法数 |

qlib 的三层缓存值得展开：① 表达式对象缓存 `expression_instance_cache`（`data.py:389,391-397`）；② 内存结果缓存以 `(str(self), instrument, start, end, ...)` 为键（`base.py:187`，`MemCache` 在 `cache.py:1198`）；③ 磁盘 `ExpressionCache`/`DiskExpressionCache`（`cache.py:329,489`，`disk_cache=0/1/2`）。更关键的是它让**每个算子自己声明需要往前多取多少根 K 线**，于是取数区间在架构层就被扩展，算完再切回目标区间——这一条同时杜绝了「在已切片 DataFrame 上直接 rolling 导致边界 NaN」和「隐式前视」。KunQuant 则走另一个极端：`generate_test_factor.py:82-84,102-104` 把 DAG 编译成机器码，`src/batch.rs:20-26` 明确写下 "In STs memory layout, `num_stocks` must be a multiple of 8 to enable SIMD vectorization"，行主序连续 `f32` 零拷贝交给 C 层。FactorMiner 目前只有顶层 `ThreadPoolExecutor` 并行候选（`core/evaluation/evaluator.py:169-174`），候选内部既无编译也无公共子式复用。三者的差距不在单次快慢，而在**搜索规模翻倍时成本是否线性爆炸**。

**工程陷阱（可直接照做）**：

1. 单标的模式别用 `cs_rank`：它退化成沿时间轴的全样本百分位，把未来信息写进特征；其余 `cs_*` 恒等，等于白加深度、白占一次 `num_trials`。要截面语义先切到 `cross_asset` 面板。
2. 别把 `cs_mad` / `cs_neutralize` 当成「去极值 / 风险中性」：前者只减截面中位数，后者只减截面均值。需要行业中性时，自己加分组残差算子，不要指望名字。
3. 缺失终端会静默补零：GP 变异拼错字段名不报错，只产出全零因子。上线前应给所有 seed / 生成 AST 做一次终端白名单校验，否则零向量会稀释多重检验分母。
4. 带参算子的 `window` 会绕过范围校验：`OPERATOR_PARAM_SPECS` 的 3–60 只约束采样器，手写 AST 传 `window=0` 要到 `rolling(0)` 才失败。一律用 `sample_operator_params()` / `default_operator_params()` 产参数。
5. 递归求值没有子式缓存：`max_depth=4` 只防 bloat，不防重算。若要把种群放大，先以规范化 AST 串（`json.dumps(sort_keys=True)`）做 DAG 缓存，否则算力全烧在重复滚动上。
6. 自定义算子必须返回 pandas 对象：`evaluate_ast` 在 `:625-628` 强制类型，返回 numpy 数组或标量会直接抛 `OperatorRuntimeError`；注册时用 `OperatorRegistry.register(arity=1/2)` 先过签名校验。

### 4.7 本章小结

1. **因子是函数，不是数**：`F(X_{≤t}) → s_t ∈ R^N`，RankIC 是打分与前瞻收益的秩相关。表达式语言的唯一任务，是把这个函数变成可枚举、可变异、可哈希、可审计的符号对象；`num_trials` 分母之所以存在，全靠这一点。
2. **表示法决定搜索算法**：AST dict 便于子树变异与签名去重，RPN 便于动作掩码保证「生成即合法」，前缀列表便于 Koza 遗传算子，字符串树便于以 `str(self)` 为键缓存，Python 源码表达力最强但必须沙箱。没有最优表示法，只有与生成器配套的取舍。
3. **表达力看四个维度，不看算子个数**：终端宽度、参数连续可采样性、分支与二元幂、组合规则深度。AlphaMaster 62 个固化窗口 token 的组合空间小于 FactorMiner 30 个参数化算子；真正的瓶颈是 OHLCV 五个终端，不是 59 这个数字。
4. **契约比算子更值钱**：arity 注册校验、缺失终端补零、强制 pandas 返回、C 序展平，这四条决定大规模搜索里算出的东西能对齐、能比较、能复现；`1e-9` / `clip` / 保号 `log` / `min_periods` 则保证表达式空间在任意输入上封闭。
5. **截面算子只在 cross_asset 面板上有语义**，而且有 `cs_rank` 例外与 `cs_mad`/`cs_neutralize` 的弱语义；误用会同时引入前视和虚假的「中性化」，且因为不报错而极难发现。
6. **执行效率是搜索规模的地基**：qlib 三层缓存与子式复用、KunQuant 编译 + SIMD（记得 `num_stocks` 取 8 的倍数）、FactorMiner 解释执行每候选全量重算，是同一问题的三个层次。在补搜索强度之前，先算清重复子树的代价。
