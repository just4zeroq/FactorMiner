## 第 8 章 强化学习：把因子构造建模为序列决策

> 本章回答：把因子构造写成马尔可夫决策过程之后，策略梯度究竟在优化什么，以及为什么真正决定 RL 挖因子成败的不是 PPO 或 REINFORCE 的选择，而是动作掩码与 reward 口径。我们从 REINFORCE 的似然比推导出发，给出带基线与熵正则的伪代码，再把栈式 RPN 的合法性约束、AlphaGen 与 AlphaMaster 两代掩码实现、三条 reward 路线的分水岭讲透，最后落到 `rl_miner.py` 的纯 NumPy 实现与五类工程陷阱。

### 7.1 原理与推导：从无模型演化到可学习的生成分布

第 7 章的 GP 有一个隐含限制：它没有任何跨代记忆。每一代都从当前种群里重新锦标赛抽样父代，种群本身是唯一的记忆载体，一旦某个子树被淘汰，关于「这类结构曾经有效」的信息就彻底丢失。强化学习（RL）换了一种记忆方式——把「什么样的表达式值得生成」压缩进一组参数 θ，让采样分布 π_θ 随训练整体平移。这是两者最本质的差别：GP 是**无模型演化**，直接在个体上做选择；RL 是**可学习的生成分布**，在分布上做梯度上升。

为此把构造一条公式建模成马尔可夫决策过程（MDP）。状态 s_t 是已生成的表达式前缀，更精确地说是 RPN 栈的当前状态（栈里有哪些子树、各自是什么类型）；动作 a_t 是从词表里选一个算子、一个终端、一个窗口 token，或输出停止符；转移由栈的弹压规则确定，是确定性的；一条轨迹 τ = (s_0, a_0, …, a_{L-1}) 折叠出一棵完整 AST，最终由评价器给出标量奖励 R(τ)。奖励是稀疏的：中间每一步都没有反馈，只有终止时才有一次 fitness。这一点决定了后面所有设计——策略必须在没有任何逐步指导的情况下，把信用分配到 L 个动作上，方差天然很大。

形式化目标与推导如下：

```
J(θ) = E_{τ ~ π_θ} [ R(τ) ]                              # 期望回报
π_θ(τ) = Π_t π_θ(a_t | s_t)                             # 轨迹概率按步分解
∇J(θ) = Σ_τ R(τ) · ∇π_θ(τ)
       = Σ_τ π_θ(τ) · R(τ) · ∇log π_θ(τ)                 # log-derivative trick
       = E_τ [ R(τ) · Σ_t ∇log π_θ(a_t | s_t) ]          # 似然比估计
```

其中 ∇log π_θ(τ) = Σ_t ∇log π_θ(a_t|s_t) 来自轨迹概率的连乘取对数。这一步是全部策略梯度的核心：把「对分布求导」变成「对采样到的动作求 log 概率的梯度再乘回报」，于是无需知道环境转移、也无需 reward 可导，只要能采样、能算 log 概率即可。符号上，θ 是策略参数，L 是轨迹长度，R(τ) 是整条轨迹的因子评价。

式子里的 R(τ) 可以换成任意不依赖当前动作的量而不引入偏差，因为 E[Σ_t ∇log π(a_t|s_t) · b] = b · ∇Σ_a π(a|s) = b · ∇1 = 0。引入 baseline b 后：

```
∇J(θ) = E_τ [ Σ_t ∇log π_θ(a_t | s_t) · (R(τ) − b) ]    # b 只减方差，不改期望
```

直观解释：我们不再奖励「绝对好的轨迹」，而只奖励「比当前水平更好的轨迹」，梯度估计的波动因此大幅下降。b 常取批次均值，或像 AlphaMaster 那样取 EMA baseline 再除以标准差。再叠加熵正则防止策略过早坍缩到单一算子：

```
J'(θ) = J(θ) + β · H(π_θ),    H(π) = − Σ_a π(a|s) · log π(a|s)
```

β 是 entropy_coef，H 是策略熵。熵高意味着分布平坦、还在探索；熵趋零意味着几乎只输出一个动作，训练随即停摆。采用 softmax 参数化 π(a|s) = exp(z_a) / Σ_j exp(z_j) 时，有两个闭式梯度会在实现里反复出现：

```
∇_z log π(a|s) = e_a − p                     # one_hot(a) 减概率向量 p
∂H/∂z_a ∝ − p_a · (log p_a + 1)             # 熵梯度，省略公共常数项
```

`e_a` 是动作 a 的独热向量，p 是完整概率向量，z 是 logits。第一条告诉我们：被采到的动作 logits 被推高，其余按概率比例被压低，推高幅度正比于 advantage；第二条告诉我们熵正则把概率质量往回拉。FactorMiner 的 `update_model` 正是这两行公式的直译，7.5 会逐行对照。

### 7.2 算法与伪代码：带基线、熵正则的策略梯度与动作掩码

把上述推导落成主循环，仍沿用四契约：

```python
# RL 主循环：策略采样轨迹 → 折叠 AST → 评价作 reward → REINFORCE 更新
def rl_mine(data, cfg):
    logits = np.zeros(len(action_space))        # 均匀初始化，纯 NumPy 概率字典
    for step in range(cfg["max_iterations"]):
        batch, trajectories = [], []
        for _ in range(cfg["batch_size"]):
            state, acts, probs = init_stack(), [], []
            for t in range(cfg["traj_len"]):
                p = softmax(logits)                     # 策略概率
                mask = valid_mask(state, remaining=cfg["traj_len"] - t)
                p = apply_mask(p, mask)                 # 非法位 logits 置 −1e9
                a = sample(p)
                acts.append(a); probs.append(p.copy())
                state = transition(state, a)            # 按 delta = 1 − arity 弹压栈
            tree = fold_to_ast(acts)                    # 折叠成合法嵌套 AST
            expr = make_expression(tree, acts, probs)   # 产物是表达式，不是轨迹
            batch.append(expr); trajectories.append((acts, probs))

        feedback = evaluate(batch, data)                # fitness 作稀疏 reward
        rewards = [r for expr in batch
                   for r in [feedback.for_candidate(expr).fitness_score]]
        b = mean(rewards)                               # 批次均值基线，减方差
        grad = np.zeros_like(logits)
        for (acts, probs), R in zip(trajectories, rewards):
            adv = R − b                                  # advantage
            for a, p in zip(acts, probs):
                grad += adv * (one_hot(a) − p)           # ∇log π = e_a − p
        grad -= cfg["entropy_coef"] * (log(probs + 1e-12) + 1) * probs
        logits = clip(logits + cfg["learning_rate"] * grad / len(batch), −20, 20)
        state.population = select_top_k(batch, by="fitness")   # 产物必须落盘
    return logits, hall_of_fame
```

注意最后一行：策略权重是训练产物，只有写进 `state.population`（或 `hall_of_fame`）的、可独立计算并带指标的表达式才是研究产物。

**合法性问题是这一节真正的主角。** 在栈式 RPN 里，每个 token 有 arity，压栈时栈深变化为 `delta = 1 − arity`：一元算子弹 1 压 1，净变化 0；二元算子弹 2 压 1，净变化 −1；终端只压不弹，净变化 +1。合法轨迹有两个约束：中途栈深始终 ≥ 1（每个算子都拿得到操作数），终止时栈深恰为 1（整条公式归约成一个根）。由此立刻得到「剩余步数能否归约到 1」的剪枝：设当前栈深 d、剩余 r 步，二元算子每步最多把栈深降 1，一元算子保持不变，所以 r 步内最多降 min(d−1, r)；若 d − 1 > r，无论后面选什么都回不到 1，这条分支必须剪掉。反过来，若 d = 1 且 r > 0，此后只能选一元算子，任何二元算子都非法。AlphaMaster 把这两个界写成 `min_future / max_future`（`docs/research/alphamaster_competitor_review.md:109`）。非法动作的处理是把对应 logits 置 `−1e9` 而不是 `−∞`：softmax 后概率近似 0，数值稳定，梯度也不会流向非法位（`engine.py:214`）。

两代掩码实现值得对照。AlphaGen 是**分类式**：`validate_op` 按算子类判定合法性——Unary 需栈顶是 featured 表达式，Binary 需至少一个 featured 且无 `DeltaTime`，Rolling 需栈顶为 `DeltaTime`、次栈顶 featured，PairRolling 需栈顶 `DeltaTime` 且下两个都 featured；`is_valid` 还要求栈恰 1 个且 `is_featured`（`docs/research/industry_factor_mining_survey.md:218`）。动作空间 `SIZE_ACTION = 22 + 6 + 5 + 14 + 1 = 48`（22 个启用算子、6 个特征、5 个窗口 token、14 个常量、1 个序列结束符，:220），`MAX_EXPR_LENGTH = 15`，窗口 token `DELTA_TIMES = [1,5,10,20,40]`；28 个算子类定义但 RL 实际启用 22 个，注释掉了 `Sign/CSRank/Pow/Skew/Kurt/Rank`（:203-212）。`action_masks()` 把判定结果转成布尔掩码交给 `MaskablePPO`（:220）。AlphaMaster 是**可微 logits 掩码**：`ConstrainedSampler.valid_mask` 用 `delta = 1 − arity` 维护栈深（:109），叠加 `min_future/max_future` 剩余步剪枝（`engine.py:151-157,176-186`），再叠加「恒正算子感染链 ≥ 2 禁止传播算子 / ≥ 3 强制恢复」的符号约束（`engine.py:190-196`），最终 `masked[b][~vmask] = -1e9`（`engine.py:214`），整段集中在 `engine.py:145-215`。后者是梯度能穿过合法性约束的实现，前者是环境给布尔掩码、由 MaskablePPO 消费。

现在把那句结论讲透：**RL 挖因子的关键不是 PPO，是 masking**。PPO 与 REINFORCE 的差别只在方差控制与样本效率，而动作掩码决定的是「采样出的候选里有多少能被评价」。没有掩码，48^15 量级的动作序列里合法占比极低，绝大多数轨迹会在生成后被校验丢弃，试验预算被烧在无效候选上；更糟的是被丢弃的轨迹往往带负 reward，梯度会把概率质量推向不可解释的方向，训练越久越糟。AlphaGen 的实际结论是采样出的每个表达式语法与类型 100% 合法，没有「生成后校验再丢弃」的算力浪费（`docs/research/industry_factor_mining_survey.md:220`），调研报告把它列为四条核心发现之一（:24）。AlphaMaster 还给了第二层教训：合法性之外还有**语义合法性**——恒正算子感染链约束是为了修复「TS_RANK 连续使用符号丢失、公式退化成 91.8% 做多的 beta 因子」这一 bug（`docs/research/alphamaster_competitor_review.md:27,109`）。所以 masking 管的不只是语法，还管「这条公式是不是一个真的因子」。判断很明确：先把试验预算对准有效假设，再谈用哪个策略梯度算法。

### 7.3 Reward 设计的分水岭：三条路线，三种搜索方向

奖励口径不是实现细节，它直接定义策略在优化什么。三条路线的分歧值得逐条拆开。

**路线一：直接优化回测年化收益。** AlphaMaster 的打分是 `score = 0.60·年化收益 + 0.10·Sortino + 0.05·Calmar + 0.10·时序IC`（`backtest.py:615-626`），FTMO 模式进一步到 `0.75·年化收益 + 0.10·Calmar + …`（`backtest.py:600-613`）；文件头注释写的「0.35 sortino + 0.20 calmar − complexity」是过时文档，复杂度惩罚实际不存在（`docs/research/alphamaster_competitor_review.md:134,137,140`）。这条路线把「搜索」和「交易」焊死，好处是目标端到端一致，代价是搜索可以直接攻击回测口径的自由度。再叠加验证集每步反复使用、无 `num_trials` 分母、无多重检验折减（:159,174），作者在仓库里主动写下结论：index 组退化成 91.8% 做多的 beta，metals 组年化 +117.7% 虚高，等权组合 +35.52% 被标注「短数据放大」（:27,180,189）。review 的判断很克制也很准确：直接攻击回测年化收益「本身就是病因的一部分」（:143）。

**路线二：单因子 IC / RankIC。** FactorMiner 的 fitness 是样本内外 RankIC 的几何混合再乘一串折减：`fitness = 100 × blended × cons_mult × shrink × penalty × tp × parsimony`，其中 `blended = |RIC_in|^(1−λ) · |RIC_oos|^λ`，`λ = oos_exponent = 0.5`，OOS 符号翻转时 `cons_mult = 0.3`（`docs/research/industry_factor_mining_survey.md:751-755`）。它不对收益曲线做梯度上升，因此不会像路线一那样把仓位口径、成本假设全焊进搜索目标，代价是策略只学「单个因子像不像样」，学不到「这个因子对现有组合有没有新增量」。

**路线三：组合增量 `new_obj`。** AlphaGen 的 `AlphaEnvCore._evaluate()` 调用 `pool.try_new_expr(expr)`，把返回值直接当 reward；`MseAlphaPool.try_new_expr` 返回的是「把该因子加入池、重新优化全部权重后的组合目标」，单因子 IC / RankIC 只用于过滤与互相关计算（`docs/research/industry_factor_mining_survey.md:224`）。权重联合优化最小化：

```
loss = wᵀMw − 2wᵀc + 1 + α‖w‖₁          M: mutual IC 矩阵，c: single IC 向量，α = 5e-3
```

`α‖w‖₁` 产生稀疏、可自动淘汰权重近零的因子；mutual IC 任一 `> 0.99` 的候选直接拒收（:232）；`α ≈ 0` 时退化为 `np.linalg.lstsq(M, c)` 闭式解（:233）。**搜索与组合是耦合的**。

为什么耦合会改变结果？因为优化目标从「这个因子单独有多好」变成「它对现有池子有多增量」。一个单因子 RankIC 0.05、但与池内因子高度相关的公式，在路线二会被当成好因子收下，在路线三会被拒收或得到极低 reward；反过来，一个单因子 IC 一般、却填补了池子空白方向的公式，在路线二根本进不了精英，在路线三却会被奖励。于是策略学到的生成分布完全不同：路线二倾向于反复生成同一类信号（每类单独看都还行），路线三被迫去找正交方向。代价同样明确：reward 变成**非平稳**的——池子在训练中不断变化，同一条轨迹在不同训练阶段得到不同 reward，策略梯度估计的方差更大；而且每加入一个因子要重优化全部权重，单次评估成本高得多。调研报告把「搜索目标是单因子 fitness、组合是事后独立一步」列为「挖出一堆 IC 还行但组合起来亏钱」的结构性原因之一（:698）。FactorMiner 末层是样本内一次岭回归、之后权重固定，组合与搜索解耦，因此它的 RL reward 没有表达「增量」这一维度的接口——这是取舍，不是缺陷，但必须知道代价在哪。

读表时不要被「PPO vs REINFORCE」带偏。三者的分水岭在两个位置：合法性约束放在哪一层（环境给布尔掩码、还是直接加在 logits 上、还是干脆靠构造保证），以及 reward 优化到哪一层（回测收益、单因子、还是组合增量）。AlphaGen 与 AlphaMaster 一个把预算全花在合法且正交的假设上、一个把预算全花在攻击回测口径上，最终产物一个是有池子的因子库、一条是 8 token 的单公式，差别从这两个选择就已注定，与策略梯度算法关系不大。

### 7.5 FactorMiner 实现：纯 NumPy 的 REINFORCE

`RLFactorExpression`（`core/miner/paradigms/rl_miner.py:22`）是整个实现里最关键的设计。它继承 `FactorExpressionAction`，但覆盖了 `compute()` 为 `evaluate_ast(self.ast_dict, data)`（:31-33），并让 `get_source()` 返回 `ast_dict` 而不是动作序列（:35-37），源码注释写得很直白：「Store the concrete AST (more reproducible than the action sequence)」。`get_complexity()` 返回折叠后 AST 的树深（:39-44）。判断：动作序列依赖采样时的策略分布与随机窗口，重放不保证一致；AST 是可脱离策略、独立重算的确定性产物，这正是研究产物该有的形态。

`initialize_search_space()`（:57）建立 `action_space`（:59-63）、`terminals`（:65-69），并在 :70-79 通过 `crypto_terminals()` 把面板里的加密流纳入终端；`windows = [5,10,20,60]`（:81）、`powers = [1.0,2.0,3.0]`（:82）；`policy_logits = np.zeros(len(action_space))`（:85，均匀初始化）、`baseline = 0.0`（:86）、`learning_rate = 0.05`（:87）、`traj_len = 4`（:88）、`entropy_coef = 0.01`（:89）、`best_expr / best_reward`（:90-91）。`_policy_probs()`（:96）实现 softmax 时先减去 logits 最大值防溢出（:97-99）。

`_sample_trajectory()`（:101）按 `traj_len` 从当前策略独立采样动作，并把每一步的**完整概率向量** `probs.copy()` 存进 `actions_probs`（:105-109）——梯度更新需要的不只是被选中的动作，还有整条分布。`_build_ast()`（:111）把动作序列折叠成合法嵌套 AST：以随机终端作累加器 acc（:113），逐个动作创建节点，`WINDOWED_OPERATORS` 随机取窗口、`POWERED_OPERATORS` 随机取幂（:118-121）；arity 1 时 `left = acc`，arity 2 时 `left = acc`、`right = random.choice(self.terminals)`（:122-127），然后把 acc 更新为该节点（:127）。这是**折叠**而非栈式生成，因此 AST 天然合法，但也正因如此，策略每一步没有掩码：它只学到算子偏好，窗口与右侧终端仍由 `random` 决定，合法性是构造保证的、不是学出来的。

`generate_candidates()`（:133）按 `batch_size` 默认 10（:136）采样，每条轨迹生成 `RLFactorExpression`，并把 `_rl_actions` / `_rl_probs` 挂在对象上供梯度更新取用（:146-147）。`update_model()`（:156）是 REINFORCE 的逐行直译：

- `reward = float(expr.metrics.get("fitness_score", 0.0))`（:164）；`best_expr / best_reward` 在 :170-172 更新。
- `advantages = reward − (np.mean(rewards) if rewards else 0.0)`（:173）。注意 `rewards` 是在遍历候选时逐个 append 的（:165），因此第 i 个候选的基线是**前 i+1 个 reward 的均值**，不是整个批次的均值——这是真实实现，读代码时不要按标准「批次均值 baseline」去理解。
- `g = -p.copy(); g[a] += 1.0`（:176-177），即 `grad_log p = one_hot(a) − p`，源码注释直接标了 `# REINFORCE`；`grad += advantages * g`（:178）。
- 熵梯度 `entropy_grad = (np.log(probs + 1e-12) + 1.0) * probs`（:181），`grad -= self.entropy_coef * entropy_grad`（:182），对应 7.1 里 `∂H/∂z ∝ −p(log p + 1)` 的梯度上升方向，用于鼓励探索、防止策略坍缩。
- `self.baseline = float(np.mean(rewards))`（:185）、`grad /= max(1, len(rewards))`（:186）、`policy_logits += learning_rate * grad`（:187）、`np.clip(self.policy_logits, -20.0, 20.0)`（:189）保持数值稳定，最后打印 top-5 算子概率（:190-196）。

关于 `state.population` 契约，这里有一处必须点破：当前 `update_model` **没有**写 `self.state.population`，只更新 `policy_logits` 与 `best_expr`。产物链路靠 `BaseFactorMiner.mine()` 在主循环里把成功候选写进 `hall_of_fame`（`core/miner/paradigms/base.py:300-308`），而 `_get_best_factors()` 优先读 `hall_of_fame`（:539-540）——所以默认流程能出产物，但这是**靠名人堂兜底**，不是显式 population。README 第 4 条仍要求自定义 RL Miner 每轮策略更新后按 fitness 选 Top-K 写进 `state.population` 或 `replay_buffer`（`README.md:339-341,397`）。一旦自定义实现关掉名人堂、或 feedback 不带 metrics，就会退化为「任务成功但零产物」。

### 7.6 工程陷阱

1. **reward hacking：策略学会输出常数或极端值。** reward 直接取 fitness，若评价器对常数 / 全零面值给出虚高读数（第 7 章 `corrwith` 陷阱），REINFORCE 会无条件放大产生这类轨迹的算子概率，且 baseline 只减方差、救不了偏差；熵正则甚至会帮它更快探索到退化组合。AlphaMaster 给非法公式 `−5.0 / −2.0` 的负 reward（`docs/research/alphamaster_competitor_review.md:110`）是一种拦截，FactorMiner 依赖 evaluator 的 Anti-Bloat 与退化判定是另一种。判断：reward 进梯度之前必须先做退化检查与数值 clip，不能把评价器的原始输出直接当奖励。

2. **训练不稳定与熵坍缩。** logits 无界会让 softmax 饱和、梯度消失，`traj_len = 4` 与 `batch_size = 10` 又意味着每轮只有 40 个动作样本，advantages 方差很大。FactorMiner 用 clip `±20`（`core/miner/paradigms/rl_miner.py:189`）与 `entropy_coef = 0.01`（:89）缓解，但两者都是软措施。更隐蔽的是顺序：没有动作掩码时，熵正则鼓励的「探索」有大量落在非法组合上，等于把预算送给无效假设。结论是熵正则必须加在掩码之后，否则它和合法性约束互相拆台。

3. **轨迹与因子是两类产物。** 策略权重、reward、轨迹是训练产物；可独立计算并带指标的表达式才是研究产物（`README.md:397`）。这解释了 `RLFactorExpression.get_source()` 为什么返回 AST 而非动作序列（`core/miner/paradigms/rl_miner.py:35-37`）：动作序列依赖当时的策略与随机窗口，重放不保证复现，入库后无法独立验算。每轮更新后应从采样表达式里按 fitness 选 Top-K 落到 `state.population` / `replay_buffer`，轨迹本身不能入库。

4. **未接动作掩码导致大量非法候选浪费试验预算。** `_build_ast` 用折叠保证语法合法，但策略每一步没有 masks，窗口与终端由 `random` 决定（`core/miner/paradigms/rl_miner.py:113,119,121,126`），「学到的分布」只覆盖算子偏好。对比 AlphaGen 采样 100% 合法、无「生成后校验再丢弃」的浪费（`docs/research/industry_factor_mining_survey.md:220`），这里既没有把 `num_trials` 对准策略认为值得试的方向，也缺少「剩余步数能否归约到 1」这类剪枝。判断：masking 不只是合法性工具，更是把试验预算分配给有效假设的机制；缺了它，增大 batch_size 只是等比例放大浪费。

5. **加密终端只接 GP 与部分 RL 的差异。** GP 在 `initialize_search_space` 里既把加密流提升为终端（`core/miner/paradigms/gp_miner.py:52`），又用 `crypto_seed_ratio = 0.3` 播种 `build_crypto_feature_asts()`（:57,61-65），窗口默认取自 `DEFAULT_CRYPTO_WINDOWS = (6,12,24,48)`。RL 只在 `core/miner/paradigms/rl_miner.py:74-79` 调 `crypto_terminals` 扩展终端，**没有对应的加密种子 AST**，也没有独立的加密窗口集。结果是 RL 的动作空间「能表达」funding / basis / OI 因子，却缺少冷启动模板，策略要从均匀 logits 里自己撞上这些终端；`framework_maturity_crypto_fit.md:279` 仍把「把 60 个流接进终端集」列为 P1-a，并注明「只有 seed」。判断：同一份数据面板，两个范式拿到的先验并不对称，直接比较两者的产出质量会得出错误结论。

### 7.7 本章小结

1. 把因子构造建模为 MDP 后，RL 与 GP 的本质差别是**可学习的生成分布** vs **无模型演化**：状态是表达式前缀 / 栈状态，动作是选算子、终端或停止，轨迹 τ 折叠成 AST，奖励是稀疏的因子评价。
2. REINFORCE 由 log-derivative trick 得 `∇J = E[Σ_t ∇log π(a_t|s_t)·(R − b)]`；baseline 无偏减方差、熵正则防坍缩；softmax 下 `∇log π = one_hot − p`，FactorMiner 的 `update_model` 就是这两行公式的直译。
3. **RL 挖因子的关键不是 PPO，是 masking**：栈式 RPN 的 `delta = 1 − arity`、剩余步能否归约到 1 的剪枝、非法位 `−1e9`；AlphaGen 的分类式 `validate_op`（`SIZE_ACTION = 48`、`MAX_EXPR_LENGTH = 15`、窗口 `[1,5,10,20,40]`）与 AlphaMaster 的可微 logits 掩码（`engine.py:145-215` + 恒正算子感染链）是两代实现，后者还说明合法性之外还有语义合法性。
4. Reward 决定搜索方向：回测年化收益（`0.60~0.75` 权重）会诱导 beta 退化；单因子 RankIC 稳定但表达不了组合增量；组合增量 `new_obj`（`loss = wᵀMw − 2wᵀc + 1 + α‖w‖₁`，`α = 5e-3`，mutual IC `> 0.99` 拒收）把搜索与组合耦合，换来正交搜索方向，代价是 reward 非平稳与评估成本上升。
5. 产物契约必须闭合：策略权重是训练产物，可独立计算并带指标的表达式才是研究产物；`get_source()` 返回 AST、`state.population` / `hall_of_fame` 必须有候选落入。轨迹、奖励与 logits 本身都不能入库，否则任务「成功但零产物」。
